# Who holds the truth

A change that adds or moves a fact updates its row here.

This table holds what the console keeps in its state folder on Spark 2 (`~/.local/state/spark-console`). What it
keeps anywhere else, or nowhere, is in `docs/state-outside.md`.

| Fact | Lives in | Written by | Read by | Survives a restart |
|---|---|---|---|---|
| Which Sparks exist | `NODES`, from `nodes` in `access.json` (or its last good copy, next row; `config.json` only seeds) | `refreshNodes` | everything | file yes, variable no |
| Who has access | `access.json`, its last good copy `access.json.good` beside it; `ownerLogin` and `members` in `config.json` win when present (neither is set today); cached 10 s | `changeAccess`, `changeMembers`, `askAccess` (requests, also from unsigned public asks), all through `accessToChange`; the service never writes `ownerLogin` or `nodes`. `ownAccess` rewrites the copy when `access.json` reads fine and differs: after every change here (read back) and after a hand edit | `accessList`. `access.json` unreadable, not JSON or naming no owner: the copy answers, one notice, every change answers 503 until it reads fine again; the bad file is never written over or set aside. Missing: no owner yet, copy or no copy | yes |
| Passkeys, sessions, agent keys | `passkeys.json` (public keys and sign counts), `sessions.json` and `agents.json` (hashes) | handler; `passkeyGate` and sign-in (count, last use); `22-sessions`; the last-use timer in `20-mcp` | the gates; `accessView` (names, times and counts for `sparkie_setup`’s `access`, the owner’s own call only, A5). Unreadable passkeys or agents file: 500 (in `accessView`: `passkeys` is null with a `problem` line; `sparkie_setup` still answers). Unreadable sessions file: every device signed out | yes |
| What should be running | `desired.json` (never the self-test’s own model, R22). A model entry has `model` (and `sparks` across two); an app entry (keep_running) has `app: true`, `port`, `memoryGB` and no `model`. Every entry has `since`: its last start that wasn’t self-healing’s (`displacedBy` reads it, R19). `parked` (a time): stopped to power its Spark off, still on the list (R41) | `desiredAfter` (job completion; clears `parked`); `parkDesired` (only `parked`); `watchHeld` (first seed); `markUndone` in `undo_last_change`; `POST /desired/forget`; `keepApp` (an app already running joins, or its port and memory figure follow Docker); `forgetApp` (an app's stop while its Spark is off). Writers that read the list first read it with `desired(true)` (R20) | `healPass` (apps: `healApp`), undo, start-on-call, `desiredNow` (`should_be_running`, `GET /desired`, `watchHeld`; apps: `appNow`; a held model or app carries `sparkOff` or `dockerDown` when its Spark is off or its Docker didn’t answer), the bring-back route, `fleetNotes`, `openProblems` | yes |
| Heal attempts | `heal-tries.json`, loaded once into `healTries` | `saveHealTries` | `maybeHeal`, `bringBack`, `watchBrain`, `keepBrain` (key `keep:<spark>/<container>`) | yes |
| What a self-test under way has started | `self-test.json`: its operation, the chat that asked, the Spark, when it began, and for its model, web page and job the container name and, once Docker has one, the full id (the model’s while it still loads). No secret | `selfTest` (`keep`, `21-selftest.mjs`), through `writePrivate`; removed when the run ends | `readKept`: `selfTestRecover` at start-up, `selfTestCutOff`, `self_test` (refuses while one is pending), `selfTestModels` (the list’s first seed and `maybeHeal` pass over its model) | only during a run, or after a restart cut one off until `selfTestRecover` has stopped what it started (a Spark that doesn’t answer is retried each minute); the daily copy and install snapshots copy it too, harmless there |
| Which version is validated | `validations.json` | `recordWorkflowRun` only | `workflowStatus` | yes |
| Spark Console’s own updates | `updates.json`: the newest 20 records (`at`, `build`, `previousBuild`, `stamp`, `note`, `result`: `first record`, `installed` or `went back`); `update-note.json`: the build and the note the installer was given (`NOTE=`) | `noteUpdate` only, once at start after the local port is bound, only when the build differs from the last one on record (`went back` when `update-note.json` doesn't name the running build); every install writes `update-note.json`, going back never does | `sparkie_setup` (`console.updates`, the newest five, notes labelled as data) | yes. It is state, so going back a build keeps it; `restore.sh --with-state` puts back the older record. A build that never started leaves no record |
| Proven runs | `verified.json` | `recordVerified` only | `bestHow`, `resolveHow`, page; `runningDetail` (names the setup only when a recorded run has exactly a running container’s model, engine, image, Spark count and flags) | yes |
| What failed (lessons) | `lessons.json`: one record per setup and known failure (B 2.2 as cut): its kind (`start` or `app`), subject, the setup tried, the failure id, `seen` or `proven`, the count, the journal ids of its newest three operations. Only the console's own typed values, else null: no `fix`, no log's or brain's words, no key (R48) | `recordLesson` only, called by `learnFrom` at `runJob`'s end: a failure adds a lesson or counts again; a success of the same setup takes its lessons out | a start, before it picks a setup: one that failed twice the same known way is passed over (`failedTwice`, B3) | yes |
| Recipes | `catalog.json` + `added-models.json` + `found-setups.json` | catalog builder; `addModel` (the page’s add routes; `startModel`’s download job and `find_setups`, for a Hugging Face repo the asker named in full or said yes to, A9); `digModel` | `recipeCatalog`, read fresh each call | yes |
| Saved workflows | `saved-workflows.json` | `save_workflow`, `forget_workflow`, `run_workflow` (last run, only for the steps it ran) | `workflows`, `run_workflow` | yes |
| A Spark’s last readings | `knowledge.sparks[id].gpu` (status check) and `.readings` (watcher); copied into `spark-offline` as `last` | `noteSparkStates`, `watchSpark` | `fleet_status`, `spark_diagnostics` (`darkPeriods`), Sparkie’s fleet notes | with the knowledge file; used only when under 3 minutes old |
| The copy from before the last save | `<file>.prev` beside each file `writePrivate` saves after `readKept` read it in this process: `added-models.json`, `found-setups.json`, `verified.json`, `lessons.json`, `validations.json`, `saved-workflows.json`, `desired.json`, `memory.json`, `memory-past.json`, `updates.json`, `backup.json` (0600; rides in the daily copy and install snapshots; no secret; never for sign-in files) | `writePrivate`, just before each save | `readKept`, only when the file itself is not JSON | yes |
| Memory | `memory.json` (`{entries}`, the live lines, no ceiling; each with who it is from, `by`, and where from, `src`) and `memory-past.json` (`{past}`, the lines replaced or forgotten, each with `gone`: when, why, the line that replaced it, who), R45 | `saveMemory` only, for `remember` and `forget_memory` (the past file first). Both are in the daily copy and install snapshots. Forgetting, also by the page’s Forget button, only retires a line. Erasing one for good (`eraseLine`: the owner’s call or a button in Spark Console) takes it out of both files, saves both twice so neither `.prev` holds its words, and blanks them in a copy set aside (`.unreadable-*`) or half-written (`.tmp`); the chat, the journal, `audit.jsonl`, daily copies already sent and install snapshots already taken keep them | `memoryPrompt` (a read error: the turn runs without the lines and the prompt says memory couldn’t be read; past 4,000 characters of lines, the newest that fit and how many more), `memory` (`past: true` reads the past file, owner only; a read error there answers 503 and forgetting writes nothing) | yes |
| Memory lines' names | `about` on each line (R45); in memory, made at start: names known (`memoryNameBook`), lines by name (`memoryIndexNow`) | `remember`, `saveMemory` | `memory` (owner's call) | the names only |
| Chats | memory `chatStore`; `chats.json` is a copy with its own writer (`saveChats` never throws: a failed write keeps the store in memory, the next save retries); also the carry-on task (the request, where it came from: `channel`, `away`, and its tool `groups`, R46): set when a multi-step request starts an operation, also when that reply then fails; kept through a typed yes; dropped by the owner’s next request or `/stop` | `sparkieTurn`, `runChoice`, `postResult`, `continueTask`, `stopTurn`, the `/chats` routes, `askSparkie` | chat routes, `ask_sparkie`, `wakeWork`. Unreadable: set aside, new empty store. The owner’s words and Sparkie’s answers are masked when saved (R7, F20) | yes, except what was said while saves were failing |
| Containers seen; history | memory `knowledge` (`knowledge.json` is a copy, saved when the watcher sees a change and at once when a Spark goes dark or comes back, `noteSparkStates`; `knowledge.sparks[id].dockerDownAt` while Docker isn’t answering there; a job’s row carries `endTold` once its end was told, and is set running when run again, A13) and `events` (last 500; `events.jsonl` rotates at 5 MB) | watcher; status loop (`knowledge.sparks`); `fleetEvent` | healing, passkey gate, fleet notes, `pickContainer` in the intent gate, `desiredNow`, `workloads`, `fleet_events` (`workloads` and fleet notes go through `sparkOff`: rows on a Spark off or not answering show as last seen, not running; the other readers use the stored rows) | yes |
| Status; cable test | memory `statusCache`; memory `lastCheck` (`links.json` is a copy) | `collectStatus`; `fabric(check)` | page, placement, `clusterNet`, public page | no; yes |
| Pause and auto-restart | `agent-settings.json` (unreadable = paused) | `setAgentSettings`, `tripBreaker` | `runAction`, `pausedCheck`, healing | yes |
| Brain setup and routes | `MAIN`, `ROUTES`, loaded once from `config.json` + `main.json`; `leftDown` in `main.json` (Spark Console took the brain down and hasn’t seen it answer since) | `switchMain`, `setRoute`, `markBrainLeftDown` | chat, `/v1`, healing, `keepBrain` | yes |
| How the brain calls tools | `brain-profiles.json`: one profile per brain setup, keyed by a hash of model, draft, engine, image, flags, environment, rope settings, how it is asked, its limits and what runs (never the name); each names those, this build's `brainReads` from the lock (null when the lock isn't this build's), the outcome (`checked` or `not checked`) with why, each request tried and what came back, and `evals`: the eval's results, by what the brain read and the case set's version (`"<reads>:<set>"`), five full main-set runs and five others each, six of those, sealed with the key in `eval-seal.json` beside secrets.json (R47, R52; kept by a new check). The newest 50. No secret (environment names only) | `saveBrainProfile` only (`brainCheck`; `storeBrainEval`, the owner's `POST /main/eval`) | `brainCheckView` (`sparkie_setup`'s `brainCheck`, with `brainEvalView`), `checkBrainSoon` (is there one yet), `brainRail` (R52: a change runs at once only while it counts) | yes |
| Spark Console’s own errors | memory `FAULTS` (the last 20 different ones, each counted; the service log keeps the stacks); `last-crash.json` (the last uncaught error: time, build, message, top 5 stack lines, secrets masked) | `recordFault` (`handler`’s catch for a 500, `mcpDoor`’s two catches, `unhandledRejection`); `recordCrash` (`uncaughtException`, before exit) | `faultView` → `sparkie_setup` (`console.faults`, `lastCrash`, `watchdogRestarts`) | faults no; the crash file yes |
| Who changed what | `audit.jsonl` | `audit` | nothing in the service | yes |
| Telegram’s offset, current chat, a turn under way, operations started there; what the needs-me line already told and when lines went out (`needs`); approval times (`approvals`) | `telegram.json` (no secret) | `tgUpdate` (offset saved before acting on the owner’s message; strangers’ at most once a second), `tgTurn`, `tgConv`, `tellAwait`, `needsMeTick`, `PUT /telegram/needs` (switching on clears what was told), `tgApprovalCounted` | `tgLoop`, `tgAfterRestart`, `needsMeTick`, `tgApproving` | yes |
| Which plug is on which Spark | `plugs.json` (`{"spark3": {"node": 2}}`, no secret); the controller’s own pairing keys in `~/.config/spark-console/matter` on Spark 2 (0700, never read by the service) | only the owner’s `deploy/plugs.sh` (`pair`, `name`), never the service | `plugMap` (every 15 s; the brain’s Spark and the console’s own are dropped unless marked `readOnly`), `wallFor` → status `wall`, `fleet_status`; `switchablePlug`, `freshWall` and `switchPlug` (21-power.mjs’s jobs only) | yes |
| Which Sparks Spark Console powered off; the idle time | `power.json` (no secret): `idleMinutes` (default 30, 0 = off), `changedAt`, `changedBy`, `activeSaidAt` (when the owner was told the idle power-off is on), and `off: {spark4: {at, why: idle or asked, by, parked, models, memTotal, diskFree, plugCut, problem}}`; written just before the shutdown, so a Spark on its way down is already off on purpose | `power_settings`; the power-off job (`offRecord`: before the shutdown, `plugCut` after the cut, `problem` when its power wasn’t cut); a failed power-on (`problem`); the power-on job and `powerTick` clear it; `sayIdleActive`; all through `savePower` (`readKept` strictly, then `writePrivate`) | `consoleOff` (healing, `desiredNow`, `maybeHeal`), `powerMark` (`/status` `poweredOff`, `fleet_status`, fleet notes), `powerView`, `openProblems` (a `problem` only), `powerFirst` (starts), `noteSparkStates`, `darkPeriods` | yes |
| Other files | `energy.json` (GPU and, where a plug reads, wall totals); `api-locked`; `watchdog-misses`, `watchdog-restarts` | status loop; `checkRoute`; the watchdog | status; the TCP lock; the watchdog, `faultView` (the last five restarts, read only) and `openProblems` (restarts in the last day) | yes |
| Funnel was seen on (R49) | `funnel-seen.json` (`seenOnAt`; no secret) | `noteFunnel`, the first time `checkRoute` sees Funnel on for the main address; `deploy/open-to-internet.sh --undo` removes it (closed on purpose) | `waysInNeeds` (`openProblems`): Funnel off while it is there is a needs-you line | yes |
| The state copy: last try, last good one and its mark (`goodMark`), first try (`since`), notice day | `backup.json` (no secret) | `backupState`, `copyLate` | `/health` (`lastBackup`), `copyDue`, `openProblems`, the page's backup line. Unreadable: set aside (its `.prev` answers if it reads), else starts with no record | yes |
| Installing from GitHub, and its way back | `repo.git` beside `go-back.sh` (fetch-only: `main`, `tested/`); the secrets file's `github` (`repo`, `token`); `update-result.json` in the state folder (`tree`, `build`, `result`, `why`, `at`); `pull.sh`; during one install, `update-guard/` and its timer; `install-mark`; `watchdog-silent-since` | `pull.sh` (`setup`, also by `/key GITHUB`, R51; `install`); `update-guard.sh`; the installer (`pull.sh` once kept, the mark); the watchdog | `pull.sh`, the timer, the watchdog; the service reads `github.repo` | yes |
