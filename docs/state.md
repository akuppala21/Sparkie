# Who holds the truth

A change that adds or moves a fact updates its row here.

This table holds what the console keeps in its state folder on the hub (`~/.local/state/spark-console`). What it
keeps anywhere else, or nowhere, is in `docs/state-outside.md`.

| Fact | Lives in | Written by | Read by | Survives a restart |
|---|---|---|---|---|
| Which Sparks exist | `NODES`, from `nodes` in `access.json` (or its last good copy, next row; `config.json` only seeds) | `refreshNodes` | everything | file yes, variable no |
| Who has access | `access.json` (the owner, the Spark list), with a last good copy `access.json.good` beside it; `ownerLogin` in `config.json` wins when present (not set today); cached 10 s. Leftovers: the `members`, `requests` and `invite` an older build wrote there (and `members` in `config.json`) are never read and never removed, so going back a build still finds them (E10d) | nothing in the service: `access.json` is written by hand or by an older build, and on the hub a put-back of the lock-out net writes it and its copy back as they were (next row). `ownAccess` rewrites the copy each time `access.json` reads fine and differs (after a hand edit) | `accessList`, `viewerForLogin` (the owner, or nobody). `access.json` there but unreadable, not JSON or naming no owner: the copy answers and one notice says so; the bad file is never written over or set aside. Missing: no owner yet, copy or no copy | yes |
| Passkeys, sessions, agent keys | `passkeys.json` (public keys and sign counts), `sessions.json` and `agents.json` (hashes) | handler; `passkeyGate` and sign-in (count, last use); `22-sessions`; the last-use timer in `20-mcp`; `putBackAtStart` (after a state put back from a copy: what the owner had removed goes again, every device is signed out, R23). On the hub, a put-back of the lock-out net (the root helper, R60) stops Spark Console, writes `passkeys.json`, `agents.json`, `telegram.json`, `access.json`, `access.json.good`, `door.json` and `cloud.json` back as they were before the change where they differ, and starts it again | the gates; `accessView` (names, times and counts for `sparkie_setup`’s `access`, the owner’s own call only, A5). Unreadable passkeys or agents file: 500 (in `accessView`: `passkeys` is null with a `problem` line; `sparkie_setup` still answers). Unreadable sessions file: every device signed out; in no daily copy; an install snapshot holds it and never puts it back (R23) | yes |
| What should be running | `desired.json` (never the self-test’s own model, R22). A model entry has `model` (and `sparks` across two); an app entry (keep_running) has `app: true`, `port`, `memoryGB` and no `model`. Every entry has `since`: its last start that wasn’t self-healing’s (`displacedBy` reads it, R19). `parked` (a time): stopped to power its Spark off, still on the list (R41) | `desiredAfter` (job completion; clears `parked` and `putBack`); `parkDesired` (only `parked`); `desiredPutBack` (a saved workflow’s clean-up puts an entry back, marked `putBack`, R57); `watchHeld` (first seed); `markUndone` in `undo_last_change`; `POST /desired/forget`; `keepApp` (an app already running joins, or its port and memory figure follow Docker); `forgetApp` (an app's stop while its Spark is off). Each reads the list strictly first (R20) | `healPass` (apps: `healApp`), undo, start-on-call, `desiredNow` (`should_be_running`, `GET /desired`, `watchHeld`; apps: `appNow`; a held model or app carries `sparkOff` or `dockerDown` when its Spark is off or its Docker didn’t answer), the bring-back route, `fleetNotes`, `openProblems` | yes |
| Heal attempts | `heal-tries.json`, loaded once into `healTries` | `saveHealTries` | `maybeHeal`, `bringBack`, `watchBrain`, `keepBrain` (key `keep:<spark>/<container>`) | yes |
| What a self-test under way has started | `self-test.json`: its operation, the chat that asked, the Spark, when it began, and for its model, web page and job the container name and, once Docker has one, the full id (the model’s while it still loads). No secret | `selfTest` (`keep`, `21-selftest.mjs`), through `writePrivate`; removed when the run ends | `readKept`: `selfTestRecover` at start-up, `selfTestCutOff`, `self_test` (refuses while one is pending), `selfTestModels` (the list’s first seed and `maybeHeal` pass over its model) | only during a run, or after a restart cut one off until `selfTestRecover` has stopped what it started (a Spark that doesn’t answer is retried each minute); the daily copy and install snapshots copy it too, harmless there |
| What a saved workflow under way has started | `saved-runs.json`: each run’s operation, title, chat, step, what its steps started (`started`, `pending`) and the Sparks it keeps awake. No secret (R57) | `savedRunKeep` as the run goes, `savedRunDone` when it ends, `savedRunsRecover` | `savedRunsRecover` and `savedRunCutOff` at start-up | only during a run, or after a restart until the start-up clean-up; in no copy (`sendCopy`), and `restore.sh --with-state` removes it |
| The lock-out net's guards | `net.json`: every change made inside the net that is still open (or whose put-back did not finish) and the newest 50 closed ones, each its id, Spark, state (`arming`, `open`, `kept`, `put back`, `timer`, `part`, `never`), when it goes back, its record and chat, and for a put-back that did not finish `unfinished` with the helper's count. No secret (R71) | `netSave` (`21-net.mjs`), as a change inside the net goes, `/putback` and at start-up | `netGuarded`, `rootChange`, `netPutbackWord`, `netRecover` at start-up | only after a change inside the net |
| Which version is validated | `validations.json` | `recordWorkflowRun` only | `workflowStatus` | yes |
| Spark Console’s own updates | `updates.json`: the newest 20 records (`at`, `build`, `previousBuild`, `stamp`, `note`, `result`: `first record`, `installed` or `went back`); `update-note.json`: the build and the note the installer was given (`NOTE=`) | `noteUpdate` only, once at start after the local port is bound, only when the build differs from the last one on record (`went back` when `update-note.json` doesn't name the running build); every install writes `update-note.json`, going back never does | `sparkie_setup` (`console.updates`, the newest five, notes labelled as data) | yes. It is state, so going back a build keeps it; `restore.sh --with-state` puts back the older record. A build that never started leaves no record |
| Proven runs | `verified.json` | `recordVerified` only | `bestHow`, `resolveHow`, `recall`, page; `runningDetail` (names the setup only when a recorded run has exactly a running container’s model, engine, image, Spark count and flags) | yes |
| What failed (lessons) | `lessons.json`: one record per setup and known failure (B 2.2 as cut): its kind (`start` or `app`), subject, the setup tried, the failure id, `seen` or `proven`, the count, the journal ids of its newest three operations. Only the console's own typed values, else null: no `fix`, no log's or brain's words, no key (R48) | `recordLesson` only, called by `learnFrom` at `runJob`'s end: a failure adds a lesson or counts again; a success of the same setup takes its lessons out | a start, before it picks a setup: one that failed twice the same known way is passed over (`failedTwice`, B3); `recall` | yes |
| Recipes | `catalog.json` (shipped in the service folder, replaced on every install; not in the state folder) + `added-models.json` + `found-setups.json` | catalog builder; `addModel` (the page’s add routes; `startModel`’s download job and `find_setups`, for a Hugging Face repo the asker named in full or said yes to, A9); `digModel` | `recipeCatalog`, read fresh each call | yes |
| Saved workflows | `saved-workflows.json` | `save_workflow`, `forget_workflow`, `run_workflow` (last run, only for the steps it ran), `compare_models` (`compared` and `best`, R57); all through `writeSaved` | `workflows`, `run_workflow` | yes |
| A Spark’s last readings | `knowledge.sparks[id].gpu` (status check) and `.readings` (watcher); copied into `spark-offline` as `last` | `noteSparkStates`, `watchSpark` | `fleet_status`, `spark_diagnostics` (`darkPeriods`), Sparkie’s fleet notes | with the knowledge file; used only when under 3 minutes old |
| The copy from before the last save | `<file>.prev` beside each file `writePrivate` saves after `readKept` read it in this process: `added-models.json`, `found-setups.json`, `verified.json`, `lessons.json`, `validations.json`, `saved-workflows.json`, `desired.json`, `memory.json`, `memory-past.json`, `updates.json`, `backup.json`, `brain-profiles.json`, `power.json`, `net.json`, `self-test.json`, `saved-runs.json` (0600; rides in the daily copy and install snapshots; no secret; never for sign-in files) | `writePrivate`, just before each save | `readKept`, only when the file itself is not JSON | yes |
| Memory | `memory.json` (`{entries}`, the live lines, no ceiling; each with who it is from, `by`, and where from, `src`) and `memory-past.json` (`{past}`, the lines replaced, forgotten or past `until`, each with `gone`: when, why, the line that replaced it, who), R45 | `saveMemory` only, for `remember` and `forget_memory` (the past file first). Both are in the daily copy and install snapshots. Forgetting, also by the page’s Forget button, only retires a line. Erasing one for good (`eraseLine`: the owner’s call or a button in Spark Console) takes it out of both files, saves both twice so neither `.prev` holds its words, and blanks them in a copy set aside (`.unreadable-*`) or half-written (`.tmp`); the chat, the journal, `audit.jsonl`, daily copies already sent and install snapshots already taken keep them | `memoryPrompt` (a read error: the turn runs without the lines and the prompt says memory couldn’t be read; past 4,000 characters of lines, the newest that fit and how many more), `memory` (`past: true` reads the past file, owner only; a read error there answers 503 and forgetting writes nothing); `recall` | yes |
| Memory lines' names | `about` on each line (R45); in memory, made at start: names known (`memoryNameBook`), lines by name (`memoryIndexNow`) | `remember`, `saveMemory` | `memory` (owner's call) | the names only |
| Chats | memory `chatStore`; `chats.json` is a copy with its own writer (`saveChats` never throws: a failed write keeps the store in memory, the next save retries); also the task a request carries on as (`conv.task`, R66: the request, where it came from: `channel`, `away`, its tool `groups`, R46, its limits and guards): set when a request with a next step starts an operation or gets a button for its first change, also when that reply then fails; kept through a typed yes and a restart; ended by the owner’s next request, `/stop`, a pressed No, a carry-on turn that owes nothing, its way in going or a state put back; at a limit it stays, stopped, until “carry on”; and what the chat read from outside, by journal record (`conv.reads`, the newest 40, R26) | `sparkieTurn`, `runChoice`, `postResult`, `continueTask`, `stopTurn`, the `/chats` routes, `askSparkie` | chat routes, `ask_sparkie`, `wakeWork`. Unreadable: set aside, new empty store. The owner’s words and Sparkie’s answers are masked when saved (R7, F20) | yes, except what was said while saves were failing |
| Containers seen; history | memory `knowledge` (`knowledge.json` is a copy, saved when the watcher sees a change and at once when a Spark goes dark or comes back, `noteSparkStates`; `knowledge.sparks[id].dockerDownAt` while Docker isn’t answering there; a job’s row carries `endTold` once its end was told, and is set running when run again, A13) and `events` (last 500; `events.jsonl` rotates at 5 MB) | watcher; status loop (`knowledge.sparks`); `fleetEvent` | healing, passkey gate, fleet notes, `pickContainer` in the intent gate, `desiredNow`, `workloads`, `fleet_events` (`workloads` and fleet notes go through `sparkOff`: rows on a Spark off or not answering show as last seen, not running; the other readers use the stored rows) | yes |
| Status; cable test | memory `statusCache`; memory `lastCheck` (`links.json` is a copy) | `collectStatus`; `fabric(check)` | page, placement, `clusterNet`, public page | no; yes |
| Pause and auto-restart; what is always allowed (R65) | `agent-settings.json` (unreadable = paused, nothing always allowed); `allowed`: at most 50 kinds of change (a Spark, a program, a folder) that run without a button in the owner’s chats when their words ask for a change | `setAgentSettings` (the page’s switches, `pauseWord`, `tripBreaker`, `putBackAtStart`; `allowed`: `aheadKeep`, at the owner’s press of “Always allow” on the page, and `/allowed off`) | `runAction`, `pausedCheck`, healing; `aheadCover` (`allowed`; none while a state put back is held) | yes |
| Brain setup and routes | `MAIN`, `ROUTES`, loaded once from `config.json` + `main.json`; `leftDown` in `main.json` (Spark Console took the brain down and hasn’t seen it answer since) | `switchMain`, `setRoute`, `markBrainLeftDown` | chat, `/v1`, healing, `keepBrain` | yes |
| How the brain calls tools | `brain-profiles.json`: one profile per brain setup, keyed by a hash of model, draft, engine, image, flags, environment, rope settings, how it is asked, its limits and what runs (never the name); each names those, this build's `brainReads` from the lock (null when the lock isn't this build's), the outcome (`checked` or `not checked`) with why, each request tried and what came back, and `evals`: the eval's results, by what the brain read and the case set's version (`"<reads>:<set>"`), five full main-set runs and five others each, six of those, sealed with the key in `eval-seal.json` beside secrets.json (R47, R52; kept by a new check); `trial`: the coding trial's newest five results, sealed alike (R67). The newest 50. No secret (environment names only) | `saveBrainProfile` only (`brainCheck`; `storeBrainEval`, the owner's `POST /main/eval`; `keepTrialRecord`, the owner's `POST /main/trial`) | `brainCheckView` (`sparkie_setup`'s `brainCheck`, with `brainEvalView`), `checkBrainSoon` (is there one yet), `brainRail` (R52: a change runs at once only while it counts), `trialPassed` (R67) | yes |
