# Can Sparkie use what it learns in a later task?

The tests use ordinary Hermes sessions and the selected single-Spark Huihui model. Each exercise checks the answer the owner receives, the evidence the assistant actually read, and any persistent result a different session can recover. The held-out cases use the same prompts, local serving settings and inputs for both versions of the research skill.

| Check | Observed behavior |
| --- | --- |
| Find an exact version | Sparkie fetched the publisher's p-limit v6.2.0 README, opened it, and correctly answered all three questions about that version. The turn took 24.877 seconds and used two tools. |
| Use research to fix code | Sparkie reproduced an HTTP retry bug, checked the upstream p-retry v7.1.1 documentation, changed the retry-budget option and reran the tests. An independent clean install reproduced the fix. The owner turn took 149.765 seconds. |
| Recall a blocked comparison | A fresh session opened the saved Larkspur project record and reported that there were no new measurements and no winner. It identified the missing service endpoints. It completed in 31.602 seconds. The preceding session saved the record but timed out before returning a final answer. |
| Finish and remember the same blocked task | With a shorter response from the unavailable service catalog, Sparkie wrote a single project record, read it back, saved a native memory pointer and delivered its answer in 180.913 seconds. A new chat reopened the record and gave the correct status in 38.066 seconds. This comparison uses a single run per version. |
| Verify a newly measured result before saving it | Sparkie collected six timed CPU completions, calculated the two medians and saved a discoverable measurement note. The request called for a warmup for each cache setting. Seven recorded completions included just one warmup. Sparkie described the protocol as complete, so this first attempt failed. The raw timings remain historical observations. |
| Recheck a remembered result | The evaluator added a dated correction to the project record and kept the old skill and raw measurements intact. A fresh chat loaded the old skill, read the corrected record, identified the missing warmup and said the timings could no longer support a comparison. The owner question gave no hint about the correction. The turn took 65.672 seconds. |
| Check what a citation proves | The native quote checker rejected an invented quote and an unknown citation. It accepted a draft whose conclusion contradicted its real quotation. This is why each research answer is graded against what its sources actually establish. |

The [four-question comparison](blind/public-results.md) kept the incumbent research skill. The proposed wording recommended publishing a 70% improvement based on unrelated jobs. Both versions found the genuine sources. On those eight turns the user never requested retention, and neither version deliberately wrote a reusable finding. Native research memory is enabled in the application profile, while automatic background review is disabled. A verified project record can improve a later answer when the agent retrieves it. None of these runs updated model weights or established a general accuracy rate.

The [held-out prompts](blind/inputs), [frozen rubric](blind/rubric.md) and [reproduction procedure](blind/reproduce.md) cover a versioned dependency, mismatched benchmarks, a withdrawn measurement and a simple calculation. The calculation measures the effect on ordinary chat. Each score belongs to its sampled turn, and a failed first attempt remains in the record.

The [measurement and recall exercise](recall/README.md) includes the exact prompts and independently recalculated sample counts. A stricter measurement skill produced the required eight requests but timed out before handing the answer to the owner. Research3 includes only the shorter unavailable-catalog response from these trials.

The sealed research3 package passed 452 affected tests in 66.95 seconds and nine automated local behavior checks in 140.53 seconds. The first affected-test container lacked the systemd parser, which caused one setup failure. All 452 tests ran again with the parser available. A manual read of the compact research answer found an unsupported extrapolation: the cited source ruled out YaRN on that build, while the answer ruled out further context extension. Ordinary fact-finding and memory can help on these tasks. Consequential conclusions still warrant checking against the specific source.
