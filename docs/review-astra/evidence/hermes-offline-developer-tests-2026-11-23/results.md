# Running the ordinary Sparkie test selector offline

A fresh non-root worker ran `python3 tools/checks.py --paths tools/checks.py --run-python` without a cache, credentials, writable host mounts, or package installation during the test. All 43 selected tests passed in 1.81 seconds, including registration with the actual Hermes plugin manager. The worker command took 2.802 seconds including workspace setup and checks of its interpreter and pins. The earlier same-container run passed the same 43 tests in 1.71 seconds. The fixture used the read-only release and base interpreter file trees at the exact absolute paths the source export supplies. It did not call a live `spark_update_source` or copy the owner’s home. A provisioning worker used its own copy of the pre-stocked cache. Native uv installed only the frozen upstream dev group, including its declared transitive extras, into a separate environment. A plain two-line `.pth` file made the matching Hermes source and production dependency directory available there. All package choices came from the sealed lock. In the measured provisioning run, copying the prepared cache into private storage plus frozen sync and writing the links took 276 ms. That excludes initial cache staging, container startup, and exporting/mounting the resulting environment. The prepared environment occupied approximately 120 MiB and the supplied wheel cache 121 MiB. [Provisioning helper](prepare-dev.sh) · [uv result](ready-prep.log)

For the independent run, a separate container used an empty home, UID 12001, a read-only root and no network. The prepared environment was mounted read-only **at its original absolute path**. Only its `bin` directory was prepended to the normal `PATH`. `PYTHONPATH` was empty. The workspace and temporary directory were disposable memory filesystems. No cache was mounted. Runtime and base interpreter were mounted read-only. The source checkout was copied to `/workspace/sparkie`. The standard command and the actual imports are recorded in the shell fixture. No fixture container remained. [Fresh-shell checks](test-normal.sh)

The first cache-copy attempt encountered unreadable, unrelated operator cache directories under the non-root UID. A private wheel-only staging copy avoided this. An early filtered cache omitted `pyjwt[crypto]`’s declared extra, which caused uv to reject the missing `cryptography` wheel. Including the full frozen dev dependency graph resolved it. An initial export through Docker’s file-copy command could not read the tmpfs payload. Streaming the prepared directory through the provisioning container and giving the test UID read/traverse access to that private copy preserved the interpreter's absolute path and produced the verified result. The sealed predecessor and operator cache were untouched.

The matched coding trial’s original harness explicitly mounted an operator pytest layer and supplied a project-local guide for that qualified interpreter. Those extra fixture mounts are a separate setup from a normal application source export. The verified default development PATH addresses the environment gap. It does not establish whether a local model will diagnose or repair the nested-test defect. A prompt change for the optional maintenance skill is a separate untested proposal.
