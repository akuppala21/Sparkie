# Power and reachability on the Sparks page

A powered socket can coexist with an unreachable computer. If a verified plug reports power on and the collector's management probe fails, the shared fleet reader now returns that explanation alongside both observations. Workloads remain unknown. The change affects the authenticated fleet API, the model's fleet observation and the native Sparks panel. It sends no command to the Spark or plug.

On Spark 2, 42 affected Python tests passed in 1.84 seconds. A separate Chromium check opened the isolated native dashboard at 1440 × 960 and 390 × 844. In both, the card showed the failed management check and 43.1 W from the synthetic plug. The authenticated API returned unreachable, null workloads and the matching measured power. Both viewports fit without horizontal scrolling. A controller-cache-only reading and a verified power-off report retained their existing behavior.

The worker mounted the edited fleet reader over the sealed test release. Its dashboard used a temporary login and fixture readings. The code SHA-256 was `b8499de586a8d0165db3fa9dd250eee7187767ab69f6712858a785bfc892d817`. This qualifies the targeted display and API change. Live power management, inference and a production installation were outside these checks.
