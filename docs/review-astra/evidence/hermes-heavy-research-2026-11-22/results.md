# Can Sparkie finish a research-heavy decision?

The development branch adds an optional public-manual reader to Sparkie's existing Hermes research skill. It retrieves exact publisher pages, saves the originals with hashes, and returns short, line-addressable passages. The selected package keeps research6’s instructions and one-Spark Huihui model. Hermes adds one 25-byte line to the normal prompt listing the new script among the skill’s supporting files. Three experimental changes to the always-loaded instructions are preserved with the evidence. [Using the reader](reader/usage.md) · [Comparison method](method.md)

## Independent checks

The final reader passed 26 focused tests on Spark 2. It retrieved the curl changelog, the current curl manual, two CPython tarfile manuals, and three SQLite pages. The old parser mistook 130 sibling HTML list items with omitted closing tags for deeply nested items and rejected the curl release note. The repaired reader returns the exact line announcing the option and retains its limit on genuinely deep input. The source check includes the tagged curl option definition. [Publisher receipts](reader/curl-fix/receipts/publisher-pages.json) · [Focused results](reader/curl-fix/receipts/focused.log)

The evaluator built curl 7.75.0 and 7.76.0 from the official sources. A loopback HTTP server returned known JSON on 200 and 503. Every suggested script ran as a complete shell job, so its final exit status counted. On both versions, the short-advice primary script saved the correct body, succeeded on 200 and failed on 503. Its optional variation also failed on 200. These independent replays establish what those scripts do. The model’s tests used a newer client. ## The selected optional reader

In a fresh chat the evaluator explicitly asked Sparkie to use the bundled reader to identify a curl option. Sparkie first tried a host-side path, recovered inside the Hermes terminal, found the exact line, and returned the correct option and release URL in 80 seconds. It added a misleading explanation that implied pairing the option with `--fail`. The original definition calls it an alternative. Source retrieval and the requested fact passed. The whole answer was partial. [curl 7.76.0 release note](https://curl.se/ch/7.76.0.html) · [Tagged option definition](https://raw.githubusercontent.com/curl/curl/curl-7_76_0/docs/cmdline-opts/fail-with-body.d)

The isolated package built in 11.80 seconds. All 146 affected tests passed in 8.13 seconds. A protected, unprivileged CLI read of the actual release note returned the expected source line. The initial assembled smoke assumed a byte-identical rendered prompt and failed. Independent native renders showed the sole difference was one supporting filename. The corrected smoke checked the exact difference and passed, including one simulated, owner-confirmed action. The sealed manifest is `9b55894f361a60e89bc13375a020315a458a50343f4d972e42072adaf1846b85`.

The selected package passed eight of nine compact behavior cases in 214.86 seconds. On the failed case, the assistant correctly reported an unknown address as JSON null. It also wrote a diagnostic marker to the isolated user-memory file while trying to read memory. Its attempted removal left the marker in that file. A fresh factual question must not mutate the owner's preferences. The schema-checked research answer cited the supplied sources and kept its benchmark conclusions within their stated conditions on this attempt. The simple compact question took 11.128 seconds to first visible text against the ten-second target. These are observed failures and timings on the selected package. This comparison cannot attribute them to the filename added by the reader. [Selected-package qualification](qualification.json)

## Development decision

The optional reader can be used directly in the Hermes workspace. The automatic prompt changes remain experiments. An accurate citation or a successful tool run does not establish that every line in the final recommendation is supported. The native tool and ordinary model behavior were assessed separately. [Research7 instructions](trial-skills/research7/SKILL.md) · [Research8 instructions](trial-skills/research8/SKILL.md) · [Research9 instructions](trial-skills/research9/SKILL.md)

Across the twelve ordinary chats, nine delivered an answer and three timed out. The full live update remains on hold. Spark 1 remained online. After the test supervisor expired, three checks found the model, its sandboxes and GPU processes gone from Spark 2. The fleet recorded no holds on Spark 2 and retained its 30-minute idle-power policy. Sparks 3 and 4 were off.
