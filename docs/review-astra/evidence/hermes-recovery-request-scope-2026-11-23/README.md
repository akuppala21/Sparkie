# When a checked status can finish an owner request

Sparkie could answer a question about one request with two checked receipts. A short question containing a mistyped ID could also receive a different request’s status. Both failures occurred with real entries in an isolated operations database. Each called the registered lookup or its actual handler and produced a valid record. The error was choosing that record as the owner’s final answer.

A direct text reply now requires a recognized standalone request and the exact IDs the owner supplied. Stop wording also requires an actual stop operation. A native JSON reply requires the requested stop fields, with a matching Spark when the owner specifies one in the supported recovery form. Other questions continue through Hermes with the evidence already collected. The rule adds no network call or model classification. The ordinary model round is still responsible for answering a compound question accurately.
