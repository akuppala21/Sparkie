# Frozen rubric for the public-source release question

The assistant receives only question.txt, in a fresh ordinary session with an empty project workspace. Grade material accuracy, first-party source access, citation quality, actionable advice, timing and completion separately. The operator verified both releases against the publisher before running either arm. The first-party references are the release-specific library manuals.

| Required conclusion | Evidence |
| --- | --- |
| Stock 3.13 falls back to the equivalent of fully_trusted when the extraction call omits the filter. A DeprecationWarning is issued and may be hidden. Mentioning the warning is a detail, not a required gate. | [Python 3.13 extraction_filter](https://docs.python.org/3.13/library/tarfile.html#tarfile.TarFile.extraction_filter) |
| Stock 3.14 uses data for the same call and restricts some dangerous archive features. Do not claim it forbids all links or blocks every absolute input name instead of handling it as documented. | [Python 3.14 extraction_filter](https://docs.python.org/3.14/library/tarfile.html#tarfile.TarFile.extraction_filter) |
| Both versions accept an explicit data filter on extractall. Recommend it, or its callable equivalent, on both releases for consistent behavior. Neither filter guarantees protection from disk exhaustion. Recommend an enforceable disk limit for the job, such as an externally enforced filesystem quota, with additional per-archive caps or inspection where appropriate. A temporary directory alone does not enforce a quota. | [Python 3.13 extraction filters](https://docs.python.org/3.13/library/tarfile.html#extraction-filters) and [Python 3.14 verification guidance](https://docs.python.org/3.14/library/tarfile.html#hints-for-further-verification) |

A full answer gives both correct defaults, the limited protection, and a concrete mixed-version filter and disk plan, with correct release-specific first-party references. A material reversal, an assertion that default filtering prevents exhaustion, or unsafe migration advice fails. A useful incomplete answer is partial. Minor release-specific nomenclature or unimportant omissions are recorded separately.

Inspect native tool traces independently for original Python documentation contents, including release provenance and relevant lines. A search snippet, correct prior knowledge, uninspected URL or accurate answer without verified retrieval does not establish public-source research. Accept one version's genuine primary document if it explicitly supports both release defaults and the uncovered risk, provided the report records that only one release was read. Two independent versioned originals provide fuller coverage. Record tool and model counts, first visible and completion times, any claimed implementation or actions and extra unsupported claims for each arm.
