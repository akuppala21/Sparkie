# Actual test results in a repair report

The affected-test command now ends with the number of path arguments passed to pytest, the number of tests selected after filtering, the number that started, pytest’s own summary, and its exit code. That gives a repair agent the evidence it needs to distinguish a single passing control from a passing suite. Other required check groups remain visible after a failure.

On the portable development sources, the command ran 50 affected tests across four paths on Spark 2 in 3.10 seconds. The standalone regression also exercised a filter selecting one passing control, a failing assertion with a passing control, an unmatched filter, collection without execution, and stopping at the first failure. Each resulting JUnit file was compared with the command output. A documentation-only selection produced no JUnit file. [Executable regression](demo.py)

A separate change to the developer’s research evidence checker keeps a quoted value attached to its unit before calculating a ratio. For example, a document may mention 12 seconds and eight items per second in the same sentence. Its text cannot support a claim of 12 items per second. Compound units and units found on another row must also be kept separate. All four misleading inputs reproduced the defect with the previous checker. On the corrected sources, 27 selected tests passed in 1.88 seconds, including matching measurements and prefixed currency. This optional checker adds no inference or overhead to ordinary chat.
