1. On stock PostgreSQL 11 an ALTER TYPE ... ADD VALUE on the stated existing enum cannot run inside an explicit transaction block. Distinguish the already-existing type from a type created in the same transaction. The latter is outside the question. [11 ALTER TYPE, Notes](https://www.postgresql.org/docs/11/sql-altertype.html)
2. On PostgreSQL 12 that ALTER may execute inside a transaction, but the added value cannot be used in an UPDATE before the transaction adding it commits. An earlier semicolon, savepoint or a separate file still inside the same enclosing transaction does not create the necessary commit boundary. [12 ALTER TYPE, Notes](https://www.postgresql.org/docs/12/sql-altertype.html) · [12 release notes](https://www.postgresql.org/docs/12/release-12.html)
