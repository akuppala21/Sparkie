# R60

## Rule

**R60.** The lock-out net: confirm, or it goes back. A change that could lock the owner out runs only with a put-back
armed first, in the Spark's own systemd, which fires with the console, the network or Tailscale down.

- **Armed in the same call, before anything changes.** The root helper's `run --net` (R42) refuses while another
  guard is open on that Spark (`pending`, neither kept nor put back, not the proof's own), then, as root, copies the
  ways in to `/var/lib/spark-console/guard/<id>/`, writes `restore.sh` and `guard.py` beside them (the helper's own
  text: its sudo line lets nothing else be root), writes `pending` and the unit `sw-guard-boot-<id>` that runs the
  same put-back if the Spark restarts inside the window, and arms the timer `sw-guard-<id>` for the command's own time
  limit plus 600 s, so it never fires under a command still running. A change inside the net is held to 30 minutes.
  If arming fails or the call is hung up meanwhile, what this call made is taken away and nothing runs; a refusal
  never touches a guard this call did not make (the same id sent again leaves it as it was).
- **The ways in** (design A 2.8, row 2, and the review of A13a): `/etc/ssh`, `/etc/default/ssh`, `/etc/hosts.allow`,
  `hosts.deny`, `/etc/nologin`, `/etc/sudoers`, `sudoers.d`, `/etc/sudo.conf`, `passwd`, `group`, `shadow`,
  `gshadow`, `nsswitch.conf`, `/etc/pam.d`, `/etc/security`, the system's and the owner's shell start files, the
  owner's `authorized_keys`, `authorized_keys2` and ssh `config`, `/etc/netplan`, `/etc/systemd/network`,
  NetworkManager's connections, `/etc/hosts`, `/etc/ufw`, `/etc/default/ufw`, `/etc/iptables`, `/etc/nftables.conf`,
  Tailscale's state file and `/etc/default/tailscaled`, systemd's files for ssh and tailscaled by name (the units,
  their `.d` folders, the links that enable them), the owner's linger file and service manager's units, and on Spark 2
  the console's sign-in files. A file is copied with its bytes, mode and owner; a link as a link, never followed; a
  folder with all in it; a path that is not there as not there (made in the window, it is taken away). Each folder
  above them, up to the owner's home (and `/var/lib/tailscale`, `/var/lib/systemd/linger`), is kept as a folder: its
  mode and owner. Tailscale's settings and serve routes and the live firewall rules are kept as text, to compare.
- **After the command**, nothing differs: the guard disarms itself (timer stopped, `pending` and the restart unit
  gone). Something differs: it stays open and says what goes back by itself, and when, and apart what does not (the
  live firewall rules; Tailscale's settings when its state file is as it was).
- **The put-back** (`restore.sh`, from the timer or after a restart) stops the command's unit and waits until it is
  gone, then puts back only what differs: exact bytes, mode and owner, through folders opened one by one without
  following a link; a folder above that is gone is made again, but only `~/.ssh`, the console's state folder,
  `/var/lib/tailscale` and `/var/lib/systemd/linger` are swapped back for a folder when a link stands there: at the
  home or a folder between (`.config`, `.local`) a link is left, and what is under it is named not put back. What the
  change added in a copied folder is taken away, and a folder above the copy did not see only once it is empty. It
  reloads only what it put back (systemd, ssh, the network, ufw, Tailscale, the console's unit) and writes `result`,
  whose first line counts what went back and what did not (after a restart the live rules and Tailscale are not
  counted: they have not started). Once kept or put back it only clears what is left (`pending`, the restart
  unit); `keep` does the same.
- **`keep`** counts only while the timer still waits and once its stop succeeded; after a put-back it answers
  "already put back at …" with the result's count. `check` names an open guard, when it goes back, and whether its
  timer waits. A walled command cannot stop or change the timer, write the guard's folder, take `pending` away or make
  `keep` count: the proof tries each (attempts 15 to 18, R42) on two guards of its own, which carry its mark, block
  no other guard, and are taken away by the next proof if one was left behind.

## Why

A change to SSH, the firewall, Tailscale or a sign-in can cut off every way the owner reaches a Spark, and the console
with it. Like `netplan try` and a router's "commit confirmed", the change goes back by itself unless it is confirmed,
from a timer nothing a change can reach (the one page, sections 4 and 7, item 2;
`docs/design-2026-11-13/a-workspace.md`, 2.8 and 2.13).
