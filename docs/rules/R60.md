# R60

## Rule

**R60.** The lock-out net: confirm, or it goes back. A change that could lock the owner out runs only with a put-back
armed first, in the Spark's own systemd, which fires with the console, the network or Tailscale down.

- **Armed in the same call, before anything changes.** The root helper's `run --net` (R42) refuses while another
  guard's `pending` mark is on that Spark, then, as root, copies the ways in to `/var/lib/spark-console/guard/<id>/`,
  writes `restore.sh` and `guard.py` beside them (the helper's own text: its sudo line lets nothing else be root),
  writes `pending` and the unit `sw-guard-boot-<id>` that runs the same put-back if the Spark restarts inside the
  window, and arms the timer `sw-guard-<id>` for the command's own time limit plus 600 s, so it never fires under a
  command still running. A change inside the net is held to 30 minutes. If any of this fails, it is taken away
  again and nothing runs.
- **The ways in** (design A 2.8, row 2): `/etc/ssh`, `/etc/sudoers` and `sudoers.d`, `passwd`, `group`, `shadow`,
  `gshadow`, `/etc/pam.d`, the system's and the owner's shell start files, the owner's `authorized_keys` and ssh
  `config`, `/etc/netplan`, NetworkManager's connections, `/etc/hosts`, `/etc/ufw`, `/etc/iptables`,
  `/etc/nftables.conf`, Tailscale's state file, the owner's service manager's units, and on Spark 2 the console's
  sign-in files. A file is copied with its bytes, mode and owner; a link as a link, never followed; a folder with all
  in it; a path that is not there as not there. Tailscale's settings and serve routes and the live firewall rules
  are kept as text beside them, to compare.
- **After the command**, nothing differs: the guard disarms itself (timer stopped, `pending` and the restart unit
  gone). Something differs: it stays armed and says what, and when it goes back.
- **The put-back** (`restore.sh`, from the timer or after a restart) stops the command's unit and waits until it is
  gone, then puts back only what differs: exact bytes, mode and owner, through folders opened one by one without
  following a link; what the change added in a copied folder is taken away. It reloads only what it put back (ssh,
  netplan, NetworkManager, ufw, Tailscale, the console's unit), writes `result`, and takes `pending` away. Once kept
  or put back it does nothing.
- **`keep`** counts only while the timer still waits and once its stop succeeded; after a put-back it answers
  "already put back at …". A walled command cannot stop or change the timer, write the guard's folder, take
  `pending` away or make `keep` count: the proof tries each (attempts 15 to 18, R42).

## Why

A change to SSH, the firewall, Tailscale or a sign-in can cut off every way the owner reaches a Spark, and the console
with it. Like `netplan try` and a router's "commit confirmed", the change goes back by itself unless it is confirmed,
from a timer nothing a change can reach (the one page, sections 4 and 7, item 2; `docs/design-2026-11-13/a-workspace.md`,
2.8 and 2.13).
