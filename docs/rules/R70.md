# R70

## Rule

**R70.** Root, only where the owner turned it on, and only inside the net. The root helper's `root` verb runs one
command as root on a Spark, on these terms, each the helper's own text:

- **Root's switch, off by default.** `/var/lib/spark-console/root-on`, which only the owner's one-time command writes
  (`--with-root`, after a passing proof): root's, 0600, in a folder only root can change, one line with the day and this
  helper's SHA-256. `--without-root` and `--undo` take it away; a plain run leaves it as it is; a new build of the
  helper finds it is not its own, so root is off again until `--with-root`. Never on Spark 2: the one-time command
  refuses `--with-root --hub` (the console refuses a root command there). Without it, or when it is not exactly so (a
  link, another owner, a wider mode, a folder others can change, another line, another helper's hash), `root` refuses
  before it reads anything else of the call and says why; `check` says "root off" ("this helper is newer than the one
  root was turned on for" in the last case), "root ready" or "root refuses" and why.
- **Inside the net armed in the same call** (R60). `--net` is required. The ways in, and what the call names
  (`--path`: up to 32 files or folders; `--unit`: up to 16 units), are copied first and the timer armed; if arming
  fails nothing runs. Held to 30 minutes, 10 with `--lockout` (the console says the lock-out class), the timer that plus
  600 s. A named unit goes back as the ways-in units do, and is reloaded or restarted when anything went back.
- **The bytes the press approved** (P-5). The command is the one word after `--`, or with `--stdin` a script's bytes on
  input, never both; either is written once to a root-owned file, hashed against `--sha256`, and that file is run by
  bash. No shell is built from pieces.
- **Its own unit**, `sw-root-<id>`: `state --id`, `stop --id` and the put-back (`putback --id`, the timer, a restart)
  find it, and the put-back stops it before the first copy back. Its settings keep the helper and its line read-only
  and the helper's folders out of sight; root can undo them. The answer says "as root" on the line after "net armed".
- **A guard on names, not a wall.** A command, or a `--path`, that names the helper, its sudo line, `/etc/sudoers*`,
  `/etc/sudo.conf`, PAM (`/etc/pam.d`, `/etc/pam.conf`, `/etc/security`, PAM's modules), the helper's folders
  (`/var/lib/spark-console`, root's switch with them; `/run/spark-console`) or the net's own units (`sw-guard-`), by a
  word anywhere (quotes and backslashes taken out) or by a path resolved through its links, runs nothing: those change
  only by the one-time command. Root can do anything, the net's switch-off and root's own switch included: what bounds
  a root command is the net and the owner's press, never these names.
- **The proof** (attempt 13) calls `root` without `--net`, and with `--net` while root is off: each must be refused.

## Why

Root for Sparkie only where the owner said so, always with a way back: with the helper's sudo line in place, every
program running as the owner could otherwise become root without a password before the console's ask, its record and
the read of the chain exist (the one page, sections 4 and 7, items 1 and 2; design A, 2.13 and step 12; the safety
critique's P-5 and P-1's time limits).

## Today

Both halves of A12 are built and on (`ROOT_ON`, with the net's switch); off (a stand-in fleet's off side), `run` has no
`root` in its schema. `run` with `root: true` is refused on Spark 2, on a Spark holding the brain, in the box and while
changes are paused. On any other compute Spark it is always the dangerous ask, "ROOT on Spark 3" (and "CAN LOCK YOU OUT"
for the lock-out class), never at once and never under a go-ahead or the standing list, never with a key, minutes, fleet
or gpu. It is sorted as root (`sortCommand` with `root: true`; the folder and home as `run` takes them), so the
sorter's root-only rules decide its class: `kill 812` or `kill 1` as root is the lock-out class. Root refuses on the
sorter's own fields, with no list of its own (`rootUnseen`): a script or other file run as code (`scripts`), code the
sorter says isn't all on the button (`unshown`: any interpreter's one-liner too, which loads from the folder it starts
in, A-16; its program from its input, a module or a file, and the rest the sorter names), and work it starts later, off
the button and outside the net (`later`: `systemd-run`, `at`, a timer, a schedule or a unit written). Its words say the
plain truth: root never runs code the button doesn't show, and no way round that is offered. A limit: a unit or drop-in
file written as root is refused (`later`), so the owner makes it by hand on the Spark, over SSH. A program the sorter
doesn't know (`unknownProgram`) is asked, and the ask says so in one line (`rootLines`). Never a mount, an unmount or a
swap (root's unit has its own mount table, so the Spark would never see it: `rootMounts` answers how to do it through
systemd); never a command the shell reader can't read whole (`rootUnreadable`); and in the lock-out class only when
a sentence of the owner's current message tells it to change a way in on that Spark (R71's test), with nothing read
since (else refused, saying how to ask, `netWhose`, contract 8.3); only its press runs it, through the net's seam
(`netGuarded`) and `root --net` (`--lockout` for the lock-out class), with the helper's own time limit (30 minutes, 10
in the lock-out class), said on the button, and an end at it said in the result. With no helper there, one this build
doesn't know or walls not proven, and where root is off on that Spark, the answer is the owner's one command (with
`--with-root` for the last), and nothing is asked; `sudo` in a plain command is answered "set root". Not built: a root
script on input (`--stdin`), `--path` and `--unit`, an installer downloaded once, the owner's command again after
`--undo`. No Spark has root on. The helper cannot tell who calls it: with root on, any program running as the owner
there can run a root command through it, inside the net, with no press; the one-time command says so as it turns root
on. Only a real Spark shows a root command inside the net, once kept and once left to go back (the owner's list). A
lock-out change asked as the owner (no root) is answered "set root", and nothing is asked or run (`netChange`): as the
owner it could change nothing. For root's ask the sorter also gives
`later` (work started later, outside the button and the net: `systemd-run`, `at`, `batch`, `crontab`, a schedule or a
unit written, a timer started; A-16). `unpinnable` lists each piece of that unseen code that is no script named as a word, so no hash pins it (a key's
check, R51). `unknownProgram` names a program it doesn't know (`gdb`, `nvidia-ctk`), which
stays asked, so the ask can say so. A kill as root, which may hit any process, is the lock-out class only when the
sorter is told `root: true`. The fourth read's Later lines: `docs/history/later-2026-11-15.md`.
