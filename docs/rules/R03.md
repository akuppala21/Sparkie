# R3

## Rule

**R3.** No action changes SSH, Tailscale, firewall, users or access, except a change on a compute Spark that runs
inside the put-back net after the owner's press (SSH, Tailscale, the firewall and users; R60); a command as root only on
a compute Spark where the owner turned root on, always asked and always inside the net (R70); and on Spark 2 a change
the owner pressed for, inside the net, never one that could lock the owner out (R61); port 8443 keeps exactly three
routes; port 10000 has one route, `/` to the app door's socket, set only by the owner's
`deploy/open-apps-to-internet.sh` (R40). Today: nothing enforces this beyond the action list; the owner’s page routes
do change `access.json` and agent keys; the service only reads Tailscale; the install scripts add serve routes with
sudo. What Sparkie is told it never changes, and what it tells the owner, is one list (`NEVER_CHANGES`, A3), with how
the rest is done (`CHANGES_ASKED`).

## Why

Lock-out; Funnel exposes the whole port.

## Today

Marked in the Rule text above. The root helper holds the lock-out net's put-back (R60), which can write back the ways
in and reload ssh, the network, ufw and Tailscale; the console's half of the net calls it (`21-net.mjs`, R60).
