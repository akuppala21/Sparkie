# R35

## Rule

**R35.** A saved workflow is checked before step 1 (`checkSteps`, one inventory look, read-only): it refuses the run
only on facts that fail the real step the same way (arguments its action refuses, a named Spark that is off, a
container that is not one of Spark Console’s there, a model name nothing matches) and says nothing was changed;
everything else “goes”, has “nothing to do”, or is “checked when reached”. A start whose model already runs where the
step names it has “nothing to do”, and the step itself answers already and starts nothing: one Spark named means its
one-Spark copy runs there; two named means both parts of one pair run on exactly those two, in either order; a step
that also names a setup is started as before (`runsWhereNamed`, F10). If the check itself fails, the run goes ahead
and says so. It never asks Hugging Face and calls no step’s code, so no workflow version changes. `save_workflow`
refuses approval arguments in a step. A step that only reads is not refused because its Spark is off; a stop, restart
or start that names no target is refused at save. Sparkie runs a saved workflow at once only when every word of its
name and of every input value is in the owner’s words, nothing was ruled out (“but don’t …”), no longer saved name
fits the words too, and they did not say rehearse, dry run, preview, simulate or what if; a name that is not saved is
an error, never a button. `workflows {name}` is the rehearsal (steps that need inputs are checked when it runs).
The run waits for each step's operation; a step that runs a job (`keep_running` with `once`, or one that answers it
is a job: run again, or already running) waits for the job's end too (`jobStepEnd`, contract 9.27): `waitJobEnd`'s
look, every 10 s, for 6 hours at most. Exit 0 goes on to the next step. Anything else ends the run there: its error's
first line names the step and how the job ended (an exit code, out of memory, never ran), then the job's last 10
lines, masked, each cut to 200 characters, labelled as data. At the limit the run ends and says the job still runs.
Cancelling the run ends the wait at once and cancels the step's own operation under way, which puts back what it did;
`/stop` cancels no operation (R34), so it does not. What a run started is stopped again, newest first, and only that
(`stopWhatRan`): each step that answered `started` (a model a start or restart ran, by `stop_model`; an app or a job
`keep_running` started, by its stop, a job only while it still runs). A step that answered `already` is never
stopped, a step saved with `keep: true` is left running, and what a step stopped stays stopped. When: a run that ends
badly (a step failed or asked, a job ended badly or ran past the limit, or it was cancelled), any run (`runCleanUp`);
a run that ends well, only a workload, a run with at least one job step: it stops the models and apps it started for
its job, and its jobs, which have ended, stay with their files (`runEndWell`). A run with no job step (a routine, a
stack) keeps what it started when it ends well. Each stop is an action call as the run (via `workflow`); one that
fails is said after the first error on its first line, never in its place. What was stopped and what was kept is in
the run's result, the cancel's answer and the chat line. `keep` is refused unless it is true or false on a step that
starts something, and a step with any other field is refused.
A `keep_running` step that keeps something may leave out its Spark (saved and
checked with only `spark` not required; the rehearsal says it is placed when reached): when the run reaches it,
`pickSpark` places it from the live look, never on the brain's Spark and only where the caller may: where its
container already is (awake, or asleep by the watcher's record); else, for a new one, a Spark that is on (the run's
last step's first, then in list order) with room under the 8 GB rule, the GPU to itself when it asks for it, and the
files under `/in` its command names; else one Spark Console powered off whose record has room (`wakeOne`), unless its
command names files; else the run ends with each Spark's reason. A step naming, or placed on, a Spark Spark Console
powered off is checked when reached, not refused (a start too): the run turns it on first (`power.wake`, for a
workflow run) and keeps it awake until it ends, so the step's own answer is the usual one and a job's wait works.

## Why

Step 2 failing after step 1 stopped a model was the common failure; a checker bug must not stop a routine. A job's
next step usually reads what it wrote: started while the job still runs, it reads nothing, or half.
