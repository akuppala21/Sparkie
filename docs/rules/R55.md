# R55

## Rule

**R55.** What `run` does with a change (R42 is the root helper and the look). First the sorter: code, never the brain,
sorts every command before anything runs, from its text and where it runs alone (`sortCommand`; no model call, no file
read, bounded work, never a throw for anything JSON can carry): a look, a change, risky, the lock-out class or not
done, in that order of danger, and when two could apply the later wins (design A 2.8; the one page, section 4).

- **The careful answer is the default.** A command is a change only when the sorter can show it is one: a program it
  knows, called by a name or path it resolves to that program, each option and sub-command on that program's list (its
  manual's, `20-options.mjs`), every word that decides what it does in view, touching only places it can place. Anything else is risky: an unknown program, option or sub-command, a `$` where an option, a
  program or a path goes, a loop or other shell form it does not read, a sign that is not plain ASCII, words a program
  reads from its input (`xargs`, `find -exec`; a plain reader fed by `xargs` stays a change), code fetched from the
  network and then run, code run with a word naming a file this command wrote or holding an address, or run from a
  folder it wrote into, and a command run on another machine or a copy onto one (`ssh`, `scp`, `git push` to an
  address; to a named remote it is a change: where that points is in settings the sorter does not read). A program
  run by another (`conda run`, `git rebase -x`) is sorted where it stands. A sign that does not show is not done.
- **A look** keeps `run`'s own checks (`lookForm`'s exact forms, no `sudo` command word, no key word) and every program
  in it only reads, with no flag that writes, no redirection but to `/dev/null`, no here-document. It runs in the look
  wall, so a wrong "look" still cannot write or send. A key shown back is not done.
- **Places** (`20-places.mjs`): a change that names a way in anywhere, even to read it, is the lock-out class (SSH,
  users and sudo, PAM and shell start files, the network, the firewall, Tailscale, linger, their units, the console's
  unit and sign-in files); one that reaches the root helper or its sudo line is not done
  and is answered with the owner's one-time command; a disk or device, the kernel, a schedule, Docker's settings and the
  console's or the brain's files are risky; so is writing what something outside the wall later runs or reads (the
  PATH, user units, tool settings, git hooks and settings, Python at the top of the home). A path is placed against the owner's home (`home`, else the configured user's):
  another user's home, or a path climbing out of it, stays itself, and a write there is risky. A folder above a way in counts for a command that reaches everything under it (`rm
  -r`, `chmod`, an archive or a patch unpacked there; `tar -P` and `unzip -:` reach `/`). As root, a path word of a
  change outside the root folders (a home, `/etc` less the lists, `/opt`, `/srv`, `/mnt`, `/data`, `/tmp`, `/var/tmp`,
  `/var/www`, below `/usr/local` but its `bin` and `sbin`) is risky, and only a plain command (one program, nothing set
  before it) runs at once; a script, a one-liner or a flag that runs a program is asked, and so is `systemctl` but to
  start, stop, restart, reload, enable or disable a service named plainly. No wall guards the Spark's own ports from
  root: a root download naming a host by number, localhost, a one-word or fleet name, or forcing an address is asked
  (root's other ways to a port already are).
- On Spark 2 every change is risky. `sudo` and `su` in a command are answered "set root".
- **The reason** is the sorter's own words; a piece of the command in it is one quoted line, cut short, with no control
  sign, so a command cannot write a line of what the owner is shown.
- **The result** carries what the next steps use: `kinds` (the dangerous asks: root, lockout, delete, brain), `form`,
  `simple` (may have an "always" kind), `open` (needs what the run wall hides), `deletes` (risky unless every named file
  is copied first), `scripts` (to hash for the ask), `answer` (`set root`, `owner command`), `lasting`, and `placed`
  and `wide` (the files it changes and the folders it reaches everything under: what the runner copies first).
- **The runner** (`runChange`) runs one plain change on a compute Spark, holding its claim (R13) from its first step to
  its end, a throw included: room for the run wall's 8 GB (R2); the copies; the start line, synced (R43), naming the
  set and its manifest's SHA-256; the command as unit `sw-run-<id>`, with its time limit, ended with all it started
  (an exit code is a result); the ways-in check; the end line (exit code, seconds, kept and not kept, the unit). It
  refuses Spark 2, a Spark holding the brain, root (`sudo`, `su`, the root helper), a pause, and all but a plain change.
- **The copies** (`21-copies.mjs`): every file the sorter placed (a `*` expanded, a wide folder walked) and the ways in
  the owner's account, in `~/.local/share/spark-console/before/<set>/` (0700, files 0600, hidden by the walls): bytes,
  mode and path; at most 16 MB a file and 128 MB a command. Past a limit, unreadable, not a plain file, under a link,
  or what a named link points to is not kept, with why; a command that removes or overwrites (`deletes`) then runs
  nothing. Never through a link: read and written with `O_NOFOLLOW`, put back by a rename.
- **The ways in** are fingerprinted before and after; on a difference the set is put back, changes pause
  (`tripBreaker`) and that notice says what differed.
- **Cut off**: a start line with no end is told once, at the next start (R43) or when the Spark stops answering, and
  never run again. A notice names a change by its record; only the owner's own chat gets its command (R59).
- **Undo**: `undo_last_change` puts back the chat's newest set, when newer than its last model change, file by file,
  saying what it could not; only what a manifest names whose SHA-256 is the start line's. Its own start and end lines.
- **The result** gives A5's line `where`, `root`, `record` and `kept` (the start and end's id) and `tail`; `putBack` is
  its own field.

## Why

Sparkie may change a Spark at once only where the copy first, the walls and the owner's words stand behind it; the
mistake that matters is a command run at once that should have been asked, guarded or refused (design A 2.5, 2.8,
2.13; the one page, sections 4 and 7; the reviews of 2026-11-14 and 15).

## Today

Dark: `sortCommand` and the runner are reached only by their tests (the runner through `run`'s test door,
`SPARK_CONSOLE_RUNNER_DOOR`, on the stand-in fleet), and `run` still sends every command to the look wall. Step A7c
(the ladder, the ask) wires them in. No set is pruned yet; a script a change runs is not copied for (the ways-in
check guards it); a change ends at its time limit. Interpreters' one-liners
are read only for names; a script's text is not read (its hash is kept for the ask). Left to the walls: names a
program never expands (`open('/etc/{a,b}')`) or builds in a one-liner, a host that only DNS makes the Spark, a plain
reader's options (any but those that write or run). As root, by the one page's choice, a file under `/etc` or
`/usr/local/lib` that root or every Python later runs (`…/dist-packages/x.pth`, `/etc/update-motd.d/99-x`) is an
at-once change. `placed` and `wide`: at most 256 paths, none with a control sign (such a name is risky); a superset
(sources, words an option may name), so the runner copies what exists.
