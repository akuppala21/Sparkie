# R55

## Rule

**R55.** What `run` does with a change (R42 is the root helper and the look). First the sorter: code, never the brain,
sorts every command before anything runs, from its text and where it runs alone (`sortCommand`; no model call, no file
read, bounded work, never a throw): a look, a change, risky, the lock-out class or not done, in that order of danger,
and when two could apply the later wins (design A 2.8; the one page, section 4).

- **The careful answer is the default.** A command is a change only when the sorter can show it is one: a program it
  knows, called by a name or path it resolves to that program, with every word that decides what it does in view,
  touching only places it can place. Anything else is risky: an unknown program or option, a loop or other shell form
  it does not read, a `$` where a program or a path goes, a sign that is not plain ASCII, words a program reads from
  its input (`xargs`, `find -exec`), code fetched from the network or written by this same command and then run, and
  any command or write on another machine (no wall and no copy there; to look there, `run` there). A sign that does not
  show is not done.
- **A look** keeps `run`'s own checks (`lookForm`'s exact forms, no `sudo` command word, no key word) and every program
  in it only reads, with no flag that writes, no redirection but to `/dev/null`, no here-document. It runs in the look
  wall, so a wrong "look" still cannot write or send. A key shown back is not done.
- **Places** (`20-places.mjs`): a change that names a way in anywhere, even to read it, is the lock-out class (SSH,
  users and sudo, PAM and the shell's start files, the network and the firewall, Tailscale, linger, the units that
  start them, the console's own unit and sign-in files); one that reaches the root helper or its sudo line is not done
  and is answered with the owner's one-time command; a disk or device, the kernel, a schedule, Docker's settings and the
  console's or the brain's files are risky; so is writing what something outside the wall later runs or reads (the
  PATH, user units, tool settings, a `.py` the console's worker imports). A folder above a way in counts for a command
  that reaches everything under it (`rm -r`, `chmod`, an archive unpacked there). As root, a write outside the root
  folders (a home, `/etc` less the lists, `/opt`, `/srv`, `/mnt`, `/data`, `/tmp`, `/var/tmp`, `/var/www`, below
  `/usr/local` but its `bin` and `sbin`) is risky, and only a plain command (one program, nothing set before it) runs
  at once; a script or a one-liner as root is asked.
- On Spark 2 every change is risky. `sudo` and `su` in a command are answered "set root".
- **The reason** is the sorter's own words; a piece of the command in it is one quoted line, cut short, with no control
  sign, so a command cannot write a line of what the owner is shown.
- **The result** carries what the next steps use: `kinds` (the dangerous asks: root, lockout, delete, brain), `form`,
  `simple` (may have an "always" kind), `open` (needs what the run wall hides), `deletes` (risky unless every named file
  is copied first), `scripts` (to hash for the ask), `answer` (`set root`, `owner command`), `lasting`.

## Why

Sparkie may change a Spark at once only where the copy first, the walls and the owner's words stand behind it; the
mistake that matters is a command run at once that should have been asked, guarded or refused (design A 2.5, 2.8,
2.13; the one page, sections 4 and 7; the review of 2026-11-14).

## Today

Dark: nothing calls `sortCommand` but its test, and `run` still sends every command to the look wall. Steps A7b (the
runner, the copies, the journal lines) and A7c (the ladder, the words, the ask) wire it in. Interpreters' one-liners
