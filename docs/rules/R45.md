# R45

## Rule

**R45.** Memory keeps every line and believes only the owner's words. Each line in `memory.json` says who it is from
(`by`: the owner, or an agent by its name, also when Sparkie answers that agent in its own chat) and where it came from
(`src`: the way in, the chat, Telegram). There is no ceiling on lines. A line that is replaced or forgotten is retired,
never erased: `saveMemory` moves it to `memory-past.json` with `gone` (when, why, the line that replaced it, who, from
where), the past file first, so a stop between the two saves leaves the line in both (live wins), never in neither;
`memory {past: true}` lists the retired lines with what replaced them, to the owner only: an agent's key, Sparkie in an
agent's chat and Telegram are refused (403). `memory.json` keeps its shape, `{entries}`, so the
build before this one still reads it after going back, and that build's saves can't drop the past file. An agent never
replaces or forgets an owner's line: its own call over the agent door, Sparkie in the agent's chat, or a button the
agent presses there is refused (403) and changes nothing; it may replace and forget its own lines (`notTheOwners`).
Forgetting keeps its own gate (R25, `saysForget`): retiring makes a wrong forget recoverable; it does not replace the
gate. Erasing a line for good (`forget_memory {erase}`, `eraseLine`) is the owner's alone: their own call on the
tailnet (`POST /actions`) or a button pressed in Spark Console, with the passkey once one is set up. From Sparkie, whatever
the owner's words, and from Telegram it is always that button, asked by the erase itself, so no gate for Telegram can let
it through; an agent is refused, for its own lines too. Every record of the line leaves both files, both are saved twice
so neither copy from before the last save holds its words, and a copy of either set aside as unreadable or left
half-written by a stop has them blanked. Its answer says in one sentence what it can't reach: the chat (the owner's
words, Sparkie's replies, the button, Telegram's copy), the journal (R43) and the record of changes (`audit.jsonl`),
daily copies already sent to another Spark and install snapshots already taken. Past the old 4,000 characters of lines, the prompt keeps the
newest that fit (the owner's before agents') and says how many more there are.

## Why

Only the owner's words become beliefs; a wrong forget or replace must be recoverable; an update can be put back.

## Today

- An erase leaves the words where it can't reach, as its answer says: the chat, the journal and `audit.jsonl` (a
  `remember` holds its text in both), daily copies already sent and install snapshots already taken.
- `src` has no journal record yet; it comes with the journal.
- The newest lines that fit stand in for the picker, which keeps the owner's wishes in the prompt instead.
- After going back, a line the build before this one replaces or forgets is dropped, as it always did.
- Once memory passes its old size (review of G1, later items): Sparkie's own `memory` result is cut at 12,000
  characters, oldest first, while the prompt keeps the newest.
- Over the agent door a `memory` result past 60,000 characters comes back cut with "ask for less", which `memory` can't do.
- The owner is not told when the oldest lines leave the prompt.
- Agents' lines have no ceiling, and `remember` is not counted by the agents' pause.
- A line with no `by` is not protected by the agent rule.
- An agent named exactly "owner" writes lines that read as the owner's, and can't forget its own.
