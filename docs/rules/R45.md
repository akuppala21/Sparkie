# R45

## Rule

**R45.** Memory keeps every line and believes only the owner's words. Each line in `memory.json` says who it is from
(`by`: the owner, or an agent by its name, also when Sparkie answers that agent in its own chat) and where it came from
(`src`: the way in, the chat, Telegram), and what it is about (`about`): up to five names of things Spark Console
lists (a Spark, a model, a container, an app, a setup, a person or an agent), each in one form, found by code in the
line's own words when it is saved, as whole words and never in a web address, never by a model and never by reading a
file then. A line saved before names were kept gets its names in memory the first time memory is read after start,
and is written with them at the next save. An index from each name to the live lines about it is kept in memory, made
at start and after every save, and read again from `memory.json` only when the file changed. `memory` shows `about` to
the owner's own call only; Sparkie and agents are shown the lines as before. There is no ceiling on lines. A line that is replaced or forgotten is retired,
never erased: `saveMemory` moves it to `memory-past.json` with `gone` (when, why, the line that replaced it, who, from
where), the past file first, so a stop between the two saves leaves the line in both (live wins), never in neither;
`memory {past: true}` lists the retired lines with what replaced them, to the owner only: an agent's key, Sparkie in an
agent's chat and Telegram are refused (403). `recall` reads lines on the same rules (`memoryPastShown`): the live
ones as `memory` gives them, the retired ones only there; an erased line is in neither file, so in no answer. `memory.json` keeps its shape, `{entries}`, so the
build before this one still reads it after going back, and that build's saves can't drop the past file. An agent never
replaces or forgets an owner's line: its own call over the agent door, Sparkie in the agent's chat, or a button the
agent presses there is refused (403) and changes nothing; it may replace and forget its own lines (`notTheOwners`).
Forgetting keeps its own gate (R25, `saysForget`): retiring makes a wrong forget recoverable; it does not replace the
gate. Erasing a line for good (`forget_memory {erase}`, `eraseLine`) is the owner's alone: their own call on the
tailnet (`POST /actions`) or a button pressed in Spark Console, with the passkey once one is set up. From Sparkie, whatever
the owner's words, and from Telegram it is always that button, asked by the erase itself, so no gate for Telegram can let
it through; an agent is refused, for its own lines too. Every record of the line leaves both files, both are saved twice
so neither copy from before the last save holds its words, and a copy of either set aside as unreadable or left
half-written by a stop has them blanked. Its answer says in one sentence what it can't reach: the chat (the owner's
words, Sparkie's replies, the button, Telegram's copy), the journal (R43) and the record of changes (`audit.jsonl`),
daily copies already sent to another Spark and install snapshots already taken. Code picks what a turn sees, with no
model call and no file read (`memoryPicks`, design G 3.4): the system prompt holds every line while their words fit the
block (4,000 characters, less for a brain with a small context), and past it only the owner's wishes (preferences and
corrections), oldest first, and one fixed line, so it moves only when a wish does. When the wishes alone outgrow the
block the newest stay, the fixed line counts the rest, and the needs-you list says so until they fit again. Facts,
lessons and agents' lines are then only picked. The lines it doesn't hold that carry a name from the owner's words, or share two rare words with them, go
in Spark Console's record ahead of the words, best first, up to 1,500 characters, each with where it came from, and one
line counts what was left. A picked line is data: the owner's request is their own words alone. With
`SPARK_CONSOLE_MEMORY_OFF` naming `names` (the eval's switch, on the stand-in fleet) the picker is off.

## Why

Only the owner's words become beliefs; a wrong forget or replace must be recoverable; an update can be put back.

## Today

- An erase leaves the words where it can't reach, as its answer says: the chat, the journal and `audit.jsonl` (a
  `remember` holds its text in both), daily copies already sent and install snapshots already taken.
- `src` has no journal record yet; it comes with the journal.
- After going back, a line the build before this one replaces or forgets is dropped, as it always did.
- Once memory passes its old size (review of G1, later items): Sparkie's own `memory` result is cut at 12,000
  characters, oldest first.
- Over the agent door a `memory` result past 60,000 characters comes back cut with "ask for less", which `memory` can't do.
- The owner is told only when wishes are left out of the prompt, not when facts are (they come when a message is about
  them).
- Agents' lines have no ceiling, and `remember` is not counted by the agents' pause.
- A line with no `by` is not protected by the agent rule.
- An agent named exactly "owner" writes lines that read as the owner's, and can't forget its own.
- Only names Spark Console lists are found: a name the owner coins (a person, a project, "my coding setup") is not,
  nor a model on disk that no recipe, brain setup or container names.
- A line's names are those known when it is saved (an older line's, when memory is first read after start); a name
  learned later is not added to it. The book of names is made again at most once a minute, after the call that used it.
- Sparkie never sees `about`. A pick's time is not yet in the turn's record in the journal.
