# R57

## Rule

**R57.** A saved workflow run as a workload (contract 9.27; design D 2.3 as cut): what R35 says of its steps, its job
waits and its clean-up holds; this rule adds what outlives the process. A run keeps a record of itself in
`saved-runs.json` in the state folder (`savedRunKeep`, through `writePrivate`; names, Spark ids and the chat's id, no
secret), rewritten as it goes: its title, the chat that asked, its step count and the step it is at, what its finished
steps started (`started`), what a step under way answered `started` for and is still bringing up (`pending`, a
`restart_model` or `keep_running` step's own container; a start's container is known only once its operation ended),
and the Sparks it keeps awake. The record goes when the run ends, however it ends (`savedRunDone`). At start-up the
watcher's one look at operations a restart cut off (`19-watcher.mjs`, its existing one-shot timer) calls
`savedRunsRecover`: for each run still on record, what it started is stopped newest first under the same rules as a
failure (`stopWhatRan`: `keep: true` and "already" left alone, a job only while it still runs; an app cut off before it
joined the list is kept first, so its stop takes it off), the keep-awake holds went with the old process, one notice
says what was stopped, kept or couldn't be stopped (in the chat that asked too), and nothing is run again. The generic
"a restart cut off …, start it again" line is not given for the run's own operation or for its steps' since it began
(`savedRunCutOff`); the operation is still marked interrupted. A state copy ignores the file (`COPY_IGNORES`).
A job a run starts from its image (`keep_running` with `once` and an image) is handed the one model address in its
settings (`jobModelEnv`, D7; design D 2.4): `SPARK_MODEL_URL`, Spark Console's one address as a container on a compute
Spark sees it (the self-test's, without `/models`); `SPARK_MODEL_NAME`, the model the step's own settings name, else the
one an earlier step of the run started or found running (a start's model, a restarted container's), else `sparkie`;
`SPARK_MODEL_PARALLEL`, for Sparkie its `--max-running-requests` less two, at least 1 (R36 caps app calls at its slots
less one, so one place stays for another app and one for the owner's chat), 1 when the setup doesn't say, and 4 for a
model of the run's own. Settings the step names are kept; only missing ones are added. Sparkie is handed only when its
setup can chat (`can`, `["chat"]` when not said) and answers at least 2 calls at once; otherwise the run says why and
the job gets none. A job run again by name keeps what it was made with. None of this touches what a save's yes covers.

A run an agent asked for (its key, its own call through the door, or its chat with Sparkie) is that agent's in each
of its steps (`savedStepAgent`: `agent` and the key's id in the step's context), so every gate that asks an agent asks
in the step as in the agent's own call (a job run again, a GPU app started again, a power-off), and a key removed
during the run stops its next step; the owner's run stays the owner's. The clean-up's stops (`stopWhatRan`, at a bad
end, a workload's good end and after a restart) run as the run, never as the agent: they only take back what this
run's own steps answered `started` for, start and wake nothing, and none of them asks an agent, so a removed or
paused key never leaves the run's leftovers running for nobody, or a question no one can answer.

## Why

A restart in the middle of a workload (an install, a crash) left the model and apps it had started running for nobody,
and the owner was told to start them again.

## Today

- A start step (`start_model`) cut off while its own operation ran isn't stopped: its container is known only when the
  operation ends. Its own cut-off line is still given.
- A Spark that doesn't answer at start-up isn't tried again: what couldn't be stopped there is said in the notice.
- A job is handed the one address on the stand-in fleet only; real use waits on the self-test's fifth line (a container
  reaches the one model address) passing on the real Sparks, the owner's check after the install.
