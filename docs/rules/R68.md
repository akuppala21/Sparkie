# R68

## Rule

**R68.** What `write_file` does (A7d): one text file on a compute Spark, the whole file or its lines `from` to `to`
(as `cat -n` numbered them; `to` = `from` - 1 puts the text before line `from`), through `run`'s ladder and runner
(R61), never around them.

- **Sorted by code from the path, never from words.** The sorter is handed a plain write of that path from where the
  change starts (`cat > ./<path>`, so a name that starts with a dash is a file; `~/…` and a whole path from the home,
  anything else from `~/work`; an empty path, `./`, `~/`, `~//…` and a folder's path are refused by name), so the file is
  refused, asked or written at once exactly as a `run` writing it would be: Spark 2, a brain Spark, root, a pause, not
  done and the lock-out class refused; a protected folder, a place the plain wall keeps read-only, a link in its folders
  and the rest of `hostClear` as for `run`; `written` gets the path, so a later command of the request that runs it is
  asked.
- **The text** (at most 128 KB, no sign that doesn't show, as the dangerous ask refuses them) is refused only for a
  key for sure: the exact value of a key the owner gave Sparkie, a private key block, or a token of a form the mask
  knows (`hf_`, `nvapi-`, `ghp_`…, `sk-`, `tskey-`, AWS, JWT, Telegram, Slack, the heartbeat's address). A line the mask
  hides by its shape alone is written as given and shown masked, marked; a hidden part that holds a sign that runs
  something (`$`, a backtick, a bracket, `|`, `;`, `&`, `<`, `>`) is shown whole on the button, marked, and stays masked
  in the records. The bytes reach the unit on the helper's
  input (`run --stdin`), from the call's own script as base64, never on a command line; for lines `from` to `to` code
  builds the whole new text of a file that is UTF-8 text (any other is refused: write the whole file), so what is
  shown is what is written.
- **The old file** is read only through the helper's `look`, the same wall `run`'s looks go through: a key, or a file
  that wall hides, is "hidden", its old text never read, and such a write is asked, never at once. What is at the name
  is looked at by name only: a link, a folder or another non-file, or a read-only file is refused by name.
- **The unit runs code's own program:** only while the file is as code read it (its SHA-256, or not there; a hidden one
  only while it is still a plain file) and its owner may write it; it writes beside the file and makes one move, with the old permission bits only (0644 for a new
  file); a trap removes the temporary file if the unit is ended. The result says `wrote` only when it ended well, else
  `notWritten` with what it said, or that whether it was written isn't known after an end the console can't know.
- **The runner's own steps** (R61): the copies first (the old file, so undo puts it back), the journal's start line
  (`tool: write_file`, the path, the byte count: the runner's lines hold no text), the run wall, the end line, the hold
  after an end it can't know, the memory cap and `--protect`. The tool's own line (Sparkie's call, an agent's) keeps
  its arguments' start, masked, as every tool's does. It is a work step, as `run` is.
- **Asked:** the button shows the path and the lines that change, old and new (masked and marked; a line past 200 signs
  cut and said so; at most 30 each way, with how many more; hidden old text and one over 256 KB not shown, and said),
  why it is asked and what put-back covers. Its
  call holds the same arguments; a press after the file changed since the ask is void and asked again.
- **Lines `from` to `to`** need the file there as plain text of at most 256 KB a look may read, with those lines in
  it; new lines after a last line with no line break start lines of their own.

## Why

A file written by the brain is a change like any command (design A 2.9, 2.14 row 7, decision 18): the same gates,
the same copy first and the same wall, and its text never passes through a shell's words.

## Today

The design's "refused if the file changed since the last look numbered it" is the file as code read it just before the
ask or the run, not the brain's own look. A text with a carriage return (Windows line endings) is refused. On the
stand-in fleet the look wall is not built, so only a key's name shows "hidden" there. A write under `/tmp` or
`/var/tmp` lands in the unit's own temporary folder and is gone when it ends. `root` is not taken (it waits for the put-back net). Not in the box (`on:
"box"` is not built).
