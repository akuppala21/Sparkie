# R61

## Rule

**R61.** What `run` does with a change, and the runner that runs it (R55 is the sorter, R42 the root helper and its
walls). `run` sorts every command: a look goes to the look wall (a look's own refusals first: sudo when the rest only
reads, a key's name); anything else to the ladder (`workChange`). `runChange` sorts the command itself (`sortCommand`
with `runnerSortOpts`: no caller hands it an answer) and runs it on a compute Spark, holding the Spark's claim (R13)
from its first step to its end, a throw included; after an end it can't know, until systemd says the unit is gone or
its time limit has passed (at a console start too, `runnerHold`), and undo is not done beside it.

- **The ladder** (`21-ladder.mjs`, design A 2.5 and 2.8). Not done, whatever is said: what the sorter calls not done,
  and the lock-out class (it waits for the lock-out net). At once: a plain change when `hostClear` holds: the owner's
  own call, or their chat whose words ask for work (`CHANGE_WORDS`' kind `work`) and name that Spark, with nothing read
  from outside since in the turn or its task, nothing placed in a protected folder, and no Spark advertising Tailscale
  SSH (`sshHostKeys` in the tailnet's own answer, read every minute; a Spark missing from it or offline, or an answer
  unread or older than three looks, can't be told: asked), and, for Sparkie's own call, while its brain is checked
  (the rail, R52; with no eval on record every change is asked). Otherwise one button for the owner with the exact command,
  built by code (why, what put-back covers, what Sparkie read, each script's SHA-256); a risky delete or the brain's
  names is the dangerous ask (R54). The press runs it sorted again; a script whose hash changed voids it and asks again.
  An agent's change is always a button. What a request's changes wrote, at once or asked, goes to the sorter as
  `written`, never trimmed (past 1,024 the sorter doubts: asked); what it read from outside is kept as its records
  (`ctx.reads`), both with its task. `/undo` is an owner's word, also while paused.
- **Where it starts:** `~/work` unless `run`'s `dir` says `~` or a folder under it (no `.` or `..` part); the copies'
  own call, before the unit, makes `~/work` (0700) and checks any `dir` is a real folder of the owner's, every part of
  its path, never a link: one that isn't there is refused, not made. The sorter places the command's paths from `dir`,
  so the same rules hold for what it names there. A look starts in `~` and takes no other `dir`.
- **What it can't change unasked:** `~/models`, `~/.cache/huggingface` and the jobs' shared folder, given to the helper
  as `--protect '~/…'` (each only when it is a real folder there now); one the sorter places a change in is asked, and
  after the yes it runs without that one. The time limit of an at-once change is 30 seconds (`RUNNER_SECONDS`).

- **It refuses by itself** Spark 2, a Spark holding the brain, root (`sudo`, `su`, the root helper named), a time when
  changes are paused, and anything but a plain change (a risky one only after the owner's yes): before the claim and any
  copy. git in the unit runs with no hooks and no file-system monitor (`GIT_CONFIG_*`, code's own first line).
- **In order:** room for the run wall's 8 GB (R2); the copies; the journal's start line, synced (R43), naming the set
  and its manifest's SHA-256 (no start line, no command, and the set goes); the command as the run wall's unit
  `sw-run-<id>`, with its time limit, ended with all it started (an exit code is a result); the ways-in check; the end
  line (exit code, seconds, what was copied and not kept, the unit). When the helper runs nothing (not set up, no sudo
  line, not this build's, no current proof, a refusal: its own answer with its own exit code, never a line the command
  printed) the set goes and the end line says it never ran; any other answer keeps the set.
- **The copies** (`21-copies.mjs`): every place the sorter lists (`placed`, `wide` walked; a name holding `*`, `?` or
  `[` is that file, what it matches, and what it matches with each `[…]` read as anything, as bash may read it) and the
  ways in the owner's account, in `~/.local/share/spark-console/before/<set>/` (0700, files 0600, hidden by both walls,
  written by the console's own call outside the unit): bytes, mode and path; at most 16 MB a file and 128 MB a command.
  Past a limit, unreadable, not a plain file, under a link, or what a named link points to is not kept, with why; a
  command that removes or overwrites (`deletes`) then runs nothing. A path under something that is not a folder is not
  there. Never through a link: read and written with `O_NOFOLLOW`, put back by a rename.
- **What the result says it kept:** `copied` counts the command's own files whose bytes were kept, nothing else. It
  never says everything a command wrote was kept: every result says that writes the sorter did not place (a script's, an
  install's, a file it could not place) are not covered by put-back.
- **The ways in** are fingerprinted before and after; on a difference the set is put back, changes pause (`tripBreaker`)
  and that notice says what differed.
- **Cut off**: a start line with no end is told once, at the next start (R43) or when the Spark stops answering, and
  never run again. A notice names a change by its record; only the owner's own chat gets its command (R59).
- **Undo**: `undo_last_change` puts back the chat's newest set whose command ran (or may have), when newer than its last
  model change, file by file, saying what it could not: changed again since; for a cut-off change, written after its
  time ran out (by the changed time, which no command sets: its limit and a minute from the end of its copies); never
  kept; its copy changed; gone. Never beside the change's own unit while systemd says it still runs. Only what a
  manifest names whose SHA-256 is the start line's. Its own start and end lines.
- **The result** gives A5's line `where`, `root`, `record` and `kept` (the start and end's id) and `tail`; `putBack` is
  its own field.

## Why

A change run at once is only safe where what it overwrites or removes was copied first, a way in it touches is put
back, and what it did is on disk before it starts (design A 2.6, 2.8, 2.13; the review of 2026-11-15).

## Today

No set is pruned yet. A change ends at its time limit: the helper's `stop` (step A13a) will end a unit sooner.
`--protect '~/…'` is not passed yet (`HELPER_TAKES.homeProtect`): the pinned helper takes absolute paths only; a
change placed in those folders is asked already. No `minutes` yet (A6): a longer change can't be asked for. Hooks and
fsmonitor off do not cover a repository's own `.git/config` (a credential helper, a gpg program, filters, an ssh
command), which git still runs inside the wall. The unit's memory cap is worked out (`runnerMemoryCap`: what is free
beyond the 8 GB kept, 1 to 8 GB) but not live: the room check stays 8 GB until the helper's `run --memory` is in.
Writes the sorter does not place (a script's or a program's own writes) are not copied. A source the command only
reads counts against the 16 MB and 128 MB like what it changes. A command over 3,500 characters is asked like any
other (not page-only yet); `run` calls of one round run side by side, so two changes there meet the claim.
