# R61

## Rule

**R61.** What `run` does with a change, and the runner that runs it (R55 is the sorter, R42 the root helper and its
walls). `run` sorts every command: a look goes to the look wall (a look's own refusals first: sudo when the rest only
reads, a key's name); anything else to the ladder (`workChange`). `runChange` sorts the command itself (no caller
hands it an answer) and runs it on a compute Spark, holding the Spark's claim (R13) from its first step to its end, a
throw included; after an end it can't know, until systemd says the unit is gone or its time limit has passed (at a
console start too, `runnerHold`), and undo is not done beside it.

- **The ladder** (`21-ladder.mjs`, design A 2.5, 2.8). Not done, whatever is said: what the sorter calls not done, and
  the lock-out class (it waits for the lock-out net). At once: a plain change when `hostClear` holds: the owner's own
  call, or their chat whose words ask for work (`CHANGE_WORDS`' kind `work`) and name that Spark, nothing read from
  outside since in the turn or its task, nothing placed in a protected folder, no Spark advertising Tailscale SSH
  (`sshHostKeys` in the tailnet's answer, read every minute; a Spark missing or offline, or an answer unread or older
  than three looks: asked), and for Sparkie's own call its brain checked (the rail, R52). Otherwise one button with the
  exact command, built by code (why, what put-back covers, what Sparkie read, each script's SHA-256); a risky delete or
  the brain's names is the dangerous ask (R54). The press runs it sorted again; a script whose hash changed voids it.
  An agent's change is always a button. What a request's changes wrote goes to the sorter as `written`, never trimmed
  (past 1,024 it doubts); what it read from outside is kept as its records (`ctx.reads`), both with its task. `/undo`
  is an owner's word, also while paused.
- **Where it starts:** `~/work` unless `run`'s `dir` says `~` or a folder under it (no `.` or `..` part); the copies'
  call makes `~/work` (0700) and checks any `dir` is a real folder of the owner's, every part, never a link (one not
  there is refused). The sorter places paths from `dir`. A look starts in `~` and takes no other `dir`.
- **What it can't change unasked:** `~/models`, `~/.cache/huggingface` and the jobs' shared folder, given to the helper
  as `--protect '~/…'` (each only when a real folder there now); a change placed in one is asked, and after the yes runs
  without that one. The time limit of an at-once change is 30 seconds (`RUNNER_SECONDS`).

- **It refuses by itself** Spark 2, a Spark holding the brain, root (`sudo`, `su`, the root helper named), a time when
  changes are paused, and anything but a plain change (a risky one only after the owner's yes): before the claim and any
  copy. git in the unit runs with no hooks and no file-system monitor (`GIT_CONFIG_*`, code's own first line).
- **In order:** room for the run wall's 8 GB (R2); the copies; the journal's start line, synced (R43), naming the set
  and its manifest's SHA-256 (no start line: no command, the set goes); the command as the run wall's unit
  `sw-run-<id>`, with its time limit, ended with all it started (an exit code is a result); the ways-in check; the end
  line (exit code, seconds, what was copied and not kept, the unit). When the helper runs nothing (not set up, no sudo
  line, not this build's, no current proof, a refusal: by its own answer and exit code, never the command's output)
  the set goes and the end line says it never ran; any other answer keeps the set.
- **The copies** (`21-copies.mjs`): every place the sorter lists (`placed`, `wide` walked; a name with `*`, `?` or `[`
  is that file and what it matches, each `[…]` also read as anything, as bash may) and the owner's ways in, in
  `~/.local/share/spark-console/before/<set>/` (0700, files 0600, hidden by both walls, written outside the unit):
  bytes, mode, path; at most 16 MB a file, 128 MB a command. Past a limit, unreadable, not a plain file, under a link,
  or a named link's target is not kept, with why; a command that removes or overwrites (`deletes`) then runs nothing.
  A path under a non-folder is not there. Never through a link: `O_NOFOLLOW`, put back by a rename.
- **What the result says it kept:** `copied` counts only the command's own files whose bytes were kept; every result
  says writes the sorter did not place (a script's, an install's, a file it could not place) aren't covered by put-back.
- **The ways in** are fingerprinted before and after; on a difference the set is put back, changes pause
  (`tripBreaker`) and that notice says what differed.
- **Pruning** (`21-copies-prune.mjs`): when a new set opens on a Spark, older sets there go: older than 7 days, all but
  the newest 20, then the oldest until 2 GB; at most 200 in one go; age is the folder's time (only the copies program
  writes it). Never the new set, a chat's newest set it can still undo (`runnerKeep`), nor a set whose change may still
  run (no end line, or one that says neither finished nor never started) while systemd says its unit runs or can't
  tell. Its copies go for good; manifest, after-look and `pruned.json` stay 62 days; one journal line (`act: prune`)
  names each set, why, and the owner's files it held.
- **Cut off**: a start line with no end is told once, at the next start (R43) or when the Spark stops answering, and
  never run again. A notice names a change by its record; only the owner's own chat gets its command (R59).
- **Undo**: `undo_last_change` puts back the chat's newest set whose command ran (or may have), when newer than its
  last model change, file by file, saying what it could not: changed again since; for a cut-off change, written after
  its time ran out (by the changed time, which no command sets: its limit and a minute from the end of its copies);
  never kept; its copy changed; gone; pruned (each file it held, “pruned: its copy was removed on <day> (why)”).
  Never beside the change's own unit while systemd says it still runs. Only what a manifest names whose SHA-256 is
  the start line's. Its own start and end lines.
- **The result** gives A5's `where`, `root`, `record`, `kept` (the start and end's id) and `tail`; `putBack` apart.

## Why

A change run at once is only safe where what it overwrites or removes was copied first, a way in it touches is put
back, and what it did is on disk before it starts (design A 2.6, 2.8, 2.13; the review of 2026-11-15).

## Today

A change ends at its time limit; the helper's `stop` (A13a) will end one sooner. `--protect '~/…'` isn't passed yet
(`HELPER_TAKES.homeProtect`: the pinned helper takes absolute paths); a change placed there is asked already. No
`minutes` yet (A6). Hooks and fsmonitor off don't cover a repository's own `.git/config` (a credential helper, gpg,
filters, an ssh command), which git still runs in the wall. The memory cap is worked out (`runnerMemoryCap`: 1 to 8 GB
of what is free beyond 8 GB) but not live until the helper's `run --memory`. Writes the sorter doesn't place aren't
copied; a source only read counts against the 16 MB and 128 MB. A command over 3,500 characters is asked like any
other; `run` calls of one round run side by side, so two changes there meet the claim. The hold and pruning read a
unit from `systemctl is-active`, which can't tell one not started yet from one ended: the helper's answer for a run
id, when it is in, settles both.
