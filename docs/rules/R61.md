# R61

## Rule

**R61.** What `run` does with a change, and the runner that runs it (R55 is the sorter, R42 the root helper and walls).
`run` sorts every command: a look goes to the look wall (a look's own refusals first: sudo when the rest only reads, a
key's name when it is a look or a key shown back); anything else to the ladder (`workChange`). `runChange` sorts the
command itself (no caller hands it an answer) and runs it on a compute Spark, holding the Spark's claim (R13) from first
step to end, a throw included. After an end it can't know (at a console start too, `runnerHold`) the claim stays until
the root helper says the call never started or has ended (`state --id`, `runnerRunState`): "running" keeps it past the
time limit; "unknown" or no answer until the limit has passed. Undo and pruning ask the same; after the console's own
time-out the after-look and ways-in check wait for "ended".

- **The ladder** (`21-ladder.mjs`; A 2.5, 2.8). Not done, whatever is said: what the sorter calls not done, and the
  lock-out class (it waits for the lock-out net). At once: a plain change when `hostClear` holds: the owner's own call,
  or their chat whose words ask for work (`CHANGE_WORDS`' kind `work`) and name that Spark, nothing read from outside
  since in the turn or its task, nothing placed or started in a protected folder, nothing the plain wall would fail
  (`runnerOutside`), no other Spark or GPU (`runnerWiden`), no Spark advertising Tailscale SSH (`sshHostKeys`, read each
  minute; one missing, offline or unread: asked), nothing on that Spark but sshd and the console's own listening on
  every address (`workListeners`, `ss`; unread: asked), and for Sparkie's own call its brain checked (the rail, R52).
  Otherwise one button with the exact command, built by code (why, its wall and what it may do there, what it widens,
  its folder, what put-back covers, what Sparkie read, each script's SHA-256 by the helper's look, or why none); a risky
  delete or the brain's names is the dangerous ask (R54), saying the same. An agent's change is always a button, and
  refused during a state put-back's hold (`workHeld`, R23). What a request's changes wrote (at once, or pressed while
  its task goes on) goes to the sorter as `written`, never trimmed (past 1,024 it doubts); what it read from outside
  (`ctx.reads`), both with its task. `/undo` is an owner's word.
- **What the runner asks for itself, and what the press checks:** R72.
- **After the yes, wider** (R63; R64's fields): `--home` for a write at the top of the home or in `~/.local`, `~/bin`,
  `~/.cargo/bin`, or an install there; `--open` for the sorter's `open`, another dot folder, `npm -g` or outside the
  home; `--fleet` for another Spark of this fleet (`reach`, a Spark named, the caller's `fleet`); `--gpu` for `gpu` or
  the caller's. The home network is asked, with no flag. A place only read (`reads`) counts as no write. The button,
  the start line (`wall`) and the result say which.
- **Where it starts:** `~/work` unless `dir` says `~` or a folder under it (no `.` or `..` part, else refused); the
  copies' call makes `~/work` (0700) and checks `dir` is a real folder of the owner's, every part, never a link. The
  sorter places paths from it. A look starts in `~` and takes no other `dir`, nor `fleet` or `gpu`.
- **What it can't change unasked:** the protect folders (R72). An at-once change has 30 seconds (`RUNNER_SECONDS`) and a
  memory cap of what is free beyond the 8 GB kept, 1 to 8 GB (`--memory`); the disk floor and the home's put-back are
  said in the result.

- **It refuses by itself** Spark 2, a Spark holding the brain, root (`sudo`, `su`, the root helper named), a time when
  changes are paused, and anything but a plain change (a risky one only after the owner's yes): before the claim and any
  copy. git in the unit reads none of the owner's or the system's settings but name and mail: no hooks,
  monitor or attributes file (code's own first lines).
- **In order:** room for its memory cap (R2); the copies; the start line, synced (R43), naming the set and its
  manifest's SHA-256 (none: the set goes); the unit `sw-run-<id>`, ended with all it started; the ways-in check; the
  end line. When the helper runs nothing (by its own answer and exit code, never the command's output) the set goes
  and the end line says it never ran; any other answer keeps the set.
- **The copies** (`21-copies.mjs`): what the sorter places (`wide` walked; `*`, `?`, `[…]` as bash may read them) and
  the ways in, in `~/.local/share/spark-console/before/<set>/` (0700, files 0600, hidden by both walls, written
  outside the unit): bytes, mode, path; 16 MB a file, 128 MB a command; what isn't kept: R72.
  Never through a link (`O_NOFOLLOW`, put back by a rename). `copied` counts only the files kept; every result says
  what put-back doesn't cover. The ways in are fingerprinted before and after: a difference puts the set back and
  pauses changes (`tripBreaker`), saying what differed.
- **Pruning** (`21-copies-prune.mjs`): when a new set opens on a Spark, older sets there go: older than 7 days, all but
  the newest 20, then the oldest until 2 GB; at most 200 in one go; age is the folder's time. Never the new set, a
  chat's newest set it can still undo, nor one whose change may still run (`runnerKeep`). Its copies go for good;
  manifest, after-look and `pruned.json` stay 62 days; one journal line (`act: prune`) names each set, why, and the
  owner's files it held.
- **Cut off**: a start line with no end is told once, at the next start (R43) or when the Spark stops answering, and
  never run again. A notice names a change by its record; only the owner's own chat gets its command (R59).
- **Undo**: `undo_last_change` puts back the chat's newest set whose command ran (or may have), when it is the
  chat's last change (R34), file by file, saying what it could not: changed again since; for a cut-off change, written after
  its time ran out (by the changed time, which no command sets: its limit and a minute from the end of its copies);
  never kept; its copy changed; gone; pruned (said per file, with day and why).
  Never beside its own change while that may run. Only a manifest whose SHA-256 is the start line's. Its own lines.
- **The result** gives A5's `where`, `root`, `record`, `kept` and `tail`; `putBack` apart.

## Why

A change at once is safe only where what it overwrites or removes was copied first, a way in it touches is put back,
and what it did is on disk before it starts (A 2.6, 2.8, 2.13).

## Today

A change ends at its time limit; with `minutes` (`21-long.mjs`), `cancel_operation` ends it sooner. Hooks and
fsmonitor off don't cover a repository's own `.git/config` (a credential helper, gpg, filters, an ssh command). Writes
the sorter doesn't place aren't copied, nor seen by `runnerOutside` (a program's own write into `~/.local` fails in the
wall); a source only read counts against the 16 MB and 128 MB.
A pressed change's writes are kept only while its request has a task. `run` calls of one round run side by side, so
two changes there meet the claim.
