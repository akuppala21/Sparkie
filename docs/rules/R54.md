# R54

## Rule

**R54.** Asks sent to Telegram and the dangerous ask (A10b). Before root, a lock-out change, an install of Spark
Console, a delete that cannot be put back and the brain, a raiser calls `dangerAsk` in place of `question`; code names
the kinds, never the brain. The ask is a message of its own in the chat that asked, holding no word of the brain's: line
1 the kinds and the Spark in capitals; line 2 "You asked for this." only when the owner's words in this request ask for
the yes's own kind of change (never a question, a "don't" or a mixed one) and name the Spark, else "You did not ask for
this." (with the agent's name when an agent asked); line 3 whether it goes back; line 4 "Came from, not from you:", each
address (with or without a scheme), path, IP address, package or image of the command that the owner's own messages of
this request do not hold whole, with the read that holds it (`cameFrom`, a string comparison over the newest 40 reads
and 64 MB, newest first, then Sparkie's last 20 answers, for the first 64 things and 64 Mi characters looked through in
all; at most 8 lines; a read not searched in full or not readable, or a bound reached, adds "Not all of what was read
was searched."); lines 5 and 6 the ways-in files, an install's facts, why it runs outside the wall, and the raiser's own
lines built by code (what its wall lets it do, what it reaches, a script's hash); line 7 the exact bytes, whole, in a
fixed-width block (framed under "The exact command:" on the page); line 8 "To run it: press Run it, then type NN." A
command or path holding a control character (other than a line break or a tab in a command), a format, invisible,
unassigned or non-plain space character, or anything the masks would change, is refused, and so is a path its one line
would change (two spaces together, a space at either end, over 400 characters): nothing is asked.
Every line but 7 is built
by code from typed facts, one line each with those characters removed. Two buttons: the fixed yes words and No. The two
digits (`randomInt`, never the last ask's) live only with the open ask in memory, in its Telegram message and in the
copy the owner's page reads (`dangerShown`); never in `chats.json`, the journal, the audit, a label, a tool result or an
event. They bind one ask: its kinds, Spark, wall, verb, arguments and exact bytes (a script it runs is pinned by the
SHA-256 the ask shows and read again at the press; a compute Spark's change checks it once more as it starts, R72). On
the page one request carries the press and the pair; in the paired chat the press is answered and the owner's next
message there is compared (spaces or punctuation around the pair allowed); the pair with no press is told to press
first; while an ask is open, a message there holding its pair as a number of its own is never
passed on, and the page's own chat box refuses one ("Type the two digits in the ask's own field."); anything else typed
after a press forgets the press and goes to Sparkie. The third wrong pair closes it.
One is open in the whole console: another call is told it waits for that one, except that the owner's own chat takes
the place of an agent's conversation; an agent's conversation just declined waits a minute before it asks again; a
third built inside ten minutes is sent a minute late, its 15 minutes starting then. No (pressed, or typed in the chat
that asked), 15 minutes, the third wrong pair, a new pairing, `/stop` in its chat, the word `/pause` and bytes that
changed close it, and a later press or pair is told "That ask is no longer open. Ask again."; a restart closes it too,
and its buttons then answer "That button has expired", as any button's do. `/lock` and the switch going off close only
its Telegram side. A call with no conversation to answer in (an agent's own call, `POST /actions`, a saved workflow's
step even when run from a chat) is told the owner asks Sparkie in their own chat, and nothing is shown. An agent can
answer nothing, is told it waits for the owner, and its tools read none of the ask's text. A change to who may approve
gets its facts in Telegram and no button there. A dangerous approval from Telegram counts as one of R32's (3 an hour,
10 a day). A task parked at one is not carried past it by the loop's budgets. Its journal lines carry `danger`,
`asked`, `from`, and `gate` (`asked:page` or `asked:telegram`) on the answer.

## Why

A tap by reflex on a root command steered by text Sparkie read is the largest risk left (design A, 5): the ask makes
the owner look, says what came from where, and slows a phone in another hand.

## Today

- Every kind is raised. `run`'s ladder raises it for a risky delete and for the brain's names on a compute Spark
  (`workAsk`, `21-ladder.mjs`; the brain's with the sorter's reason, "Why it is asked: …", when no other line says
  it), and for a change whose files it removes or overwrites couldn't be copied first, at once or after a plain press:
  line 3 says so, and a line each names a file and why (`workAfter`, `workGoneLines`). Spark 2's ask raises it for a
  delete (`hubAsk`, `21-hub.mjs`). Root raises it always, with the lock-out kind for a lock-out change and the delete
  and brain kinds beside it (`rootChange`, `21-root.mjs`, R70, R71). An install raises it (`updInstallAsk`,
  `21-updates.mjs`, R58; `updProposalAsk`, behind R69's switch, off). On the stand-in fleet a test raises one through
  `dangerForTest`, which a real console never reaches.
- The list of what was read is handed in (`ctx.reads`): each outside read's journal record, kept with the turn and its
  task (A7c). Each read's text is read back by its record id (`dangerJournalWhere`: the journal's index of its newest
  records, else one pass over the months the reads were made in, 256 MB at most).
- While approvals from Telegram are off, a dangerous ask sends nothing there (as R32's asks).
- The page's pause switch and the automatic pause leave an open ask open; only the word `/pause` closes it.
- A script a command runs is pinned by its hash at the ask and read again at the press; on a compute Spark the root
  helper then runs its own copy of it, the bytes hashed (`--script`, R72). On Spark 2 the press reads the hashes again
  and nothing checks them in the unit (`hubChange`): the script runs by its path, and a script is read as it runs, so
  what is written to it while it runs is run unchecked.
