# R28

## Rule

**R28.** Edit parts, never `server.mjs`; rebuild. A part’s name matches `^\d{2}-[a-z0-9-]+\.mjs$` (a capital or
underscore is silently left out of the build; the installer compares against a shell glob, so a name that sorts
differently makes it refuse); imports only in part 01; top-level code uses earlier parts only; no npm packages. Every
part starts with its header, declared by hand from what its code does: a title line, then `Area`, `Rules`, `Tests`,
`Owns` (each state file it names, with every function that writes it, wherever that is), `Timers` (every repeating
timer, named by the function it calls) and `Wakes` (what it may power on). The two digits are a band its area fits:
01–09 ground (no actions), 10–15 knowledge or brain, 16–19 core, 20 record or safety, 21 features, 22–24 ways in, 25
start. A new job type is named in R13 and a new event type in `EVENT_TYPES`. Today: `20-mcp` is a way in, numbered 20
(`BAND_TODAY`).

## Why

Parts are concatenated as written.
