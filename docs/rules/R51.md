# R51

## Rule

**R51.** Keys given once (A14a; contract 9.15, owner decision 22): a key, token or address the owner gives in their
own chat, on the page or in the paired Telegram chat, is taken out at the door, before anything else reads the words:
the page's chat route (`answerKeys`, before the owner's words) and `tgUpdate` (`tgKeys`, first, before the minute's
limit, an old message's too).
Two forms: `/key NAME value` (the value after the name, or on the next line; the name, as typed, must match
`^[A-Z][A-Z0-9_]{1,40}$` and not look like a key itself: no key shape, no piece between underscores of 8 or more
characters mixing letters and digits; a value is one run with no spaces and no quotes at its ends, or nothing is
kept), and the heartbeat's address (`hc-ping.com/<uuid>`), known by its shape anywhere in the words. The message is
answered by code, never by the brain: the chat keeps the words with the value replaced (`/key NAME [kept]` or `[not kept]`, and a name is said back only when a key came after it; an
address becomes `[key HEARTBEAT kept]`), then the answer as a notice; the journal gets those words as `said`; the
audit gets `key-given` with the name and whether it was kept. On Telegram the message that held it is deleted first
(`deleteMessage`), and when that fails the answer tells the owner to delete it. A key is kept by name in the secrets
file (R32) through `secretsWrite`. `GITHUB` and `HEARTBEAT` have a home of their own, each saved through its own
check: `GITHUB` is handed to `pull.sh setup` (on its input, for the repository already set up), which tries it with its
one fetch and keeps it as `github.token` only if GitHub takes it, so it is kept only when the file holds it afterwards;
`HEARTBEAT` is checked and saved as `PUT /heartbeat` saves it (`beatSave`), and the beat starts. Any other name goes in
`keys` (`{ NAME: { value, at } }`, 30 at most, a new value replacing the old), with values of 8 characters to 4 KB.
Nobody else gives a key: a member's, an agent's (the door or `ask_sparkie`) and a carry-on turn's words go to
`sparkieTurn`, whose first line, `keysHidden`, hides a `/key` form, a heartbeat's address and every kept value, and
keeps nothing; so the owner's own later message carries a kept key hidden too. Every kept value (named keys, the GitHub
token, the heartbeat's address, Telegram's token) is hidden wherever text is written or sent: `hideKeys` runs
`keptHidden` first (R7), with each value's %-form and its base64 at each alignment, read again when the file changed
(looked at once a second at most; no timer). A key is never shown back: no action, route or answer shows `keys`, and only `run` hands one to a command.
A value typed in plain words before it was given: `turnHistory` passes every earlier message through `keptHidden`, so
the brain is never sent a kept value as history, however it was kept; and when a key is kept at the door,
`hideKeptInChats` hides every kept value in the owner's stored chats (messages, titles, a carried-on request) and
saves them once if one changed (a chat
that never held one is left as it was, its time too), and the answer adds one line, only when the owner's own earlier
words held it, that the journal (never rewritten) and, if one was on Telegram, that earlier message still hold it.
Used by name (A14b, `21-run-keys.mjs`): `run` takes `keys`, names only (8 at most). Each value goes to the root
helper on its input (`--stdin`, after the call's script; the helper holds it in
`/run/spark-console/<id>/`, root's file on the memory disk that the owner's account there can read, and removes it
with the unit), and the unit's own first line puts it in the environment for that run alone: never on a command line,
in the unit's name or settings, the command's text or SHA-256, the journal's lines (`keys` names them), a button or
the copies. The mask hides a key the command prints as it is, %-encoded or in base64, and no other form: a command
given a key can show it another way, write it to a file or send it to any host the wall lets it reach. So a command
given a key is always asked, on a button that says so and names each key and each place it hasn't gone to (its Spark,
each host the command names as the sorter reads an address, or else where the sorter's `reach` says it goes by
itself), and it runs only on the owner's press of that button: never at once, never on a go-ahead; the owner's own
call is told so. After the run those places are kept with the key (`hosts`; a new value starts with none). It runs as
a change, never in a look's wall, and never `--open` (a `--home` run keeps the home's keys hidden). Refused in plain
words, nothing run (the text check is a courtesy; the press is the guard): a name not kept, `GITHUB`, `HEARTBEAT`, or
one the shell reads to decide what runs; root; a command whose text prints the environment (`env`, `printenv`, `set`
alone or `-x`, `export -p`, a shell's `-x`, `/proc/…/environ`, `ps e`); what the sorter calls open; a delete that
can't be put back or the brain's names; a script changed after its ask.

## Why

The owner gives a key once and is never asked again; a key in a chat, a log or the journal would travel with the
chats' daily copy, the install snapshots and the brain's context (critic-safety finding 4).

## Today

- Only `run` uses a kept key (A14b; `keep_running` and downloads are A14c). A program's own settings aren't read.
- The text check misses `declare -p NAME`, `typeset -p NAME`, a pattern for `environ` and `busybox env`.
- A word with a colon becomes a place; a place has no length limit; a host with an ending outside the list isn't one.
- An agent that may change things can learn which key names are kept and where a key has been.
- A value under 8 characters put in the secrets file by hand is handed over and never masked.
- A name such as WANDB_BASE_URL or AWS_ENDPOINT_URL may be a key's name, though it decides where a program sends.
- A key over ~900 characters across `forBrain`'s cut is shown in part.
- A shape mask can reach across a line break (`NAME=`, then `bytes: 49`, came back `[hidden] 49`).
- The helper: the held `stdin` is 0440 for the owner's group (0400, or removed once open, would do).
- The helper: no `LimitCORE=0` in the run wall.
- The helper: a killed call's held folder stays up to 130 minutes, longer if no call follows.
- No key can be removed but by hand (contract 9.15 asks first); `sparkie_setup` does not list their names.
- A key of another shape pasted without `/key` is hidden by shape when saved (R7) but reaches the brain for that turn.
- The secrets file is never copied: after a dead Spark 2 disk the owner gives every key again (contract 9.15).
- A value typed before it was given stays in the journal, in memory lines and in the earlier Telegram message; members'
  stored chats are not cleaned (their history to the brain is); a key kept another way cleans no stored chat.
