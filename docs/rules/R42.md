# R42

## Rule

**R42.** Sparkie's reach: root on a Spark only through one root-owned helper, `/usr/local/sbin/spark-console-root`,
which the owner's one-time command puts there with one sudo line that names that file and no other command.

- **The one-time command**, `deploy/root-for-sparkie.sh`, is always Spark 2's installed copy (from the Mac, over
  ssh). Once per Spark: compute Sparks first; Spark 2 last, only with `--hub`, and `--hub` nowhere else (by number
  here, by machine id there). As you, before the password: `/usr`, `/usr/local` and `/usr/local/sbin` root's alone;
  the copy's SHA-256; each name the run wall must hold made if missing. Then as root, staged where only root can
  change them: the line `<owner> ALL=(root) NOPASSWD: /usr/local/sbin/spark-console-root` through `visudo -cf`, the
  helper hashed again; both moved into place (root, 0440 and 0755); the proof. A failed proof removes both; a second
  run changes nothing. `--check` changes nothing, asks no password, and names listed names missing or
  linked, the login shell, whether PAM reads `~/.pam_environment`, enabled units run from the home, and
  whether Tailscale SSH is on. `--undo` removes the line, the helper, the mark. Only this command puts the helper on
  a Spark or replaces it.
- **What a caller chooses**, and nothing else: the verb (`check`, `prove`, `look`, `run`, R60's `keep` and `putback`,
  `stop` (ends that id's unit); `root` is refused), the id (8 to 40 of a-z and 0-9, starting every answer line), the
  command's bytes and SHA-256, the seconds, the folder, and for `run` only `--open`, `--net` (R60), R63's `--memory`,
  `--fleet` and `--gpu`, up to eight `--protect` folders (whole paths or `~/`, no link) and `--stdin`. The command
  goes to a root-owned file in `/run/spark-console/<id>/`, is hashed there and run by bash, never on a unit's command
  line; the folder goes when the call ends (a killed call's, 130 minutes on). A look: 60 s, no input, no `--open`; a
  change: 120 minutes. A look or run ends `<id> end <code>` (or `end time`) on its own last line; a refusal is one
  line, `<id> refused: <why>`, exit 125.
- **The walls** are a short-lived unit of the Spark's systemd with fixed settings. Look: a throw-away account
  (`DynamicUser`) with `CAP_DAC_READ_SEARCH` alone, `open_by_handle_at` filtered, the whole tree read-only, its own
  `/tmp`, IPC, network and devices, the hidden list. Run: the owner's account in its own process tree (`unshare`),
  without the groups that are root by another name (`setpriv`), `NoNewPrivileges`, the hidden and read-only lists, and
  R63's bounds. `--open` drops the hidden list, R63's network, device and home bounds, the own process tree and the
  left-out groups. The lists are the helper's text (design A, 2.13; R63 names them): hidden, in every home, where
  keys, sign-ins and tokens live, and `/run`, `/root`, the shadow files and other system secrets; read-only, Spark
  Console's code and caches, the helper and its line.
- **What the run wall holds in the owner's home is there, real and pinned.** `run` refuses by name when the owner's
  login shell is not bash, sh or dash, or a name of `MUST_BE_THERE` (start files, `.ssh`, `.docker`, the service
  manager's and Spark Console's folders, the shared folder and its `jobs`) is missing, a link or under one. Both walls
  leave other listed links alone; `check` names them. Where a change may write (R63), each folder from the home to a
  held path, never one under it, is bound onto itself (`BindPaths`), as are those two (`PLACES`) and each job's
  folder. A look refuses only while `.ssh`, `.docker` or the console's folder is a link or under one.
- **No look or change reads what was said** (R43 keeps it from every agent key): on Spark 2 both walls hide
  `chats.json`, `memory.json`, `memory-past.json`, `audit.jsonl`, `saved-workflows.json`, their copies and the
  journal; the owner asks through `recall` and `memory`.
- **It refuses** when the Spark lacks what a wall needs (systemd 248 or newer as the first process, `cgroup2`, an
  `unshare` with `--kill-child` and `--mount-proc`, a `setpriv` with `--groups` and `--bounding-set`, python3); when
  its file or a folder above it can be written by anyone but root; when not called through sudo by an ordinary account
  in `/etc/passwd`; and, for `look` and `run`, when the mark (`/var/lib/spark-console/proved`: the helper's
  SHA-256, systemd's version, the kernel) is missing, out of date or writable by anyone but root.
- **The proof** (`prove`) makes each attempt outside the walls as the owner, then inside each wall, directly and from
  a child, where it must fail; what is left is checked from outside: a write through a link, a connection, the Docker,
  Tailscale, console and door sockets, another program's environment, a write that stays, another program's `/proc`, a
  signal, more rights, starting something outside, a hidden key (also by handle), a disk or the GPU, something left
  behind, root with no net, (14) moving a folder above a held one, R60's 15 to 18, (19) swapping a job's folder, (20)
  the helper's `stop`, and R63's 21 to 26. It removes the old mark first and writes one only when every attempt was
  stopped, else names it. A "blocked" counts only when the same attempt worked outside (15 to 18, 23 and 24: checked
  afterwards; 21 read inside): the proof fails when its own program, files, folders, key or line did not, when attempt
  2 missed its program on the loopback, or when the checks afterwards missed what it left on purpose. Only the
  sockets, a user manager, the devices and attempt 22's addresses may be absent, saying why.
- **No host outside the owner's own is contacted.** The proof's connection attempts (2 in a look, 22 in a change) go
  to its own program on the loopback, this Spark's Tailscale (`100.100.100.100:53`) and its own port 22, and all must
  fail; no internet host. The run wall reaches the internet on purpose, the tailnet only with `--fleet` (R63); the
  console gives a Spark's own address only `/v1/` (R5), so the open way in is Tailscale SSH, which `--check` reports.
- Run as root it reads nothing from the environment but `SUDO_UID` and `SUDO_USER`, and has no test switch; run as
  anyone else it is a rehearsal under `SPARK_CONSOLE_REHEARSAL`, with the stand-ins on PATH. Only R60's put-back touches
  SSH settings, Tailscale, a firewall or users, to put back what was; none touches Docker or a container.
- **The console's call** is `helperCall` alone, and `run` (core) is today a look in the look wall; the rest is in
  `docs/how/call-the-root-helper.md`.
- **Its event** (`commandShown`) adds `where`, `line` (first 200), `tail` (last line's last 200, `exit N`), `root`,
  `kept` (its record), `look` (the result's own line), masked, cut by whole characters; on the page, one row.

## Why

Root for Sparkie with no password stored anywhere and no other script made silent root, and every command it runs
inside walls the kernel holds, proven on that Spark before they are used (`docs/design-2026-11-13/README.md`,
sections 4 and 7, items 1 and 2; design A, 2.13).
