# R42

## Rule

**R42.** Sparkie's reach: root on a Spark only through one root-owned helper, `/usr/local/sbin/spark-console-root`,
which the owner's one-time command puts there with one sudo line that names that file and no other command.

- **The one-time command**, `deploy/root-for-sparkie.sh`, is always Spark 2's installed copy (from the Mac it runs
  that copy over ssh). Once per Spark: compute Sparks first; Spark 2 last, only with `--hub`, and `--hub` nowhere else
  (by number here, by machine id there). As you, before the password: `/usr`, `/usr/local` and `/usr/local/sbin` root's
  alone; the copy's SHA-256; each name the run wall must hold made if missing. Then as root, staged under names nothing
  uses and checked where only root can change them: the line `<owner> ALL=(root) NOPASSWD: /usr/local/sbin/spark-console-root`
  through `visudo -cf`, the helper hashed again; both moved into place (root, 0440 and 0755); the proof. A failed
  proof removes the line and the helper; a second run changes nothing. `--check` changes nothing and asks no password;
  it also names held names that are missing or links, whether PAM reads `~/.pam_environment`, your enabled units that
  run a program from the home, and whether Tailscale SSH is on. `--undo` removes the line, the helper, the mark. Only
  this command puts the helper on a Spark or replaces it.
- **What a caller chooses**, and nothing else: the verb (`check`, `prove`, `look`, `run`; `root` is refused until the
  net is built), the id (8 to 40 of a-z and 0-9; every answer line begins with it), the command's bytes and SHA-256,
  the seconds, the folder, and for `run` only `--open`, up to four `--protect` folders (whole paths, no link) and
  `--stdin`. The command goes to a root-owned file in `/run/spark-console/<id>/`, is hashed there and run by bash, never
  on a unit's command line; the folder goes when the call ends (a killed call's, at a later call after 130 minutes). A
  look: 60 s, no input, no `--open`; a change: 120 minutes. A look or run ends `<id> end <code>` (or `end time`) on its
  own last line; a refusal is one line, `<id> refused: <why>`, exit 125.
- **The walls** are a short-lived unit of the Spark's own systemd with a fixed list of settings. Look: a throw-away
  account (`DynamicUser`) with `CAP_DAC_READ_SEARCH` alone, `open_by_handle_at` filtered, the whole tree read-only, its
  own `/tmp`, IPC, network and devices, the hidden list. Run: the owner's account in its own process tree (`unshare`),
  without the docker, lxd, libvirt, disk and sudo groups (`setpriv`), `NoNewPrivileges`, no loopback but the resolver
  (`IPAddressDeny`), the hidden and read-only lists. `--open` drops the hidden list, the loopback rule, the own process
  tree and the left-out groups. The lists are the helper's text (design A, 2.13): hidden, in every home, where keys and
  sign-ins live (`.ssh` with its plain non-key files put back, `.docker`, Spark Console's state folder with all but its
  sign-in files and sockets put back, token files, histories), and `/run`, `/root`, the shadow files and other system
  secrets; read-only, the owner's start files, what the owner's service manager reads, Spark Console's caches, set-up
  scripts, page, code and source, the editor's programs, the helper and its line.
- **What the run wall holds in the owner's home is there, real and pinned.** `run` refuses by name when a name of
  `MUST_BE_THERE` (the start files, `.ssh`, `.docker`, the service manager's folders, `.cache/spark-console`) is
  missing, or when a held path is a link or under one; each folder between the home and a held path is bound onto
  itself (`BindPaths`), so it cannot be moved or replaced. A look is not refused for these.
- **It refuses** when the Spark lacks what a wall needs (systemd 248 or newer as the first process, `cgroup2`, an
  `unshare` with `--kill-child` and `--mount-proc`, a `setpriv` with `--groups` and `--bounding-set`, python3); when
  its file or a folder above it can be written by anyone but root; when not called through sudo by an ordinary account
  that `/etc/passwd` knows; and, for `look` and `run`, when the mark (`/var/lib/spark-console/proved`: the helper's
  SHA-256, systemd's version, the kernel) is missing, out of date or writable by anyone but root.
- **The proof** (`prove`) makes each attempt outside the walls as the owner, then inside each wall, directly and from
  a child process, where it must fail; what is left is looked for from outside afterwards: a write through a link, a
  connection, the Docker and Tailscale sockets, `api.sock` and the door's socket, another program's environment, a
  write that stays, another program's `/proc`, a signal, more rights, starting something outside, a hidden key (also by
  handle), a disk or the GPU, something left behind, root with no net, and (14) moving a folder above a held one. It
  removes the old mark first and writes one only when every attempt was stopped; a failure names the attempt. A
  "blocked" counts only when the same attempt worked outside: the proof fails when its own program, files, folders, key
  or line did not, when attempt 2 missed its program on the loopback, or when the checks afterwards did not see what it
  left on purpose. Only the sockets, a user manager and the devices may be absent, with the reason said.
- **No host outside the owner's own is contacted.** A look's connection attempt goes to the proof's program on the
  loopback, this Spark's own Tailscale (`100.100.100.100:53`) and its own first address on port 22: it shows a look
  reaches none of them, and nothing about the wider internet by a test of its own. The run wall reaches the internet
  and the tailnet on purpose; the console answers a Spark's own address only on `/v1/` (R5), so the open way through
  the tailnet is Tailscale SSH, which `--check` reports.
- Run as root it reads nothing from the environment but `SUDO_UID` and `SUDO_USER`, and has no test switch; run as
  anyone else it is a rehearsal under `SPARK_CONSOLE_REHEARSAL`, with the stand-ins on PATH. It never touches SSH
  settings, Tailscale, a firewall, users, Docker or a container.

## Why

Root for Sparkie with no password stored anywhere and no other script made silent root, and every command it runs
inside walls the kernel holds, proven on that Spark before they are used (`docs/design-2026-11-13/README.md`,
section 4 and section 7, items 1 and 2; `docs/design-2026-11-13/a-workspace.md`, 2.13).

## Today

Step 1a and the held lists only: the helper, its proof and the one-time command. Nothing in the console calls the
helper yet (the next step adds the call, the "run this one command first" answer, the known-helper check and the proof
in the self-test). The net, and with it `root`, is a later step. Whether the walls hold is decided by the proof on
each real Spark: the tests use stand-ins, which show what is asked for, not what a Spark grants. The helper's hash
changed with the held lists; no real Spark has the helper yet, so nothing needs running again.
