# R42

## Rule

**R42.** Sparkie's reach: root on a Spark only through one root-owned helper, `/usr/local/sbin/spark-console-root`,
which the owner's one-time command puts there with one sudo line that names that file and no other command.

- **The one-time command**, `deploy/root-for-sparkie.sh`, is always Spark 2's installed copy (run from the Mac, it runs
  that copy over ssh). Once per Spark: compute Sparks first; Spark 2 last and only with `--hub`, and `--hub` nowhere
  else (refused by the Spark's number before anything connects, and by its machine id on the far side). In this order:
  `/usr`, `/usr/local` and `/usr/local/sbin` writable by root alone; the copy's SHA-256 is the one Spark 2 sent; the
  line `<owner> ALL=(root) NOPASSWD: /usr/local/sbin/spark-console-root` passes `visudo -cf` before anything is put in
  place; the helper (root, 0755); the line in `/etc/sudoers.d/spark-console-root` (root, 0440); the proof. A failed
  proof removes the line and the helper again. A second run changes nothing. `--check` changes nothing and asks no
  password; `--undo` removes the line, then the helper, then the proof's mark. Only this command puts the helper on a
  Spark or replaces it (the owner's call on letting Sparkie replace it is open; until then, no).
- **What a caller chooses**, and nothing else: the verb (`check`, `prove`, `look`, `run`; `root` is always refused
  until the put-back net is built), the id (8 to 40 of a-z and 0-9; every answer line begins with it), the command's
  bytes and their SHA-256, the seconds, the folder, and for `run` only `--open`, up to four `--protect` folders (whole
  paths, no link) and `--stdin`. Every other path, name and setting is the helper's own text or read from the Spark.
  The command is written to a root-owned file in `/run/spark-console/<id>/`, hashed there (one changed byte starts
  nothing) and run from there by bash; it never stands on a unit's command line. The folder goes when the call ends
  (also on a hang-up); one left by a call killed outright is removed by the next call once older than 130 minutes. A
  look is held to 60 s, with no input and no `--open`; a change to 120 minutes. A look or run ends with a line break and `<id> end <code>` (or `end time`),
  the last line; a refusal is one line, `<id> refused: <why>`, exit 125.
- **The walls** are a short-lived unit of the Spark's own systemd with a fixed list of settings. Look: a throw-away
  account (`DynamicUser`) with `CAP_DAC_READ_SEARCH` alone and `open_by_handle_at` filtered; the whole tree read-only;
  its own `/tmp`, IPC, network and devices; the hidden list. Run: the owner's account in its own process tree
  (`unshare`), without the docker, lxd, libvirt, disk and sudo memberships (`setpriv`), `NoNewPrivileges`, no loopback
  but the resolver (`IPAddressDeny`), the hidden list and the read-only list. `--open` drops the hidden list, the
  loopback rule, the own process tree and the left-out memberships, and keeps the rest. Both lists are the helper's
  text: what holds keys (`.ssh` but `authorized_keys`, `known_hosts`, `config` and `*.pub` as plain files, `.gnupg`,
  token files, histories, Spark Console's secrets folder, sign-in files and sockets, `~/.local/share/spark-console`,
  `/run`, `/root`, the shadow files, host keys, `/etc/ssl/private`, network settings, Tailscale's, Docker's and
  containerd's data, `/var/lib/spark-console`, `/var/backups`, swap files) in every home; and, read-only, the owner's
  start files, `.config/systemd`, `.config/environment.d`, `.config/autostart`, Spark Console's code and source, the
  helper and its line.
- **It refuses** when the Spark lacks what a wall needs (systemd 248 or newer as the first process, `cgroup2`, an
  `unshare` that knows `--kill-child` and `--mount-proc`, a `setpriv` that knows `--groups` and `--bounding-set`,
  python3 for the proof); when its own file or a folder above it can be written by anyone but root; when it was not
  called through sudo by an ordinary account that `/etc/passwd` knows; and, for `look` and `run`, when the proof's mark
  (`/var/lib/spark-console/proved`: the helper's SHA-256, systemd's version, the kernel) is missing, out of date, or
  writable by anyone but root.
- **The proof** (`prove`) makes each attempt outside the walls as the owner, where it must work or the thing is not
  there, then inside each wall, directly and from a child process, where it must fail; the writes, link targets and
  programs left behind are looked for from outside afterwards: a write through a link, a connection, the Docker and
  Tailscale sockets, `api.sock` and the door's socket, another program's environment, a write that stays, another
  program's `/proc`, a signal, more rights, starting something outside, a hidden key (also by file handle), a disk or
  the GPU, something left behind; and root with no net. It removes the old mark first and writes a new one only when
  every attempt was stopped; a failure names the attempt. A "blocked" counts only when the same attempt was seen
  working outside the walls: the proof fails when its own program outside the walls did not start or stopped early,
  when an attempt that uses its own files, folders, key or line did not work outside, when attempt 2 did not reach its
  program on the loopback, when the checks afterwards did not see what it left on purpose, or when it got no file
  handle or no folder on a disk. Only the sockets, a user manager and the devices may be absent, with the reason said.
- **The proof contacts no host outside the owner's own.** Its connection attempt goes to the proof's own program on
  the loopback (both walls) and, for a look, to this Spark's own Tailscale at `100.100.100.100:53` and to the Spark's
  own first address (`hostname -I`) on port 22. That shows a look reaches neither its own Spark nor the tailnet, and a
  look's private network has no route anywhere else either; but no internet host is tried, so the proof shows nothing
  about the wider internet by a test of its own. The run wall reaches the internet on purpose: only its loopback is tried.
- Run as root it reads nothing from the environment but what sudo sets (`SUDO_UID`, `SUDO_USER`) and has no test
  switch. Run as anyone else it is a rehearsal: every system path is read under `SPARK_CONSOLE_REHEARSAL`, and it calls
  the stand-ins on PATH. It never touches SSH settings, Tailscale, a firewall, users, Docker or a container.
- **The console's call** is `helperCall` alone, and `run` (core) is today a look in the look wall; their rules, who may
  call, and what is refused first are in `docs/how/call-the-root-helper.md`.
- **Its event** (`commandShown`) adds `where`, `line` (first 200), `tail` (last line's last 200, `exit N`), `root`,
  `kept` (its record), `look` (the result's own line), masked, cut by whole characters; on the page, one row.

## Why

Root for Sparkie with no password stored anywhere and no other script made silent root, and every command it runs
inside walls the kernel holds, proven on that Spark before they are used (`docs/design-2026-11-13/README.md`,
section 4 and section 7, items 1 and 2; `docs/design-2026-11-13/a-workspace.md`, 2.13).

## Today

Steps 1a and 1b: changes, `root` and the net come later. That the walls hold is decided by the proof on each real
Spark: the tests use stand-ins, which show what is asked for, not what a Spark grants. The card (Rules) lists the
look's own gaps.
