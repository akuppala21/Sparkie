# R10

## Rule

**R10.** Every command on a Spark goes through `spawnOn`; `run` never rejects, so test `code`. Two failures in a row
mark a Spark as not answering for a minute (`noteReach`), each judged by the moment it speaks for: a failed connection
by when its command began, so one begun before the Spark last answered marks nothing (a Spark back on isn't taken for
off by what ended late); a time-out by when it ended, so it always counts (a Spark that takes commands and never
answers, a frozen worker, is marked). Today: ssh is spawned
only there; these local commands on Spark 2 skip it: tailscale ip, python3 for YAML, systemd-run (the rollback, and
`pull.sh install`), `pull.sh` (`setup`, `check`), tailscale status and serve status (four callers), tar for the backup,
and git, tar and node for Sparkie’s own code; HTTP to model servers does not use it.

## Why

Timeouts, offline memory and the test switch live there.
