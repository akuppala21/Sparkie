# R10

## Rule

**R10.** Every command on a Spark goes through `spawnOn`; `run` never rejects, so test `code`. Today: ssh is spawned
only there; five local commands on Spark 2 skip it (tailscale ip, python3 for YAML, systemd-run, tailscale status
twice, tar for the backup); HTTP to model servers does not use it. A command the console runs as the owner on a Spark
reads nothing from the owner's home: it takes its programs from `FIXED_PATH` (`/usr/local/sbin`, `/usr/local/bin`,
`/usr/sbin`, `/usr/bin`, `/sbin`, `/bin`, `/snap/bin`; no home folder), set before a plain command and before
`bash -s`, and again by `PREAMBLE` at the top of every script, where `python3` is `python3 -I` (no folder of its own,
no user site) and `curl` is `curl -q` (no `~/.curlrc`); the status worker runs as `python3 -I`. The library and
setups scans list only folders, cache entries and snapshots named with letters, digits, `.`, `_` and `-`, and keep a
model's architecture, type, dtype and `spark.json` title only when they are 80 characters or fewer of letters,
digits, spaces and `._+/()-` (a context length only as a whole number). Each status round looks for every program
the console calls (`PATH_PROGRAMS`) on that PATH; one that is missing is a needs-you line naming it and its Spark.
`deploy/path-check.sh` is the same look by hand, and changes nothing.

## Why

Timeouts, offline memory and the test switch live there. A change inside the run wall may write most of the home;
the console runs as the owner outside the wall, so a program, a Python module or a curl setting it found there would
be a way out (`~/base64.py`, a `.pth`, `~/.local/bin/hf`, `~/.curlrc`), and a folder whose name holds a line break
would add lines of its own to the library's answer (the Spark's address, its memory).

## Today

Marked in the Rule text above. `deploy/plugs.sh`'s part on Spark 2 runs Python as `-I`; the installer, its restore
script and watchdog, `deploy/pull.sh` and the update guard to come don't yet. Docker's client still reads
`~/.docker`, and the five local commands use the service's own PATH.
