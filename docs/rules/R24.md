# R24

## Rule

**R24.** Sensing only reads; loops start on delayed timers, one round at a time; status passes `cleanStatus`. The
watcher’s sysfs readings (hottest thermal zone, NVMe, fan) print before the docker look and never change how its
script ends; each is a range-checked number or null, and no limit on them decides anything (`19-watcher.mjs`
`readingsScript`, `darkPeriods`). The watcher’s container look ends with `docker ok` only when `docker ps` exited 0
(`PIPESTATUS`, inside an `if`), so that line never changes how the script ends either. The brain check
(`brainCheck`) only asks Sparkie's model, with one toy tool written in its part, never an action: it changes nothing
and has no timer of its own. It runs after a switch, on the owner's `POST /main/check`, and once, a minute after Spark
Console starts, when the brain in use has no profile (`adoptRunning`); one at a time, one request at a time, each
waiting while a chat, an app call or a switch is on the brain; never inside a chat turn. A brain that doesn't answer
keeps no profile. The rail reads the outcome: R52.

Wall electricity keeps separate calendar-month totals in `energy.json`, in `America/Los_Angeles`. Only distinct
plug observations count, including real zero watts; GPU power never fills a missing wall reading. Adjacent readings
at most two minutes apart are integrated, with interpolated watts where a month changes. Missing readings, a changed
plug and longer gaps are left uncounted. Months and their coverage survive a restart; the current month appears on
read even before its first interval. A partial month is marked partial. A legacy lifetime total is assigned only
when both saved timestamps prove it belongs to one month; it stays partial. Other lifetime totals remain intact and
unallocated. Unreadable electricity state does not stop fleet or power status (R20 preserves its saved data).
