# R34

## Rule

**R34.** The owner’s words (2026-11-11): `/status`, `/pause`, `/restart sparkie`, `/stop`, `/undo`, `/undo update`,
`/allowed` (also `/allowed off 2` or `all`), `/putback` and `/help`, typed as the whole message (trimmed, lowercased, `_` as a space, 40 characters at most) in the owner’s own page chat
(never one with `agent`), are answered by code in the chat route before any model call, also while an answer is coming
there, and saved as one notice. `/status` says what is waiting on the owner right after Sparkie's own line (“Needs
you: …”, the same lines as `fleet_status.needsOwner`, or “Needs you: nothing.”); Telegram's `/status` is the same
text, then one line saying whether approvals from Telegram are on (R32). In the paired Telegram chat (R32) `/status`, `/pause`, `/restart sparkie`, `/stop`, `/undo`, `/allowed`,
`/putback`, `/undo update`, `/resume`, `/admin` and `/help` are answered by code too through `tell()`. Administration
uses the same shared operations as the page and asks for the exact owner confirmation before making a change. They
are not tools (no `/mcp`, `/v1`, `POST /actions` or carry-on turn reaches them) and can only look, pause agents’
changes, bring back the brain’s own container, end the talking (`/stop` also closes that chat’s open dangerous ask and
removes its box, R62), list or take away what is always allowed (`/allowed`, R65), go back a build, put back the
newest change still open inside the lock-out net (`/putback`, R71), or put back this chat’s last change (`/undo`). `/undo`, on the page and in
the paired Telegram chat, runs `undo_last_change` as the owner’s own, also while changes are paused: its steps pass the
pause (`ownerWord`, `pausedCheck`) and count toward no hour (`hourCounts`, R9). It goes back only on the chat’s last
change of any kind (a command’s files, a change still running, a model change on the list); when that one is one it
can’t put back (a change inside the lock-out net, a file saved, power, memory, an update: `undoNotMine`), it says so,
names the one before it, and puts nothing back (C-16). An undo that put nothing back, or only part, takes its mark off
the change, so the next `/undo` is that change again, never the one before it (R1-01). Bringing back: restart it with
`restartBrain()` when Docker says it is running and has run over 10 minutes; when it is stopped or gone from Docker,
start the saved setup through the page’s `main-start` job (`mainPlan`, `startMain`, which removes the old container
first, so a stopped one’s stale `/tmp` rendezvous file can’t hang the load), with every other container on that Spark
kept running. Each only when no brain job runs, nothing else holds the brain’s Spark and no restart is going, and each
holds that Spark’s claim while it runs; never another model or setup, and nothing is stopped to make room. `/stop`
ends the reply under way in that chat (`stopTurn`: the model is no longer asked and its call ends whatever state its
connection is in, a lookup under way finishes and nothing after it runs) and clears the chat’s carry-on task; it never cancels an operation and never stops a model, and
results of operations already started are still posted. `/undo update` calls the `undo_update` action through
`runAction` with the real channel and adds no rule of its own, so R31 decides: on the owner’s tailnet it runs; from a device
signed in over the internet the answer is the owner-only button. The same operation is available in the paired
Telegram chat. `/resume` raises an exact owner confirmation and works with the brain down or changes paused. By
hand, with the console down: `~/.local/share/spark-console/go-back.sh` (the newest complete snapshot not marked
`same`, its `restore.sh`, files only, no options) and `RECOVERY.txt` beside it, copied from `deploy/` by every install
before anything installed is replaced; `/help` prints both paths. With the brain not answering, a one-line `/` message
that is not a word gets `/help` (a look at the brain that takes over 6 seconds counts as not answering). The page
sends a word even while another chat’s answer is still coming. Owner administration commands preserve their argument spelling and use a bounded parser; they cannot call an arbitrary route.

## Why

They must work with the brain down or stuck, with the same owner authority and confirmations as the page. A dead console still needs
one fixed line to type.
