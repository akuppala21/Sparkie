# R75

## Rule

**R75.** Where the sorter can't tell, the stricter side (R55's classes, R64's shape; the final reads and F1,
2026-11-16).

- **A doubt does not stop the read** (F1). Each part (a program of a pipe, a command of a list, what a `$( )` or a
  `-c` holds) is sorted on its own; a part it doubts is asked, saying why, and its words are still read by the tables
  that need no option's meaning (ways in, the helper, the brain, keys, hosts). The strictest class wins and every field
  is gathered. Only a bound (folders, steps, depth, length) stops the whole read. A sign outside plain ASCII is asked
  and the read goes on.
- **`unreadable`**: the sorter's words when the shell reader can't read the command or a part of it (a quote left
  open, a loop over a `$`, a form it doesn't know, a bound), else null; `unshown` is set with it. An option a program's
  table doesn't hold is asked, not `unreadable`; inside a program that runs code (a shell, an interpreter, a wrapper,
  a build, a package tool, git, ssh, docker) that doubt sets `unshown`.
- **What runs code:** an interpreter by its real name (`python3.12`, `pypy3`, `lua5.4`) is that interpreter. The
  launchers wrap the script they name (`scripts`): `torchrun`, `deepspeed`, `accelerate launch`, `uv run`, `pytest`,
  `python -m torch.distributed.run` (or `launch`, `pytest`), behind `nohup`, `time`, `stdbuf`, `ionice`, `nice`,
  `taskset`, `numactl` or `chrt`; with no file, a folder or a file not `.py`, the code is `unpinnable`. A `for` loop
  over plain names, the whole command, is its body once per name. A program it doesn't know, or a lock-out or
  become-user one with no handler (`chroot`, `nsenter`, `runuser`, `sg`), handed a shell, an interpreter, `-c` or a
  script sets `unshown`; so do `npm exec`, `dlx`, `init`, a unit given to systemctl by path, and ssh's `ProxyCommand`,
  `LocalCommand`, `KnownHostsCommand`, `RemoteCommand`. awk is read with its strings taken out: `system`, a pipe,
  `print >` and `getline <` are a change.
- A container that reaches the host is the lock-out class: every privilege, a capability, a device, a security option,
  another container's mounts, the host's network, processes, IPC, users, host name or control groups (or another
  container's), a mount at or above a way in or of `/`, `/etc`, `/root`, `/home`, `/run`, `/proc`, `/sys`, `/dev` or
  Docker's socket, a word it can't read there, a lock-out program among its words; so are `nsenter`, `chroot`,
  `unshare`, `systemd-nspawn`, `runc`, and `ctr`, `crictl` or `machinectl` starting one.
- A command for the hub from a compute Spark (ssh, scp, rsync, sftp, git, `docker -H`, `DOCKER_HOST`, `tailscale ssh`,
  by any name or address the console knows) is not done: it goes through the hub's own path.
  A host that can't be told there (a `$`, a one-word name, an address of the tailnet or the home network it doesn't
  know, a host option, a Docker context) may be the hub: the dangerous ask (kind `brain`), saying so.
- What the net can't put back (`lasting`, not done) by any spelling: a Tailscale sign-out, a sign-in again (`login`,
  `switch`, `--force-reauth`, `--auth-key`, `--login-server`), its lock, a verb it doesn't know or words it can't read
  (options first, `xargs`, a `$`); a package the ways in depend on removed by any package tool (`apt`, `dpkg -P`,
  `snap remove`, a trailing `-`, `autoremove`); and an inline program naming `tailscale`, `userdel` or a package tool
  beside a way-in package or a removal. An inline program naming a way-in program is the lock-out class.
- Also the lock-out class: a way-in process killed by a name or a pattern that may match it (or one it can't read),
  `killall5`, `fuser -k`, `kill -1`, any `kill`, `pkill`, `killall` or `skill` as root, and one by user, group, session
  or pid file; `rfkill`, `networkctl`, `wg`, `wg-quick`, `iwctl`, `dhclient`, `brctl`, `bridge`, `ipset`, `conntrack`,
  `netfilter-persistent`, `iptables-apply` but their read forms; a network driver taken out (`modprobe -r`, `rmmod`); a
  write under `/proc/sys/net` or `/sys/class/net`; an init script (`/etc/init.d/x`, `invoke-rc.d`, `update-rc.d`) as
  its service; `systemd-user-sessions`; another target or run level (lasting: it stops the net's timer), a slice or a
  core target stopped, killed or frozen; the clock set (`date -s`, `timedatectl`, `hwclock`); `hostnamectl` renaming; a
  way-in program's own file changed, moved or removed (`sshd`, `tailscaled`, `sudo`, `ufw`, a login shell, PAM's
  modules, `systemctl`, `dbus-daemon`, journald), or a library they load (the loader, libc, libpam, libcrypto, libssl,
  libsystemd, libnss and their kin). Named as a word (`ls /bin/bash`, `docker exec web /bin/bash`), such a file is
  not. A way-in program a timer or a schedule runs later (`systemd-run`, `at`, `crontab`, a schedule or a unit
  written) is lasting: it runs after the net has kept or put back.
- Work started later (`later`, R70): any `systemd-run`, `at` or `batch`, `crontab` but `-l` and `-r`, a timer started
  or enabled, `update-rc.d` enabling, `systemctl set-environment` or `import-environment`, a unit given by path, and a
  file written with content in one of the doors it lists: where systemd reads units (a unit, a drop-in, a `.wants`
  link), its generators, sleep and shutdown folders; cron's and at's; `/etc/rc.local`, `/etc/init.d`, `rc?.d`; udev's
  rules; logrotate's; `update-motd.d`; apt's settings with a hook; `/etc/ld.so.preload`; the shells' start files
  (`/etc/profile`, `profile.d`, `bash.bashrc`, `/etc/environment`, root's); the desktop's autostart. A removal, a move away, a copy's source,
  an empty file or a name alone (`touch /tmp/my.target`) is not later.
- A protected container (the brain's; `CONFIG.protect`, or `protect` given) stopped, killed, removed, restarted, paused,
  updated, renamed or entered is not done (on the hub, its own rule); a hex word (an id's start), a `$`, a pattern, a
  compose project or the Docker service stopped is the dangerous ask (kind `brain`), saying so.
- A key's text (a file `keyWord` says is a key, R51) is not done when the command reads it as a source (`<`, a file a
  program reads, what `cp`, `scp`, `rsync`, `tar`, `zip`, `curl -T` or `-d @`, `git add`, `docker cp` take) and its
  bytes leave: shown by a look, on through a pipe or a `$( )`, into a file not a key's name or place, to another
  machine but under a key's name there, or to code the sorter doesn't read or a program it doesn't know. Into a folder,
  here or there, a key is judged by the name it lands under. One rule, no list of ways out. Moved or copied to a key's name or place, or `chmod`, it is asked; only named, it is as the rest is.
- In text a program reads, `.*`, `.+`, `.?` and `\` are a regular expression, not dot files (`s/.*//`); `~/.*` counts.

## Why

The sorter reads lists: what its tables hold, it knows; what they don't, it can't guess as safe. So where it can't
tell it takes the stricter class, says why, and reads on, so one doubt never hides a worse answer behind it (the
sorter's final read of round two, 2026-11-16).

## Today

On, with R55 and R64. Every list here is a list and never complete: a later door, a way-in library, a launcher or a
key's way out it doesn't hold is asked as a plain change would be, with its text on the button. `hf --token
$(cat ~/.cache/huggingface/token)` is not done: the key leaves through a `$( )` into an argument, though hf reads that
file itself; so is `openssl … -CAfile ca.pem`, a program it doesn't know handed a key-shaped name.
