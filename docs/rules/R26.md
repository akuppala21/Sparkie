# R26

## Rule

**R26.** Outside text reaches the brain labelled as data: not as an ordinary user message (program messages carry
`notice: true`), not in the system prompt, not into memory without a button, and not into a saved workflow without a
button that lists its steps (R25). `running_models {detail}` carries a container’s own command: it is labelled
`textFromSparks`, and a turn that called it counts as having read outside text (`readOutside`), though plain
`running_models` stays an inside read. Today: the system prompt carries memory lines (agents’ too) and, in chats
without tools, the page’s snapshot; the carry-on message is stored as role user with `auto: true` and later goes to
the brain unlabelled; an agent that may change things calls `remember` over `/mcp` with no gate and no button; after
reading outside text a line still needs no button when 60% of its words are the owner’s. `sparkie_setup` labels its
fault and crash text as data (`faultsNote`); it stays an inside read. `sparkie_setup {about: "abilities"}` (“What can
you do?”, A3) is built only from the action registry’s titles and lines written in the code (`abilities`). It must
never carry saved-workflow, memory, recipe, file or container text, so it stays an inside read and masking leaves it
unchanged. `fleet_status`’s `needsOwner` lines (`openProblems`, 20-needs) are written by code from Spark Console’s own
state (names of Sparks, containers and files only; never a log line, an error’s text or a program’s output), so
`fleet_status` stays in `INSIDE_READS`; a line that quotes outside text must not join the list. The journal’s text
(R43) reaches the brain only through `recall`, labelled as data and outside `INSIDE_READS`: after it, `remember` needs
a button.

## Why

The brain acts on what it reads.
