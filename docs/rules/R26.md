# R26

## Rule

**R26.** Outside text reaches the brain labelled as data: not as an ordinary user message (program messages carry
`notice: true`), not in the system prompt, not into memory without a button, and not into a saved workflow without a
button that lists its steps (R25). Inside is the exception (A-17, 2026-11-16): a lookup is an inside read only when its
action says so itself (`inside: true`, or a function of its arguments), and only where every field it returns is
written by the console's own code or is a bare name (`bareName`: one word of letters, digits and `._-/:@+`, at most 100
signs; a name with a space is left out). Inside: `fleet_status` (its `needsOwner` lines are written by code from Spark
Console's own state, `openProblems` in 20-needs: names of Sparks, containers and files only, never a log line, an
error's text or a program's output, and a line that quotes outside text must not join the list; its container and
parked model names bare), `linked_sparks` (link names and addresses bare), `guide`, and `sparkie_setup {about:
"abilities"}` (“What can you do?”, built only from the action registry's titles and lines written in the code,
`abilities`: never saved-workflow, memory, recipe, file or container text). Every other lookup, a new one too, counts as
outside text once handed over (`readInside`, `readOutsideBy`), its error too: `models_on_disk` (a model's own title,
architecture, type and dtype, R53), `running_models` (labels, a served model's id; with `detail` a container's own
command, labelled `textFromSparks`), `where_it_fits`, `deploy_plan` and `cluster_plan` (a GPU process's name),
`should_be_running` (a failure's first line), `sparkie_setup` otherwise (faults, crash text, install notes, the brain's
last line, each labelled as data), `workflows`, `memory`, `recall` (the journal's text, R43). `run` and `write_file`
count only once something ran there (a command that ran, a failed one too; one started with minutes; write_file's ask,
which shows the file's old lines; a failure on the far side), never one refused, asked or answered "nothing ran"; what
a command printed counts from the next round, as the brain asked for a round's calls before any came back. After an
outside read a change on a Spark is asked (R61), and `remember` is a button unless 0.6 of the line's own words are the
owner's (`memoryClear`), not a quarter.

The record ahead of the owner's words in every turn (`brainContext`: `fleetNotes`, 19-watcher.mjs; the date line; the
memory picks and lesson cards) and the system prompt's memory block hold the console's own words, bare names and the
owner's own lines, never text from a Spark, a container, a model or an agent. A memory line an agent noted (by anyone
but the owner) rides in neither the block nor the picks (`memorySystem`, `memoryPicks`, `ownLine`): it stays in memory,
`recall` gives it, and the block says in code's words how many there are and that `recall` has them
(`memoryAgentsLine`). A lesson card carries only a lesson's typed fields, each checked by its shape (a model, container
or image name, an engine from the console's list, a known failure's title, days); lessons are written by code from
operations, never by an agent. an event is said by code (`recordEvent`: what happened, where, when, its kind; an operation's error
as "operation_log has why", a notice as "fleet_events has its words", a bring-back's reason as "should_be_running says
why"), and a container, model or served id that isn't a bare name is not shown (`recordName`). The tools that have the
words are outside reads. A chat keeps what its turns read from outside (`conv.reads`: each read by its journal record,
the newest 40, `chatReadsKeep`), and `chatEarlier` gives a later turn those reads, loaded, and Sparkie's earlier
answers, in the form `cameFrom` takes (contract 8.5).

## Why

The brain acts on what it reads.

## Today

- `hostClear` (21-ladder.mjs) does not ask `chatEarlier` yet: a command that names what an earlier turn read, and not
  the owner's words, still runs at once when the owner's new message asks for work (contract 8.5).
- With the eval's switch that turns the picker off (`names`, stand-in consoles only) the block is built as before the
  picker (`memoryPrompt`), agents' lines in it, labelled.
- A power record's problem (a wake that failed) carries the error the plug controller or SSH gave, in `fleet_status`
  and the record (`powerMark`, 21-power.mjs). A Spark's `issues` are worker.py's own lines.
- In chats without tools the system prompt carries the page's snapshot; the carry-on message is stored as role user
  with `auto: true` and later goes to the brain unlabelled.
- An agent that may change things calls `remember` and `forget_memory` over `/mcp` with no gate and no button, on its
  own lines only (it never replaces or forgets the owner's, R45). After reading outside text a line still needs no
  button when 60% of its words are the owner's.
