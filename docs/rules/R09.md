# R9

## Rule

**R9.** The pause fails closed and trips itself: 12 started changes an hour, or three failed operations in a row.
A `run` or `write_file` change that ran, or a long one started, is one of the 12 (`hourCounted`, S-11; a look, a
button or the box is none); the owner’s own `/undo` counts toward neither (R34). The
failure count is for agents: the owner’s own failed work never counts toward it (the page, `POST /actions` via `api`,
and what Sparkie starts in the owner’s own chat on the page or Telegram, carry-on turns included: via `sparkie` with
no agent, the job marked `ownersOwn` by `runAction`; one that fails before the mark is counted). The hourly count is
unchanged: it still counts the owner’s chat and Telegram, not `api`. Steps of a saved workflow (via `workflow`) count
for neither, so one counted `run_workflow` can start 12 steps. Removing an agent, or making it look-only, cancels
nothing already running: its operations, the rest of a saved workflow it started and an undo it asked for keep running
and post their results, as after `/stop` (R34); the owner cancels one in Activity. A reply of Sparkie’s to that agent
still under way changes nothing more: `runAction` reads the key as it is now (`ctx.agentId`) before each change, and
refuses with 403.

## Why

A confused loop must stop. `save_file`, like memory and saved workflows, starts no operation and is not in the hourly
count; the worker’s 64 MiB and 1,000-entry limit per shared folder bounds it.
