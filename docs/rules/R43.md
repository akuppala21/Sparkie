# R43

## Rule

**R43.** Learning (2026-11-14, B1: the journal and `recall`): everything said, called, run and seen goes in the journal
through its one writer, `journal`, masked before anything is written. Its fields pass `maskDeep`; its long text passes
`maskSecrets` piece by piece with an overlap (`jMasker`), so a key across two pieces is still hidden. It lives outside
the state folder (`JOURNAL_DIR`, `~/.local/share/spark-console/journal` on Spark 2: folder 0700, files 0600), so the
daily copy and install snapshots never take it; it is append-only and is never copied off Spark 2, rewritten or
deleted. `journal` never throws: a look, a result or an event that can't be written is lost, never an error. A change
that is written down first (`journalFirstFor`) runs only after its start line is written and synced to disk; when it
can't be, the change is refused (“nothing was changed”, `JOURNAL_REFUSED`) and nothing runs. Its end is a second line
with the same id; a start line written but not synced gets its end (“refused”) at once, so it is never reported as cut
off. Stop, pause, cancel and put-back never wait on the journal. At start-up, only in the local port's
listen callback, a start line with no end is marked cut off once (`journalAfterRestart`): one notice in the chat that
asked and one needs-you line for a day; it is never run again. Journal text reaches the brain only through `recall`,
labelled as data and counted as outside text (not in `INSIDE_READS`), so `remember` needs a button after it (R26).
Who reads what: `recall` is the owner's (members never); words said in a chat and the text of a chat's tool results
come back only on the owner's own call (`jOwnCall`: `POST /actions`, or Sparkie in the owner's own chat, on the page or
Telegram, the test `sparkie_setup` uses for access), which reads everything, every call's arguments and error too.
An agent's key, `ask_sparkie` and a chat an agent started (`jOpen`) get no `said` record, a `tool` record without its
arguments or text, and a call made by someone else as who, what, when and whether it worked: never its arguments or
its error, which carry the owner's words (a line to remember, a file's name and text, an app's settings), and those
words never match their search. Their own calls (the same agent key, directly or through `ask_sparkie`) they see
whole. Operations, attempts and events stay readable: they carry names and programs' output, as `operation_log` and
`fleet_events` already give agents. A `cmd` record (what `run` printed on a Spark, kept whole, without escape codes)
is seen whole, its text too, only by a call that may run there now (`mayRun`: the owner, or an agent whose key may
change things). An operation's end line also says how much electricity its Sparks drew at the wall
while it ran (D9 as cut: one number): `wh`, in watt-hours, summed over the Sparks on the job (`node`, `nodes`) from
`createdAt` to `finishedAt`. It comes from the wall counter the status loop already keeps (`sampleEnergy`), read as
the operation begins (`opEnergyStart`, in `newJob`) and as it ends (`opWh`, in `journalOp`), each end moved to the
operation's own moment at the watts read last; no timer and no plug read of its own. When the readings can't cover
its time on every one of its Sparks there is no number, and `noWh` says why: no plug, a plug not answering or giving no
watts (R41), its newest reading older than the operation, none counted while it ran (one count every 30 s), or
readings that stopped part-way. `recall` shows both, to agents too: `fleet_status` already gives them the wall totals.
Nothing reads the number to decide anything yet. Names and an
event's text are masked before they are cut. A record's long text is kept whole up to 16 MB; past that reading stops
and the record says so (`cut`). Today: the
command runner's changes are not built (`run` only looks, R42, and writes its one `cmd` record when it ends;
`write_file` is not built), and the start line covers `save_file` and `keep_running` with an image only, and what a cut-off change wrote can't be put back yet (T123's undo); the other
changes get one record after they run, beside `audit`. An operation's
text is the log it keeps (its last 300 lines) and its error, not every line of its output. A start's retried attempts
are recorded from a hook in `note` that reads `startWithFixes`'s own lines, because a call inside `startWithFixes`
would change the start workflows' versions (R18). A stop of a model across two Sparks names one Spark on its job, so
its `wh` is that Spark's; a start a power-on hands over to (`powerThen`) is an operation of its own inside the
power-on's time, so a sum of both counts that stretch twice. Lessons are R48's. Cards, the learn pass and its `pass` records (B 2.3
to 2.7) are not built; when they are, this rule takes B's sections 2.5 and 2.6 too. That a look syncs nothing is read in the
code, not tested. A short write counts as written (the count `writeSync` gives back isn't checked). `recall` with an id
that isn't there reads the whole journal with no pause. A `said` record doesn't say who spoke (the owner, a member or
an agent). A key longer than 16,384 characters that falls across a cut can show its tail. Nothing can blank a value
in the journal yet (5.13's “hide this value everywhere”).

## Why

What happened is still known after a restart, and Sparkie and the owner can look it up; a change never runs with no
record of it on disk (the one page's P-2).
