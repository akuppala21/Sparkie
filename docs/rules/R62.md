# R62

## Rule

**R62.** The box (design A 2.4; steps A2 and A4): `run {on: "box"}` and `write_file {on: "box"}` act in the caller's
box, a throw-away container on a compute Spark that reaches nothing of the Spark but its own folder. One a chat
(outside a chat, one a caller: the owner's API, each agent key), named `spark-console-box-<12 hex>` from that chat or
caller, opened on first use.

- **Where**: a compute Spark that is on (`boxPlaces`), the caller's last one first; never Spark 2 or a Spark holding
  the brain (R1), looked at again just before each open and each use of a box already open (`boxBarred`: one whose
  Spark holds the brain now is removed, and another opens elsewhere). It wakes nothing: with none on, it says so.
- **Who, and when**: whoever may look (`whoMayLook`): the owner, an agent whose key may also change things, never a
  saved workflow's step. Opening one is a change: Sparkie's and an agent's call are refused while changes are paused,
  and Sparkie's meets the rail (R52): unchecked, it is one button, and the owner's press opens it. The owner's own call
  meets neither.
- **The one line** (`workBoxCommand`), every word of it code's; from the caller comes only which chat it is (hashed
  into the name): `docker run --detach --rm --pull never --name <name> --label spark-console.box=<name> --user <the
  owner's ids> --runtime runc --network none --ipc none --cap-drop ALL --security-opt no-new-privileges --read-only
  --memory 4g --memory-swap 4g --pids-limit 256 --cpus 4 --ulimit fsize=<1 GiB> --mount <its folder> at /work --workdir
  /work --env HOME=/work --env TMPDIR=/work --env NVIDIA_VISIBLE_DEVICES=void --entrypoint sleep <image> 7200`. Plain
  runc, so no NVIDIA runtime hook runs even where it is Docker's default, and `void` keeps one off if it did. The image
  is `config.json` `work.images.python`, pinned by digest (none pinned: nothing opens), fetched once apart from the
  call. Its folder, `~/.local/share/spark-console/work/<name>` (0700), is made empty at each open; at the next open on
  that Spark, once Docker's daemon has answered, the folders of boxes that are gone go too. When the daemon doesn't
  answer, nothing is swept and the answer says Docker isn't answering.
- **The check** (`BOX_CHECK`) runs inside the new box before anything else does, and must find every wall: not root
  (also from a child), no capabilities, no new privileges, nothing writable outside `/work`, `/work` writable, nothing
  mounted but its own folder at `/work` (and the three files Docker writes for every container), the owner's home not
  there, no socket at all (Docker's, containerd's, Tailscale's), no key handed in, no network device but loopback and
  no connection to the console or to Tailscale's resolver, nothing in `/dev` beyond Docker's own set and no NVIDIA
  library mounted. Each probe names the tools it needs; one missing is "can't tell", a failure. Its lines begin with a
  random id; a wall missing, unknown, open or not told removes the box, and the answer names it.
- **In it** (A4): a command runs by `docker exec` into the container kept at its open (its id), in `/work`, as the
  box's user, with nothing added, 30 seconds; past them the box goes, with its folder. Its output is kept to 1 MB and
  cut for the brain as a look's; the script's last line is `<id> end <code>` with a fresh id the command is never
  given, read only at the very end, so nothing it prints passes for it. A box removed while it runs (`/stop`) is said.
  `write_file` writes a path under `/work` from inside the box: a link at the name, or a link on the way that leaves
  `/work`, is refused; the text's rule is `write_file`'s (`writeKey`), the old text is read from inside, the button
  shows exactly what is written (`writeShown`), and code's program (`writeProgram`) writes only while the file is as
  read; a press after it changed is void and asked again.
- **It ends** at its time (its `sleep` ends and `--rm` removes it), at `/stop` in its chat, at `run {on: "box",
  command: "/stop"}` from whoever opened it, at `"/stop <its name>"` from the owner's own call, and when its check
  fails. The console keeps a box on record until its removal is seen, and says which happened. The watcher, and so
  `workloads`, leaves out only a container this record knows on that Spark whose `spark-console.box` label is its own
  name; typed starts (`keep_running`, a saved workflow's step, a compare) refuse a name beginning `spark-console-box-`.
- **Records** (R43): each open, use, ask, refusal and removal the console makes is a journal record (`where: box`); a
  box that ends at its own time is not, since nothing in the console sees it end.

## Why

One place where trying needs no yes and code from a web page may run, because it can reach nothing (design A 2.2 and
2.4; the one page, section 4, milestone 5); design C fills one with Spark Console's source (C8).

## Today

A command gets 30 seconds, never `minutes`. What one box command fetched is not tracked as `written` for the next. Which box
is where lives in memory, so after a console restart a box left open ends at its own time,
`/stop` no longer finds it, and the watcher lists it until then. The check proves the walls on the day it runs; a real
Spark's first check is the owner's to see. The stand-in docker answers the check from the run's own flags.
