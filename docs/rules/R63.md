# R63

## Rule

**R63.** What bounds a plain change. The sorter will never be provably complete, so the run wall (R42) bounds what a
command it wrongly lets through can cost: never the Spark, the fleet, a model or the owner's way in. Each setting is
the root helper's own text; the proof tries the walls' settings (attempts 11, 14, 19 and 21 to 31; not the left-out
groups, nor what `--fleet` and `--gpu` lift). `--open` (an asked change with the owner's groups) drops the network,
device and home bounds and the disk floor; `--home` (an asked change) drops the read-only top of the home and the
start floor, and with them the bound on what the owner's next terminal runs (below).

- **The lists** (both walls): hidden, in every home, `.ssh` (its `authorized_keys`, `known_hosts`, `config` and `*.pub`
  put back read-only, plain files only), Spark Console's state folder (its plain files put back but the sign-in files
  and their copies, the sockets, the owner's words and a `.tmp` being written), the start files (`.profile`, `.bashrc`, the other bash and zsh ones,
  `.pam_environment`), the service manager's folders (`.config/systemd`, `environment.d`, `autostart`,
  `user-tmpfiles.d`, `.local/share/systemd`), the tools' key folders (`.kaggle`, `.config/rclone`, `.config/gcloud`,
  Ollama's folder (its models put back read-only), `.claude`, `.claude.json`, `.codex`, `.gemini`,
  `.config/github-copilot`, `.config/anthropic`, `.openai`, `.azure`, `.wandb`, `.vault-token`, `.terraform.d`,
  `.config/sops`, `.continue`, `.aider.conf.yml`, `.env`, `.my.cnf`, cargo's credentials, `.gnupg`, `.aws`, `.kube`,
  `.ngc`, `.config/gh`, `.docker`, the Hugging Face tokens, `.netrc`, `.git-credentials`, `.config/git/credentials`, `.npmrc`, `.pypirc`,
  `.pgpass`, pip's settings), the tokens of programs that listen (`.local/share/jupyter`, `.jupyter`, `.ipython`), the
  browsers' profiles (`.mozilla`, Chrome's, Chromium's, Brave's, the snap browsers'), the console's own secrets and
  journal, X's `.Xauthority`, and histories; with `/run`, `/root`, the shadow files and `opasswd`, the host keys,
  `/etc/ssl/private`, the network settings (WireGuard's and wpa_supplicant's too), apt's sign-ins, systemd's
  `credential.secret`, crash dumps (`/var/crash`, systemd's and apport's), Tailscale's, Docker's (also where
  `daemon.json` puts it) and containerd's data, `/var/lib/spark-console`, `/var/backups` and swap files. A hidden name
  that is a link is hidden where it leads, a file or folder in the home holding nothing held; else both walls refuse,
  naming it (one to a device is left).
  Read-only in a change: Spark Console's caches, set-up scripts, page, code and source, the editor's programs, the
  helper and its line (with `--open`, the start files and the service manager's folders instead).
- **The top of the home is read-only** in a plain change: nothing made, removed or renamed directly in `~`; every
  dot name there read-only but the download caches (`.cache`, `.npm`, `.cargo/registry`, `.cargo/git`, `.m2`,
  `.gradle`, and only the cache in Bun's, Yarn's and pnpm's folders, whose installers put a folder of theirs first on
  the PATH: `.bun/install/cache`, `.yarn/berry`, `.local/share/pnpm/store`); `~/bin` read-only; the other plain
  folders there writable, each the real folder whose name can stand in a setting (one with a space in it stays
  read-only) and on no list. Only inside those writable folders are the folders above a held path pinned (R42); the
  shared folder and the jobs' folders are read-only with the rest of `.local`. Bash's own start files (`.bashrc`,
  `.profile`, `.bash_profile`, `.bash_logout`, `.bash_aliases`) and `.pam_environment` must be there and are hidden
  (what else bash reads: a Later line).
- **`--home`** (never with `--open`) makes the top itself, `~/.local`, `~/bin` and `~/.cargo/bin` writable; a dot name
  that is there when it is called, real and plainly named, stays read-only, and the places are pinned again. While it
  runs it is not root, reads no key, reaches no Docker and no other Spark (but with `--fleet`), and cannot change
  `~/.ssh`, a start file, the owner's units or `.config`. But what it leaves in `~/.local/bin`, `~/bin`, `~/.cargo/bin`,
  Python's user folder or a new dot file runs outside every wall at the owner's next terminal on that Spark (or at the
  next `--open` change that runs python); it can write the shared folder and the jobs' folders unless `--protect` names
  them; it can fill the disk down to 5 GB free; and it can shut ssh out (the home's mode) while it runs.
- **The network**: on the loopback only 127.0.0.53, for name look-up, and that address is open whole: the filter
  knows no ports, so a program on this Spark that listens on every address (sshd, an app or a notebook published
  wide) answers there. None in the private, link-local, unique-local, tailnet, multicast or
  broadcast ranges; a global IPv6 address is in none of them. `--fleet` lifts those ranges (never the loopback), for an asked change.
- **No devices** (`PrivateDevices`); `--gpu` keeps them, for an asked change. No terminal of the Spark's (`/dev/pts`
  empty), with `--gpu` too, nor in a look. Its own `/dev/shm` (mode 1777) and IPC. The control groups read-only
  (`ProtectControlGroups`, as in a look): no freezing or ending the owner's services.
- **Memory, processors, disk**: its cap (`--memory`, 1G to 8G; 8G without), no swap, a weight of 20 for the processors
  and the disk's traffic. A plain change does not start while the home's disk has less than 50 GB free, and is ended,
  saying so, when the free space falls under that while it runs (other disks are not watched); the refusal tells the
  owner to ask. One the owner pressed (`--asked`, which the console sets only on a pressed change) may start under it,
  and so may `--home`: each is ended when the free space falls under 5 GB (one started under 5 GB: 100 MB under its
  start, so a delete runs). `--asked` gives nothing else:
  the helper cannot know who pressed, and a caller who says it falsely gains only the right to start under the floor,
  watched.
- **The home itself**: its mode and owner are noted before a change and put back right after it, as root, and access
  rules it did not have before taken away; the answer says so (sshd refuses a key in a home others can write).
- **`--protect`**: up to eight folders, a whole path or `~/` and a folder in the owner's home (from `/etc/passwd`),
  each there and real, no link at any part. **Groups**: `adm` and `systemd-journal` are left out with the docker, lxd,
  libvirt, disk and sudo groups.

## Why

The wall analyst (2026-11-15): without these a wrongly sorted plain change could lock
the owner out (`chmod 777 ~`), read a token from a start file or a tool's folder, reach the home network, the other
Sparks and their models, use the GPU, leave a program the owner's next terminal runs, fill the disk, keep files and
memory in `/dev/shm`. What is left: a project's own files on that one Spark, read or changed (and what a change
changed stays changed), the internet, and what listens on every address of that Spark; with `--home`, also what the
owner's next terminal there runs.
