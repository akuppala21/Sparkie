# R20

## Rule

**R20.** New state files: `writePrivate` to write, `readKept` to read-then-rewrite, no `await` between; one process.
The safety exceptions are `self-test.json` (R22: `selfTestRecord` reads the primary only, with no stale-copy stop authority) and `saved-runs.json` (R57): `savedRunsNow` reads only the primary and validates the whole record.
Missing means empty; a bad read or shape throws, preserves the file and never consults `.prev`. Its writers skip the
save, and `openProblems` keeps an owner line until the primary reads correctly. See `docs/saved-run-recovery.md`.
The journal is not a state file: lines appended outside the state folder, never rewritten (R43).
`writePrivate` syncs its temporary file to disk before the rename (after a power cut the file is the old one or the new
one, never an empty one), and a file `readKept` has read keeps one earlier copy, `<file>.prev` (0600, made just before
each save; sign-in files never get one). When that file is not JSON it is set aside as `<file>.unreadable-<time>`; the
`.prev` copy takes its place if it reads, and the notice says which happened (“the copy from before the last save is in
use, so the last change may be missing”, or “it starts empty now”). A missing file never falls back. A function that
saves a file back lets `readKept`’s error through and skips the save; only lookups may take a failed read as empty
(`desired()`, `validations()`; the writers use `desired(true)` and `readKept` itself, `recordWorkflowRun` too). Today:
only the files marked “Read kept” in `docs/registry.md` use `readKept` (`self-test.json` is removed with `unlinkSync`
when a run ends); the self-test note uses `selfTestRecord` (primary only); the rest use `readJson` (unreadable reads as empty), except `access.json`: `ownAccess` falls back to
`access.json.good`, and the service never writes `access.json` itself (the copy is only ever written from a good
`access.json`, never read then rewritten); `main.json`, `chats.json`, `energy.json` and the secrets file have their own
writers, which do not sync and keep no `.prev`; `saveChats` never throws (a full disk or an unwritable folder must not
end a turn, a button press or a Telegram message): the chats stay in memory and the next save retries. A read error on
`memory.json` never ends a turn (`memoryPrompt`), but `remember` and `forget_memory` still refuse. An unreadable
`main.json` would be rewritten without its presets.

## Why

No locks; a failed read is never "empty"; a power cut or a damaged file must not quietly cost what Sparkie learned.
