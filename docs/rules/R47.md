# R47

## Rule

**R47.** An eval result belongs to what it ran against (the one page's P-4). `test/eval.mjs` writes one record a run:
what the brain reads in the build that answered (`reads`, computed as the lock computes `brainReads`, R29, on a stand-in
console of that tree with its stand-in brain), the case set's version (`set`: the sha256 of the case file as read, so an
edited case is a new set), the cap, the brain (`standIn`, and the setup's key, model, engine, image and flags as that
console shows them), the build, when, and for each case and run: passed, rounds, seconds, what it called, the changes
it made, whether it asked. It keeps nothing the brain said beyond what a grade needs, and is masked before it is
written. The cases run only on a stand-in console (this tree's, or another checkout's with `--tree`), never through the
installed console's chat: a case that asks for a change would change the real Sparks. The real brain is reached only
through a relay to its port or to the one model address. `POST /main/eval`, the owner's own call (as `/main/check`:
no passkey), keeps a record in the profile of the brain serving now, under `evals["<reads>:<set>"]`, the newest five
each, for the six newest of those; `saveBrainProfile` stays the file's one writer. It refuses a malformed record (400),
one run at another cap, one from another brain (the stand-in's on a real console, a real brain's on a stand-in one, or
another setup key) and one for a brain with no profile yet (409), and stores nothing then. The score kept is counted by
the console from the runs. `sparkie_setup`'s `brainCheck` shows `inUse` (the setup serving now, with its key) and
`eval`: on record for what this build's brain reads (the lock's `brainReads`) on today's case set, with its score and
date, or which is missing (none at all, another version of what the brain reads, another case set, or not known).
Nothing acts on it yet (design E, build step 5). Today: today's case set is `test/eval/cases.json` in the source copy
every install keeps (`~/spark-console-src`), not in the lock, so after going back a build it is the newer build's set;
a record from a run on a stand-in console names the setup as the runner's `service/config.json` has it, so when Spark
2's own `main.json` differs (another image digest, say) the store is refused.

## Why

A checked grade must belong to what the brain reads now and to today's cases, or an old pass would vouch for a new
prompt.
