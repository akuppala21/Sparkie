# R47

## Rule

**R47.** An eval result belongs to what it ran against (the one page's P-4). `test/eval.mjs` writes one record a run:
what the brain reads in the build that answered (`reads`, computed as the lock computes `brainReads`, R29, on a stand-in
console of that tree with its stand-in brain), the case set's version (`set`: the sha256 of the case file as read, so an
edited case is a new set), the cap, the brain (`standIn`, and the setup's key, model, engine, image and flags as that
console shows them), the build, when, and for each case and run: passed, rounds, seconds, what it called, the changes
it made, whether it asked. It keeps nothing the brain said beyond what a grade needs, and is masked before it is
written. The cases run only on a stand-in console (this tree's, or another checkout's with `--tree`), never through the
installed console's chat: a case that asks for a change would change the real Sparks. The real brain is reached only
through a relay to its port or to the one model address; the serving console's `GET /v1/models` names the brain (its
setup and key), and the run is refused when it would ask as another setup. `POST /main/eval`, the owner's own call,
keeps a record in the profile of the brain serving now, under `evals["<reads>:<set>"]` (with `setFile` and
`memorySwitches`, how it was kept and a seal: R52), five full main-set runs and five others each, for the six newest of
those; one that could unlock changes waits for the owner's yes once a passkey is set up (R52); `saveBrainProfile` stays the file's one writer. It
refuses a malformed record (400), one run at another cap, one from another brain (the stand-in's on a real console, a
real brain's on a stand-in one, or another setup key) and one for a brain with no profile yet (409), and stores nothing
then. The score kept is counted by
the console from the runs. `sparkie_setup`'s `brainCheck` shows `inUse` (the setup serving now, with its key) and
`eval`: on record for what this build's brain reads (the lock's `brainReads`) on today's case set, with its score and
date and set file, or which is missing (none at all, another version of what the brain reads, another case set, memory
additions off, or not known). The rail acts on it (R52). Today's case set is the lock's `evalSet`, else
`test/eval/cases.json` in the source copy every install keeps (`~/spark-console-src`). Today: a record from a run on a
stand-in console names the setup as the runner's `service/config.json` has it, so when Spark 2's own `main.json`
differs (another image digest, say) the runner refuses to run (R52). Each case's fresh stand-in console checks the
brain and keeps a passing record of its own as it starts (test/start-mock.mjs), so its rail lets clear changes run at
once as on a checked brain: each case sends six toy-tool requests to the real brain (not counted as rounds).
The held-out set (`test/eval/memory-held-out.json`) is never a file on Spark 2: the installer leaves it out of the source
it sends (`~/spark-console-src`), and `pull.sh` out of what it unpacks, so the brain can't read it once commands run
there; it is there only as one of git's packed objects in the copy of the repository, which the wall hides. A box filled
from that copy (R62, R69) is filled without it, and a read back never takes it (`FILL_HELD_OUT`, `21-box-fill.mjs`).
Nothing else the console runs names it; it is run from the machine that holds the repository.

## Why

A checked grade must belong to what the brain reads now and to today's cases, or an old pass would vouch for a new
prompt.
