# R49

## Rule

**R49.** The ways in, watched ahead (ledger 5b, addition 6; contract 4.7 and 9.17): Spark Console looks, and only
looks, at what can close a way in with no warning, and puts each on the needs-you list (`openProblems`) with what will
stop working, when, and the one thing to do. A Tailscale key that expires within 14 days, or has expired: the hub's
(`Self` in `tailscale status --json`) and each compute Spark's (the peer holding its tailnet address), read from the
hub's own answer by `refreshBlocked`, so no command runs on another Spark. Linger off for the console's own user on the
hub (`loginctl show-user <uid> -p Linger --value`, through `spawnOn`, as the installer reads it). Funnel off for the
main address while `funnel-seen.json` says it was on: `noteFunnel` writes that record the first time the route check
(`checkRoute`) sees Funnel on, and only `deploy/open-to-internet.sh --undo` (closed on purpose) removes it. An answer
that can't be read, or none for three looks, is a "couldn't check" line, never silence. No timer of its own: the
Tailscale look rides on `refreshBlocked`, linger and Funnel on `checkRoute` (at start, then every 60 s; also on the
stand-in fleet, where `SPARK_CONSOLE_ROUTE_MS` shortens both). Only reads are run (`tailscale status --json`,
`tailscale serve status --json`, `loginctl show-user`), each look one at a time and 10 s at most for linger, and a
look that never answers blocks nothing. A line names the fix for the owner: Tailscale's admin page, a command written
out, or the project's own script, never a bare Tailscale command that drops a route. Its key is its kind and Spark,
never a date, so the needs-me line tells it once. A machine name in a line is Tailscale's, kept only when it is a plain
name (letters, digits, dashes). Disk space is the status loop's line: the state folder and the journal sit under the
home folder whose free space `worker.py` reports.

## Why

A lapsed Tailscale key takes every way in but Telegram with it, and before this nothing warned; linger and Funnel go
quiet the same way.

## Today

- The GitHub token for pull installs (contract 4.7) isn't watched: `pull.sh` keeps no expiry date. A needs-you line
  comes only once a `check_update` finds GitHub refusing it.
- The lines come last but for the update check's, so on a day with more than 7 others they are in the count.
