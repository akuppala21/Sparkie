# R23

## Rule

**R23.** Event types and `knowledge.workloads` fields keep their meaning; events stay rare. `spark-offline` carries
`last` (the last readings, only if under 3 minutes old) and `spark-online` carries `upSeconds`; no new event type was
added for them. Docker not answering on a Spark that is on is one `notice` (carrying `spark`) per outage, held by
`knowledge.sparks[id].dockerDownAt` until Docker answers again; it never writes `removed`. A row on a Spark that is
off or not answering is never changed for that; only the `workloads` action and fleet notes show it as last seen, not
running (`sparkOff`, `19-watcher.mjs`). The daily copy posts one `notice`, at most one a day (`noticedOn` in
`backup.json`), when no good copy is from today or yesterday. A job (`keep_running` with `once`, A13) that ends is one
`notice` (carrying `spark` and `container`), once: its row keeps `endTold` until it runs again, and the first look at
a Spark that Docker answered only marks what had ended (`knowledge.sparks[id].sawContainers`, set by that look even
when it finds nothing, so the first job on a Spark first seen empty is told). The line is built from its name, how it
ended and when, never its log.

## Why

Healing reads a 500-event window; the passkey gate reads `byConsole`; the intent gate picks a stop or restart target
from the watcher’s view.
