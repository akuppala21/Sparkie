# R64

## Rule

**R64.** What a command run at once must look like (R55 is the sorter). The sorter reads the tokenizer's words once
(`sortShape`): a change that is not of this plain shape is asked (risky), and a look only when it holds a `{…}`. The
lock-out, risky and not-done answers of R55 stand, so the shape only makes answers stricter.

- No `{…}` that bash would expand.
- No `$` but `$(nproc)`, `$(nproc --all)` and `$(getconf _NPROCESSORS_ONLN)`.
- A `*`, `?` or `[` only in a word the sorter places as a file: never the program, a file it runs, an option's value
  or cd's folder.
- No group, subshell, loop, `if` or function; `&&`, `||`, `;`, `|`, and a `&` only last.
- At most one cd: the first word, `cd <folder> &&` (a plain folder, no option).
- Redirections: only `>`, `>>`, `<`, `&>`, `&>>` to a path (its word kept to these rules), `>&1`, `>&2`.
- Nothing under `/dev` or `/proc` but `/dev/null`.
- Only safe names set, whichever way: before a program, `env`, `export` and its kin, `read`, `unset` (R55's safe list,
  and a few Hugging Face and logging switches).
- No here-text (`<<`, `<<<`).

A redirection's word, and a word after `--` for a program whose options the sorter reads, is a name whatever its first
sign (`cat > -x.sh` writes `./-x.sh`): the word itself is placed, beside the sorter's other readings of it.

Four allowances, from the everyday commands: a `$` in a word of `echo`; here-text into `cat` or `tee`; a plain
`cd <folder>` as the last command; the `/proc` status files (`meminfo`, `cpuinfo`, `loadavg` and their kin).

What a command uses beside the places it changes (`sortUses`) is four fields of the result for the ladder (A7c), never
a class, so no answer and no place listed changes with them:

- **`reads`**: the places of `placed` a known program only reads (a copy's source for `cp` and `install`, an rsync or
  scp source, what tar or zip packs, the archive tar or unzip unpacks, a name hf downloads by). Still placed, for the
  copy first. None when the command writes one of them, above or under one, or by a pattern that may match either way;
  none when it runs code the sorter does not read; none for `cp -l`/`-s`, `ln`, `mv`, `zip -m`, `tar --remove-files`,
  `rsync --remove-source-files`; none unless it is a look or a plain change.
- **`installs`**: where an install puts programs that the plain wall keeps read-only: `~/.local` (pip outside a Python
  environment or with `--user`, pipx, `uv tool`), `~/.cargo/bin` (`cargo install`), `~/bin`, or `npm -g`; and a write
  it places under one of the first three.
- **`gpu`**: `true` when it plainly uses the GPU (an NVIDIA tool, a GPU picked by `CUDA_VISIBLE_DEVICES` or
  `NVIDIA_VISIBLE_DEVICES`, a `/dev/nvidia…` name, `--gpus`); not there when that can't be told (`python3 train.py`).
- **`reach`**: which of `fleet` (another Spark: a name or address the console knows), `home` (a private, link-local or
  tailnet address, a one-word or local name, this Spark's own ports) and `internet` its words reach: an address or a
  host, where a proxy or `--resolve` points, an installer's registry.

Beside them, **`unshown`**: the sorter's own words for code the command runs that isn't all on the button (a file of
code named as a word, any interpreter's one-liner, here-text, input or module, awk or sed that start or write, a
wrapper's or git's option it can't read, a build, a project's or a package's scripts, a start file a setting names, an
image; as root, git in a repository; a launcher's script; code handed to a program it doesn't know; a doubt inside a
program that runs code; a part it couldn't read), else null. A root command is refused on it (R70). As the owner, only
code fed from input (`bash < f`, `cat f | sh`) or a start-file setting (`BASH_ENV`, `LD_PRELOAD`) is asked for it: a
script, a build, a module or a project's scripts stays a plain change: the run wall bounds it, and every everyday
build would be asked otherwise. **`unreadable`**: the sorter's words when the shell reader couldn't read the command
or a part of it, else null (R75).

**Where it can't tell, the stricter side** is R75: a doubt in one part is asked and the read goes on, and its lists
(containers, the hub, what the net can't put back, the lock-out class, work started later, the brain, keys, launchers)
are there.

## Why

A spelling the tables never met falls outside the shape and is asked, so safety no longer rests on the tables being
complete (the sixth review of A7a, 2026-11-15).

## Today

On, with R55. The sorter is a list-reader: it knows only the programs, options, places and forms its tables hold,
and never guesses. Where it doesn't know (a program, a changing program's option, a form, a place a `$` names), the
answer is never a plain change: it is asked (risky), saying why, and the rest is still read (R75). A look stays a look
only for a program its tables hold as a reader, inside the look's wall. As root, a doubt about code the command runs,
or a command it can't read, is refused (R70). The allowances come from one list of 230 everyday commands written by a
person; the brain may write `$` and loops more often, so count real turns before changing them.
`pip install huggingface_hub[cli]` is asked (bash reads the `[` as a pattern); quoted, it is a change. The fields'
gaps: `docs/history/later-2026-11-15.md`.
