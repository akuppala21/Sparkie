# R64

## Rule

**R64.** What a command run at once must look like (R55 is the sorter). The sorter reads the tokenizer's words once
(`sortShape`): a change that is not of this plain shape is asked (risky), and a look only when it holds a `{…}`. The
lock-out, risky and not-done answers of R55 stand, so the shape only makes answers stricter.

- No `{…}` that bash would expand.
- No `$` but `$(nproc)`, `$(nproc --all)` and `$(getconf _NPROCESSORS_ONLN)`.
- A `*`, `?` or `[` only in a word the sorter places as a file: never the program, a file it runs, an option's value
  or cd's folder.
- No group, subshell, loop, `if` or function; `&&`, `||`, `;`, `|`, and a `&` only last.
- At most one cd: the first word, `cd <folder> &&` (a plain folder, no option).
- Redirections: only `>`, `>>`, `<`, `&>`, `&>>` to a path (its word kept to these rules), `>&1`, `>&2`.
- Nothing under `/dev` or `/proc` but `/dev/null`.
- Only safe names set, whichever way: before a program, `env`, `export` and its kin, `read`, `unset` (R55's safe list,
  and a few Hugging Face and logging switches).
- No here-text (`<<`, `<<<`).

A redirection's word, and a word after `--` for a program whose options the sorter reads, is a name whatever its first
sign (`cat > -x.sh` writes `./-x.sh`): the word itself is placed, beside the sorter's other readings of it.

Four allowances, from the everyday commands: a `$` in a word of `echo`; here-text into `cat` or `tee`; a plain
`cd <folder>` as the last command; the `/proc` status files (`meminfo`, `cpuinfo`, `loadavg` and their kin).

What a command uses beside the places it changes (`sortUses`) is four fields of the result for the ladder (A7c), never
a class, so no answer and no place listed changes with them:

- **`reads`**: the places of `placed` a known program only reads (a copy's source for `cp` and `install`, an rsync or
  scp source, what tar or zip packs, the archive tar or unzip unpacks, a name hf downloads by). Still placed, for the
  copy first. None when the command writes one of them, above or under one, or by a pattern that may match either way;
  none when it runs code the sorter does not read; none for `cp -l`/`-s`, `ln`, `mv`, `zip -m`, `tar --remove-files`,
  `rsync --remove-source-files`; none unless it is a look or a plain change.
- **`installs`**: where an install puts programs that the plain wall keeps read-only: `~/.local` (pip outside a Python
  environment or with `--user`, pipx, `uv tool`), `~/.cargo/bin` (`cargo install`), `~/bin`, or `npm -g`; and a write
  it places under one of the first three.
- **`gpu`**: `true` when it plainly uses the GPU (an NVIDIA tool, a GPU picked by `CUDA_VISIBLE_DEVICES` or
  `NVIDIA_VISIBLE_DEVICES`, a `/dev/nvidia…` name, `--gpus`); not there when that can't be told (`python3 train.py`).
- **`reach`**: which of `fleet` (another Spark: a name or address the console knows), `home` (a private, link-local or
  tailnet address, a one-word or local name, this Spark's own ports) and `internet` its words reach: an address or a
  host, where a proxy or `--resolve` points, an installer's registry.

Beside them, **`unshown`**: the sorter's own words for code the command runs that isn't all on the button (a file of
code named as a word, any interpreter's one-liner, here-text, input or module, awk or sed that start or write, a
wrapper's or git's option it can't read, a build, a project's or a package's scripts, a start file a setting names, an
image; as root, git in a repository), else null. A root command is refused on it (R70). As the owner, only
code fed from input (`bash < f`, `cat f | sh`) or a start-file setting (`BASH_ENV`, `LD_PRELOAD`) is asked for it: a
script, a build, a module or a project's scripts stays a plain change: the run wall bounds it, and every everyday
build would be asked otherwise.

**Where it can't tell, the stricter side** (the final reads; R55's classes):

- A container that reaches the host is the lock-out class: every privilege, a capability, a device, a security option,
  another container's mounts, the host's network, processes, IPC, users, host name or control groups (or another
  container's), a mount at or above a way in or of `/`, `/etc`, `/root`, `/home`, `/run`, `/proc`, `/sys`, `/dev` or
  Docker's socket, a word it can't read there, a lock-out program among its words; so are `nsenter`, `chroot`,
  `unshare`, `systemd-nspawn`, `runc`, and `ctr`, `crictl` or `machinectl` starting one.
- A command for the hub from a compute Spark (ssh, scp, rsync, sftp, git, `docker -H`, `DOCKER_HOST`, `tailscale ssh`,
  by any name or address the console knows) is not done: it goes through the hub's own path.
  A host that can't be told there (a `$`, a one-word name, an address of the tailnet or the home network it doesn't
  know, a host option, a Docker context) may be the hub: the dangerous ask (kind `brain`), saying so.
- What the net can't put back (`lasting`, not done) by any spelling: a Tailscale sign-out, a sign-in again (`login`,
  `switch`, `--force-reauth`, `--auth-key`, `--login-server`), its lock, a verb it doesn't know or words it can't read
  (options first, `xargs`, a `$`); a package the ways in depend on removed by any package tool (`apt`, `dpkg -P`,
  `snap remove`, a trailing `-`, `autoremove`); and an inline program naming `tailscale`, `userdel` or a package tool
  beside a way-in package or a removal. An inline program naming a way-in program is the lock-out class.
- Also the lock-out class: a way-in process killed by a name or a pattern that may match it (or one it can't read),
  `killall5`, `fuser -k`, `kill -1`, any `kill` as root; `rfkill`, `networkctl`, `wg`, `wg-quick`, `iwctl`, `dhclient`,
  `brctl`, `bridge`, `ipset`, `conntrack`, `netfilter-persistent`, `iptables-apply` but their read forms; an init script
  (`/etc/init.d/x`, `invoke-rc.d`, `update-rc.d`) as its service; `systemd-user-sessions`; another target or run level
  (lasting: it stops the net's timer); the clock set (`date -s`, `timedatectl`, `hwclock`); `hostnamectl` renaming; a
  way-in program's own file changed or removed (`sshd`, `tailscaled`, `sudo`, `ufw`, a login shell, PAM's modules). A
  way-in program a timer or a schedule runs later (`systemd-run`, `at`, `crontab`, a schedule or a unit written) is
  lasting: it runs after the net has kept or put back.
- Work started later (`later`, R70): any `systemd-run`, `at`, `batch` or `crontab` (but `crontab -l`), a timer started
  or enabled, and a file written where systemd reads units (a unit, a drop-in) or cron reads jobs.
- A protected container (the brain's; `CONFIG.protect`, or `protect` given) stopped, killed, removed, restarted, paused,
  updated, renamed or entered is not done (on the hub, its own rule); a hex word (an id's start), a `$`, a pattern, a compose
  project or the Docker service stopped is the dangerous ask (kind `brain`), saying so.
- A key file copied, moved, archived, linked or sent where it isn't a key's is not done, as showing it is; to a key's
  name or place, or `chmod`, is asked.
- In text a program reads, `.*`, `.+`, `.?` and `\` are a regular expression, not dot files (`s/.*//`); `~/.*` counts.

## Why

A spelling the tables never met falls outside the shape and is asked, so safety no longer rests on the tables being
complete (the sixth review of A7a, 2026-11-15).

## Today

On, with R55. The allowances come from one list of 230 everyday commands written by a person; the brain may write `$`
and loops more often, so count real turns before changing them. `pip install huggingface_hub[cli]` is asked (bash
reads the `[` as a pattern); quoted, it is a change. The fields' gaps: `docs/history/later-2026-11-15.md`.
