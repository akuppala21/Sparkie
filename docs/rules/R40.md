# R40

## Rule

**R40.** The app door (the owner, 2026-11-12: “once you’re signed in, you shouldn’t need a separate password”; every
Spark in one environment): the owner opens an app kept with `keep_running` (R38) on any Spark on the list that isn’t
the brain’s (`brainSparks()`; a Spark added to the list works with no code change) from anywhere. It is port 10000 of
the console’s own name (Funnel’s one free port; 443 is the public Funnel’s), a second listener for apps only:
Tailscale serve hands it to `door.sock` (0600, beside `api.sock`), and only the owner’s
`deploy/open-apps-to-internet.sh` points it there (`--undo` closes it; it refuses when port 10000 serves anything
else, never touches 443 or 8443, never runs a plain `off`; the console only reads `doorOn`). Its own origin:
`sameOrigin` compares the whole origin, port included, no route answers CORS, and `requestGate` refuses any request
whose Origin is the door’s, a read too. The sign-in cookie is sent only under `/console/api`, so opening an app is
`GET /console/api/open/<spark>/<container>` on the door: `viewerFor` as on the main address, the owner only, a browser
(never a terminal’s token, an agent key or a member), only from Spark Console’s page or opened by itself
(`Sec-Fetch-Site` same-site or none; never an app’s own page, which could switch the door and read another app, nor
another site). It forwards only to an entry of `desired.json` marked `app` with its recorded port (never the model
port, nor a port a model server answers on, nor a console model) at its Spark’s tailnet address from the inventory;
nothing from the request but the two names. It gives a door ticket: a random token in `__Host-sc_door` (HttpOnly,
Secure, SameSite=Lax, Path=/, 12 hours), kept in memory as its hash (a restart forgets them: open the app again).
Every request and WebSocket checks again: the Sparks’ addresses refused (R5), then the owner by Tailscale on the
tailnet, or from the internet the ticket’s session still signed in; the app still on the list at that port. One
browser runs one app at a time: the door can’t tell its tabs apart (one cookie), so opening another app while the
first is in use (a request in the last 10 minutes, or a WebSocket open) shows a page saying the other tab stops
working and anything it still saves would go to the new app, whose “Switch anyway” (a one-time word, from the door’s
own page) switches; a switch drops the old ticket and closes its WebSockets, and the old tab’s later requests reach
the new app (not prevented). No service worker: a request with `Service-Worker` is refused, `Service-Worker-Allowed`
is dropped, and the open’s redirect carries `Clear-Site-Data: "cache"` (never cookies or storage). A reply the door
can’t pass on (a status of 099) gets a 502, never an uncaught error. Toward the app: no `sc_*` cookie (whatever
prefix), no Tailscale identity, no client `X-Forwarded-*`, no `scs_` token; Host is the door’s. Back: no Set-Cookie
with an `sc_*` name, no CORS grant, the app’s own absolute redirects kept on the door. Changes (not GET, HEAD or
OPTIONS) and WebSockets only from the door’s own origin. `/console/api` on the door is never passed on. Signing a
device out closes its app WebSockets. Nothing is logged but an `app-opened` audit line. Not done: the editors’ 12-hour
passkey rule (R31), since the owner asked that being signed in be enough; the ticket, a Path=/ cookie, also reaches
any page on this name, port 443’s public app included.

## Why

An app’s page must never act as the owner on the console, and the door must never reach anything but an app the owner
kept.
