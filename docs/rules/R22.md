# R22

## Rule

**R22.** One writer each: `verified.json` in `recordVerified`, `found-setups.json` in `digModel`, `validations.json` in
`recordWorkflowRun`, `updates.json` in `noteUpdate`, the lock in `test/lock.mjs` (`lockFor`), wherever it runs: on one
machine, a compute Spark (`tools/test-on-spark.sh`) or GitHub’s `suite` job. GitHub’s `mark` job writes no lock: it
checks the one the suite wrote and commits it, as it is, on top of the tested commit. `desired.json` has six:
`desiredAfter`, `watchHeld`’s first seed, `markUndone`, `POST /desired/forget`, `keepApp` (an app already running joins
the list, or its port and memory figure follow Docker, R38), `forgetApp` (an app’s stop while its Spark is off, R38).
The ones that read the list first read it strictly (`desired(true)`, or `readKept` itself), so a read error writes
nothing. `backup.json` has one: `backupState`. The journal has one: `journal` (R43). `main.json` has three: `saveMainChoice`, `saveRoutes`, and
`markBrainLeftDown` (only the `leftDown` mark; it reads with `readKept`, so a read error writes nothing). `desiredAfter`
skips a job marked `selfTest`: the self-test’s own model start and stop (marked by the self-test through `stepRun`’s
`started` hook, so no function in a workflow’s `code()` carries the flag) and the drill’s restart (marked in `maybeHeal`
by the drill’s id). That model never joins the list while it is the self-test’s: `watchHeld`’s first seed (60 s after a
start with no `desired.json`) passes over it, and `maybeHeal` marks its restart after a crash outside the drill too. Both
ask `selfTestModels`: a run under way, by its job (made before anything starts), and one a restart cut off, by
`self-test.json`, until `selfTestRecover` has stopped what it started; a note that can’t be read seeds nothing that
minute. The self-test never picks a model whose container is on the list for that Spark, so it never takes an owner’s
entry off. Its web page joins the list while it runs, as any app kept running does, and its stop takes it off.
