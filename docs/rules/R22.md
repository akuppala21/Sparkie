# R22

## Rule

**R22.** One writer each, or the few its part’s header declares: `docs/registry.md` lists every state file’s writers,
found in the code, and `node tools/make.mjs --check` fails on a writer nobody declared. `desired.json` has several;
`main.json` has one, `writeMainFile`, for three callers (`markBrainLeftDown` writes only the `leftDown` mark). The lock
has one, `test/lock.mjs` (`lockFor`), wherever it runs: on one machine, a compute Spark (`tools/test-on-spark.sh`) or
GitHub’s `suite` job. GitHub’s `mark` job writes no lock: it checks the one the suite wrote and commits it, as it is, on
top of the tested commit. The map beside it, `test/affected-map.json`, is written in the same run (`buildMap`), and
only `noteMissed` adds to its `missed` (R29). The writers of `desired.json` that read the list first read it strictly (`desired(true)`, or
`readKept` itself), and `markBrainLeftDown` reads with `readKept`, so a read error writes nothing. `desiredAfter` skips
a job marked `selfTest`: the self-test’s own model start and stop (marked by the self-test through `stepRun`’s `started`
hook, so no function in a workflow’s `code()` carries the flag) and the drill’s restart (marked in `maybeHeal` by the
drill’s id). That model never joins the list while it is the self-test’s: `watchHeld`’s first seed (60 s after a start
with no `desired.json`) passes over it, and `maybeHeal` marks its restart after a crash outside the drill too. Both ask
`selfTestModels`: a run under way, by its job (made before anything starts), and one a restart cut off, by
`self-test.json`, until `selfTestRecover` has stopped what it started; a note that can’t be read seeds nothing that
minute. The self-test never picks a model whose container is on the list for that Spark, so it never takes an owner’s
entry off. Its web page joins the list while it runs, as any app kept running does, and its stop takes it off.
