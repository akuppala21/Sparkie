# R16

## Rule

**R16.** Jobs record `ranHere` and `stoppedHere`, set `consoleStopped` before a purposeful stop, and return
`{outcome:'started', operation}`; failure puts back exactly that; a running copy of the same model that a start
replaces is renamed aside, never removed before the new one answers, on one Spark (`deploy`, F9) and across two
(`clusterDeploy`); `asideBack` starts it again on failure or cancel. Today: a console restart in the middle of a start
leaves that copy stopped under its `-before-` name. Fixes retry 3 times at most.

## Why

Put-back, the desired list, healing and chat read these.
