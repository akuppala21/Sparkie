# R65

## Rule

**R65.** The go-ahead for one task (A9a) and "Always allow" (A9b). On a change's button (`workAsk`) the owner may answer "Run it, and don't ask
again for this task: …". The press runs that command, and for the rest of the request it was asked in (the turns that
carry it on), a command of that kind runs without a button. The kind is built by code from a plain change's answer
from the sorter alone, never from words the brain or a page gave: its tool (the one program it resolved, `program`),
its place (the deepest folder its places are under; where it starts when it places nothing; never the home itself, nor
outside it), and the Spark. A command with no kind gets "this same
command" (the same text, starting in the same folder). One list a chat, in memory, for the request it was given in (its
task's start, else the owner's last message of their own): gone when that request ends (a No, its task ended, the
owner's next request), at `/stop`, at a new pairing and at a restart; a press of that request's button after any of
these runs its command and keeps nothing. A press in the paired Telegram chat may give it. It stands in only for the
request's own rules (rules 2 and 3 of design A 2.5: the words asked for a change and named the Spark; nothing was read
since). Everything else still holds: the sorter, the wall, the pause (R9), the rail (R52: a brain that is not checked
gets a button for every change), the copies and the journal, whose record of the run says gate `go-ahead`. Never ahead,
and so never offered (`aheadWhyNot`): an agent's change; the hub or a Spark holding the brain; root; a command that
reads or sends a key; a script (its hash is for one press); a command that uses what an earlier command of the task
fetched or wrote (`opts.written`); a command any of whose things (an address, a whole path, a package) came from what
Sparkie read or said anywhere in the chat, its reads, answers, notices and agents' messages (R54's "came from" over
`workChatEarlier`, or a search that could not read it all); the dangerous ask's kinds; anything the sorter calls
risky, lock-out, open or not done; a protected folder; a change that runs with `--home` or `--open` after its yes; an
install (the sorter's `installs`); the GPU (`gpu`, or `gpu` asked); a reach beyond the Spark itself (`reach`: another
Spark of the fleet, the home network, the internet). A chat's page reads the go-ahead holding there (`ahead` on
`GET /chats/:id`).
"Always allow" keeps a kind across tasks: one list (`allowed` in `agent-settings.json`, 50 at most, each entry a kind
and an id), added only by the owner's press of "Always allow …", which the page shows for a kind while a passkey is set
up (so the page press needs it), or which the paired Telegram chat shows and confirms with its verified owner press. In the owner's chats it stands in for the naming of
the Spark and for nothing read since; the owner's words must still ask for a change; the never-ahead list is the same,
and the run's record says gate `always:<id>`. `/allowed` (page and Telegram) lists the kinds, numbered; `/allowed off 2`
takes one away, `/allowed off all` every one; each one taken away raises the put-back number and is noted (R23), so a
copy from before it, put back by hand, holds and the kind is taken away again. After a state put-back they wait until
"Keep these", listed with what came back. Only well-formed kinds in the file count.

## Why

Asking is the owner's largest complaint, and a task that runs ten commands of one kind should ask once. The one-task
go-ahead is the narrowest answer to that: one kind, one Spark, one request, and nothing that the risky list, the
dangerous ask or "came from" would ask about.

## Today

- A press can't come while Sparkie is answering in that chat, so the go-ahead covers the turns that carry its request
  on (an operation's result, a reply cut at a budget). The owner's next message is a new request, which ends it.
- It is given only by a button's answer: the owner's words ("do what you need on Spark 3 for this") don't give it.
- `sparkie_setup` doesn't show the "always" list: `/allowed` does.
- A plain name a read showed (a file a look listed, in the kind's folder) runs on the go-ahead: the owner's press for
  the task stands for its reads (contract 8.14), so a line read from outside that names such a file runs under it.
