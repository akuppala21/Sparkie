# R46

## Rule

**R46.** Each round, Sparkie’s brain is offered the core and the groups this request opened, at most `TOOL_CAP` tools
(24: the core and two groups); a brain setup’s `toolCap` may lower it, never raise it (an eval run on the stand-in
fleet sets any cap). Every action has one `group`; the core holds at most 12 actions and a group at most 6. The
owner’s words open groups (`GROUP_WORDS`, in the order the words come), and so does state: an operation of the chat running opens control, the chat’s last operation failing
opens dig, a `search_web` call opens reading. A call to an action that was not offered runs through `runAction` like
any other call (hidden is not forbidden: permission stays in `runAction`, `PAGE_ONLY` and the gates) and opens its
group; so does `guide {tools}`. Both undos (`undo_last_change`, `undo_update`) are in `control`, so a request is
offered both or neither: the gate clears either for any undo word. With a group more than fit, the newest one the
words opened gives way: a third the words open isn't opened, and one that state, a call or `guide` opens closes the
newest group the words opened, so a request keeps the groups it began with. Groups last for the
request and its carry-on turns. A prompt line that names a tool goes only into a round that offers it; the core prompt
stays under 2,500 characters and names only core tools. The agent door hides nothing: `tools/list` is every action in
the key’s scope. The tested mark (`brainReads`, R29) covers every group: each action’s text, inputs and group, the cap,
`GROUP_WORDS`, the lines that follow tools and the brain setup’s sampling and limits.

## Why

Fewer tool texts per turn (owner decision 21), so a local brain chooses better; a wrong guess by the word table costs
one round, never a refusal.

## Today

- The word table is a first cut, tuned on everyday requests (`tools.test.mjs`). What the cap costs on the real brain
  is measured by the eval (`node test/eval.mjs --cap all`, then without `--cap`), not yet run.
- A saved workflow opens `routines` on any word of its name of four letters or more, so with “coding mode” saved,
  “which model is best for coding?” opens `routines` beside `find`.
- On the real server a hidden call whose argument is a number, true/false or a list fails once (the server sends it as
  text) and works the next round: 11 of the 31 hidden tools. The stand-in sends typed arguments, so no test shows it.
- A core-only round names 6 of the 31 hidden tools (in core tools’ descriptions); the rest are reachable only through
  `guide`.
- The mark covers only the first setup in `service/config.json` (the one the stand-in fleet runs).
- Several groups are thinner than design F’s table: their other actions don’t exist yet. `updates` comes back with its
  update actions; until then `undo_update` is in `control`, beside the other undo.
