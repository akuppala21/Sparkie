# R53

## Rule

**R53.** What the console runs as the owner reads nothing from the owner's home. On a Spark it takes its programs from
`FIXED_PATH` (`/usr/local/sbin`, `/usr/local/bin`, `/usr/sbin`, `/usr/bin`, `/sbin`, `/bin`, `/snap/bin`; no home
folder): `spawnOn` sets it before a plain command and before `timeout … bash -s`, and `PREAMBLE` again at the top of
every script, where `python3` is `python3 -I` (no folder of its own, no user site) and `curl` is `curl -q` (no
`~/.curlrc`); the status worker runs as `python3 -I`. On Spark 2 the service's own `PATH` is `FIXED_PATH` from its
start, so `ssh`, `bash`, `timeout` and the local commands Node starts are found there too, and one that is missing
fails that command, never the service. The library and setups scans list only folders, cache entries and snapshots
named with letters, digits, `.`, `_` and `-`. From a model's own files the library keeps the architecture, type, dtype
and `spark.json` title only as 80 characters or fewer of letters, digits, spaces and `._+/()-`, a context length only
as a whole number, and a setting name only shaped like one; the plans show an image only as 200 characters or fewer
of letters, digits and `._/:@-`, and say so in `deploy_plan` and `cluster_plan` when a folder's image or setting names
weren't plain. A flag a refusal quotes is cut to 40 characters. Each status round looks for every program the console calls
(`PATH_PROGRAMS`) on that PATH, and one that is missing is a needs-you line naming it (only names on the list) and
its Spark. `deploy/path-check.sh` is the same look by hand and changes nothing.
The installer's half on Spark 2 and the `restore.sh` and watchdog it writes, `deploy/pull.sh` and
`deploy/update-guard.sh` run Python as `python3 -I` and curl as `curl -q`. The installer asks `deploy/path-check.sh`
on Spark 2 before it changes anything (at `check` and at `install`) and refuses, naming each program missing; the
restore script and the watchdog take their programs from `FIXED_PATH`. The watchdog reads its miss count as text and
counts from 0 unless it is all digits, and writes its three files (`watchdog-misses`, `-silent-since`, `-restarts`)
whole, by a new file renamed over them, never through a link that is there. The stand-in fleet's switch reaches the
restore script, the watchdog, `go-back.sh` and the installer's path look only as an argument (`--stand-in`; the
installer's own put-back tells its restore script by a mark in the snapshot, there only while it runs), never from
their environment.
The installer runs the console on a Node.js of Spark 2's own, 22 or newer with its built-in WebSocket client (the plug
control), found on `FIXED_PATH` less `/snap/bin`; code-server's (`~/.local/opt/code-server-*/lib/node`) or one that is
in the home, or leads there, is refused before anything changes, saying what to install (NodeSource's `nodejs`).

## Why

A change inside the run wall (R42) may write most of the home. The console runs as the owner outside the wall, so a
program, a Python module or a curl setting it found there would be a way out (`~/base64.py`, a `.pth`,
`~/.local/bin/hf` or `ssh`, `~/.curlrc`); a folder whose name holds a line break would add lines of its own to the
library's answer (the Spark's address, its memory); and text in a model's files would reach the brain as the
console's own reading.

## Today

- The installer's half itself, `deploy/pull.sh` and `deploy/update-guard.sh` (its timer's put-back too) still take
  their programs from the PATH they are given (the ssh session's, the user's systemd); only `-I` and `-q` are theirs.
- With `--stand-in` the restore script, the watchdog and `go-back.sh` keep the PATH they are given, and the
  installer's path look reads `~/.mock/off-path-<program>`, as the console's own look does. `pull.sh` passes it on
  from `SPARK_CONSOLE_ALL_LOCAL=1`, as it takes its other test settings; the console reads that switch too.
- Docker's client still reads `~/.docker` (the helper's lists, R42).
- An agent's refusal quotes a `spark.json` image that isn't plain, and flags Spark Console sets itself, whole
  (`agentSafeSetup`, in the start code). A start still tries such an image as named (a lesson keeps it as none).
- `PATH=…; export PATH;` needs a far login shell that is bash, zsh or another POSIX shell.
