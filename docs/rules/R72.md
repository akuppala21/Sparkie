# R72

## Rule

**R72.** What the runner asks for itself, and what the press checks (moved from R61 on 2026-11-15; R61 is `run` with a
change and the runner, R54 the dangerous ask).

- **The press:** The press, by its button's record, runs it sorted again; another wall or hash asks again; a failed
  look stops it.
- **The protect folders:** `~/models`, `~/.cache/huggingface` and the jobs' shared folder, given to the helper
  as `--protect` (`helperProtect`: a link as the folder it leads to; one leading nowhere is asked); one placed or
  started in is asked, and after the yes runs without it.
- **What isn't copied:** What is past a limit, unreadable, not a plain file or under a link is not kept, with why;
  then a command that removes or overwrites (`deletes`) runs nothing, at once or pressed: with a chat to ask in it is
  the dangerous ask's delete (R54), line 3 saying it can't be put back and a line each naming a file and why
  (`workAfter`, `workGoneLines`); the owner's API call is told nothing ran, and why. Which commands overwrite is the
  sorter's `deletes` (R55). Its press (and the press of the sorter's own delete, of files it can't see) runs it
  with no copy of what that ask named (`gone`): the start line's `gone` counts them, the result's `cannotPutBack` says
  undo can't put them back (contract 8.2: asked first, then done); a file it didn't name asks again.

- **A key file named** (`workKeyLines`): a change that names one (`mv .env.example .env`) is asked, never refused as a
  look; its button says a key file is named, and what it prints is neither shown back nor kept (`withheld`).

- **A command on its button** (`workCommandText`, Spark 2's too): one plain line goes on its own `$ ` line; one with a
  line break or a sign that doesn't show goes last, whole, under "The exact command:", so no line of it can pass for
  one of code's.
- **Code it runs unseen** (`workUnshownLines`): where the sorter says what runs is in a file the command doesn't show
  (its `unshown`), either ask says so in one line; it is never by itself a reason to ask.

## Why

A change at once is safe only where what it overwrites or removes was copied first (R61): what the runner can't copy
or keep read-only, and a script that changed after its ask, go back to the owner.
