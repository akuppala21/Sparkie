# R72

## Rule

**R72.** What the runner asks for itself, and what the press checks (moved from R61 on 2026-11-15; R61 is `run` with a
change and the runner, R54 the dangerous ask).

- **The press:** The press, by its button's record, runs it sorted again; another wall or hash asks again; a failed look
  stops it. A dangerous kind (a delete it can't see, the brain's names) runs only from the dangerous ask's own press,
  with its two digits (`workPressCovers`); a plain button's press of one is asked again. It takes the Spark's claim
  before it reads the scripts again, and lets go only in the tick `runChange` takes it back. On a compute Spark each
  pinned script runs from the root helper's own copy: the press passes `--script <sha256>:<path>` for each (up to 8,
  P-5); before the unit starts the helper reads the file as the owner into its held folder, hashes that copy and
  refuses "the script <path> changed" when it differs (the owner is asked again), and the unit gets the copy read-only
  over the path for its whole run, so a write to the script while it runs is never seen. A script it can't copy
  (outside the owner's home, a path with other signs or reached through a link, over 4 MB, past the eighth) is said not
  pinned at the ask, and runs by its path; one it can't read as the owner, or that the wall hides, is refused and
  nothing runs. The unit's own first lines (`runnerPins`) still check each pinned script once more, a second check of
  those same copies (`runnerPinRead`). On the hub the net runs the command with no `--script`: there the script runs
  by its path, read as it runs (R54's Today).
- **The protect folders:** `~/models`, `~/.cache/huggingface` and the jobs' shared folder, given to the helper
  as `--protect` (`helperProtect`: a link as the folder it leads to; one leading nowhere is asked); one placed or
  started in is asked, and after the yes runs without it.
- **What isn't copied:** What is past a limit, unreadable, not a plain file or under a link is not kept, with why; then
  a command that removes or overwrites (`deletes`) runs nothing, at once or pressed: with a chat to ask in it is the
  dangerous ask's delete (R54), line 3 saying it can't be put back and a line each naming a file and why (`workAfter`,
  `workGoneLines`); the owner's API call is told nothing ran, and why. Which commands overwrite is the sorter's
  `deletes` (R55), and which files must be copied its `overwrites` (`runnerOverwritten`: as written, under a folder it
  removes whole, or by a pattern; with none, every file it names). Its press (and the press of the sorter's own delete,
  of files it can't see) runs it with no copy of what that ask named (`gone`): the start line's `gone` counts them, the
  result's `cannotPutBack` says undo can't put them back (contract 8.2: asked first, then done); a file it didn't name
  asks again.
- **A key file named** (`workKeyLines`): a change that names one (`mv .env.example .env`) is asked, never refused as a
  look; its button says a key file is named, and what it prints is neither shown back nor kept (`withheld`).
- **A command on its button** (`workCommandText`, the hub's alike): one plain line goes on its own `$ ` line; one with a
  line break or a sign that doesn't show is said in how many lines it has, each after `│ `, so no line of it can pass
  for one of code's.
- **Code it runs unseen** (`workUnshownLines`): where the sorter says what runs is in a file the command doesn't show
  (its `unshown`), either ask says so in one line; it is never by itself a reason to ask. A program the sorter doesn't
  know (its `unknownProgram`) is said in one line too (`workUnknownLines`).
- **The script on the button** (`workScripts`, `workScriptText`, `workScriptRecord`): the ask's look reads each script
  it pins (eight at most; past the eighth, said not pinned) with its hash, from the same read when the script is under
  256 KB; the plain button (the hub's too) shows its first 40 lines, each after `│ `, and how many more, and the whole
  text as read is one journal record the button names (`recall` reads it); the dangerous ask names that record.
- **An installer from an address** (`workFetchRun`): `curl … | sh`, `wget -O- … | bash`, `bash <(curl …)`,
  `sh -c "$(curl …)"` are answered "download it to a file first, then run that file", and nothing runs: the download
  is one change, the run is asked with the file's text shown and pinned. A pipe into an interpreter given its code
  another way (`-c`, `-m`, a file) is data, not an installer.
- **A script the command writes** (`workWrittenFirst`): download-then-run in one command (`curl -o i.sh … && bash
  i.sh`), a here-document written then run, a clone then its script: one the sorter's `placed`, `overwrites` or `wide`
  holds. Asked, never refused (it runs in the wall on the owner's yes), with one line: what runs may not be there yet,
  so its text can't be shown or pinned, and a key is refused for it (`WORK_WRITTEN_KEY`). It is not read, nor handed
  to `--script` (whose read-only copy would stop the command writing it).
- **A key and unseen code** (`workKeyCode`, R51): a key is refused for a command whose code runs unseen (the sorter's
  `unpinnable`: unseen code no script's hash pins), saying to put it in one script and ask again; and for a script not
  pinned (`RUNKEY_SCRIPT_UNPINNED`: unread, past the eighth, or one the root helper can't copy).

## Why

A change at once is safe only where what it overwrites or removes was copied first (R61): what the runner can't copy
or keep read-only, and a script that changed after its ask, go back to the owner.

## Today

A script is pinned only where the folder it is read from can be told (`workScriptPaths`, from the words as bash splits
them: no cd but one first `cd x &&`, no program told another folder by `-C` and its kin); else it is said not pinned.
The page (`askLines`) and Telegram show a button's text as one block: a command's lines are told apart by `│` alone. A
`write_file` whose old file couldn't be copied first is told nothing ran, not asked (`workAfter`); a command given
`minutes` then fails its operation with that reason (`longStart`, `21-long.mjs`).
A home folder that is itself a link (`/home/owner` leading elsewhere) reads as no link at the ask, so a script there
is pinned; the root helper then refuses its `--script` ("no link in its path"): the owner sees that refusal and
nothing runs.
