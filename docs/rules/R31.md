# R31

## Rule

**R31.** From the internet (security audit, 2026-11-11): a new agent key is refused through Funnel until the owner
turns on “Works from anywhere” (`internet: true`, with the passkey; keys made before have no field and keep working);
the editors open only within 12 hours (`EDITOR_PASSKEY_MS`) of this device using the passkey (signing in or
confirming); code-server’s `/proxy/` and `/absproxy/` are never passed on; `undo_update` runs as asked only for the
owner on their tailnet (page, the `/undo update` word, API, or Sparkie in the owner’s own chat) or from an owner-only
button pressed on the page (`ctx.ownerConfirmed`); anyone else (an agent, directly or through `ask_sparkie`, a
signed-in device, Telegram, a workflow step, or a plain button pressed by any of those) gets that owner-only button,
and `POST /rollback` from a signed-in device needs the passkey; a carry-on turn keeps where its request came from (a
task made from a signed-in device records `away`, and `continueTask` gives that turn’s viewer a session marker, so it
gets the same button); sign-in, code and poll limits are per address only (no shared cap anyone can fill), polling a
real code is never counted; at most 3 waiting codes per address (an IPv6 /64 is one), and at 300 the oldest code of
the address with the most waiting makes room; every socket gets an `error` listener before anything else, and an
uncaught network error (`ECONNRESET`, `EPIPE`) never ends the process; secret masking uses bounded patterns (private
keys are found by searching forward, and one cut off before its END is hidden to the end), the audit masks 200
characters past its 1,000-character cut, and the agent door reads at most 256 KB.

## Why

A stolen cookie or leaked key, a reset connection or a flood must not become the owner, end the console or lock the
owner out.
