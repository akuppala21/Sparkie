# R69

## Rule

**R69.** Sparkie's own code (design C 2.5, step 8): `propose_update {do: start, send, drop}` (in `updates`; its word
kinds `code` and `cancel`) proposes a change to Spark Console's own code as a pull request, all by code. It is refused
inside `runAction` for everyone until the coding trial has a pass on record for the brain in use and the piece is turned
on (`SELF_CHANGE_ON`); then only in the owner's own chat (Sparkie on the owner's own words, or the owner's button there),
never by an agent's key, `ask_sparkie`, an API call or a saved workflow's step, and from Telegram it waits for the page.
`start` fills this chat's box with `main`'s tree from Spark 2's copy of the repository and nothing else, and notes that
commit; it is refused while a proposal is open or the box holds other work. `send` reads the box back entry by entry
as data, never run; builds the proposal's tree itself on the noted commit; rebuilds the generated files with the
installed build's own generator (its `tools/`, never the proposal's, reading the proposal's sources) and refuses a
generated file in the box that isn't what that generator makes; refuses any path under `.github/`; lists the protected
paths (the ones that always run the whole suite, of `tools/` only `build-server.mjs` and `affected.mjs`, and
`AGENTS.md`, `docs/architecture.md`, `docs/contract.md`) and every removed or edited line of an existing test; commits;
pushes `sparkie/<id>`, never by force and never to another ref; and opens the pull request. Sent again, it adds a commit
to the same branch. `drop` closes the pull request and deletes the branch. One proposal at a time, 6 pushes each; it is
known from the copy's refs (`refs/sparkie/<id>`, `refs/sparkie-base/<id>`, `refs/sparkie-chat/<id>`) and from GitHub,
with no state file. The title (3 to 80 characters) and why (10 to 600) are the brain's words: masked, bounded, and
marked as its words wherever shown. `check_update` answers for the open proposal (its pull request, the run on its
head, the failed tests' names, the reviews and whether each is of the head), labelled as outside text. The token is read
from the secrets file only for a push or a call to GitHub: to git only in its environment, to GitHub only in the
`Authorization` header; never in a chat, a journal line, a tool result or a log.

## Why

Sparkie may change its own code only as a proposal the owner can read, built and checked by code, and only once a brain
has shown in the coding trial that it can.
