# R59

## Rule

**R59.** What `recall` and `memory` show (design G 3.4, step 5): a long tool result enters Sparkie's turn as its
digest, cut by code. A result past 12,000 characters (`DIGEST_AT`) is seen as lines (`textLines`: a newline ends a
line, and in a JSON result an escaped one too; a line past 300 characters goes on in the next), and the digest keeps the lines that
name a failure (an error word, an exit code that isn't 0, a known start failure's sign: 20 at most, each with the line
before and after it), then the first 5 and the last 15, then each run of 10 or more of the same line, folded to one;
failures first when room is short, all within a recall answer's size (`memorySizes`, 6,000 characters at most). No
model is called and no file is read for it. It is JSON built by code (`digestOut`): its own words (`digest`, `isData`),
the count of lines and the record are fields of their own, and each kept line is [its number, its text], or [first,
text, last] for a run, so no line of the result can pass for Spark Console's words, a line number or the count. The
result is masked before it is cut, so a key across two lines is hidden whole. The whole result is in the journal the
moment it is read (`journalTool`); the digest names its record, and `recall {id, find}` gives that record's lines that
hold every word of `find`, `recall {id, lines}` a stretch (like `1860-1880`), numbered as in the digest, 200 lines or
8,000 characters at a time with `next` (`recordPart`). The record's text is read whole and masked again whole before
it is cut into lines, so a key across two lines, or one kept after the record was written, stays hidden. Who reads a
record's lines is who reads its text (R43): a chat's tool results the owner's own call only, a command's output a
caller that may run there (`mayRun`); in an agent's chat the digest says only the owner reads the record back. The
tool output a message may read (R50) counts the digest, not the result. `run`'s output keeps its own first-and-last
cut (`forBrain`, R42), because every caller gets it (agents and the API too, never only a turn); its `shown` line names
`recall {id, find}` for the middle. With `digest` in `SPARK_CONSOLE_MEMORY_OFF` (stand-in consoles: the brain eval) a
long result is cut at 12,000 characters, as before.

## Why

A cause in the middle of a long log was cut off before the brain saw it, and a cut could not say where the rest was.

## Today

- There are two cuts: the digest for a turn's long results, and `run`'s own first-and-last cut for every caller.
- A JSON result is seen as its text: a line is part of the JSON, quotes and escapes and all.
- The digest keeps no line for sharing words with the owner's request (design G 3.4's third list).
- `recall {id, find}` reads the record's whole text (16 MB at most) and masks it each time.
