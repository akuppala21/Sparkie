# R59

## Rule

**R59.** What `recall`, `memory` and the questions about a memory line hand to whom (the review of the memory steps,
2026-11-15; R43 says who reads the journal, R45 what memory keeps). The words of a line that is no longer live
(forgotten, replaced, past its day) go only to the owner in Spark Console: `memoryText` reads live lines alone, so a
label, a question, a reply, a `choices` entry or an inline Telegram button about such a line says “that line”, to
Telegram and to an agent alike; `eraseLine` puts the words on its own button only for a caller who may see the
history. That caller (`memoryPastShown`) is never an agent's key, Sparkie answering an agent, a channel, or a chat an
agent started, even when the owner types there: the agent reads the reply. From Telegram the journal reads as R43
says, so neither a forgotten or erased line nor words said on the page come back there through `recall`. What the
memory block of the system prompt, the picks and the lesson cards (B4, kept in memory once made) send the brain goes
through `keptHidden` (`memoryKeysHidden`), so a value given later as a key is hidden there too (R51).

A long tool result enters Sparkie's turn as its digest, cut by code (design G 3.4, step 5). A result past 12,000
characters (`DIGEST_AT`) is seen as lines (`textLines`: a newline ends a line, and in a JSON result an escaped one too;
a line past 300 characters goes on in the next; one pass over the text whatever it holds, so megabytes made to be
slow, a run of backslashes or one line with no space, take well under a second), and the digest keeps the lines that name a failure (an error word, an
exit code that isn't 0, the words exit code, exit status, return code or return status whatever follows them, a
known start failure's sign: 20 at most, each with the line before and after it), then the
first 5 and the last 15, then each run of 10 or more of the same line, folded to one; failures first when room is
short, the kept lines within a recall answer's size (`memorySizes`, 6,000 characters at most; the digest's own words add a
few hundred). No model is called and no file is
read for it. It is JSON built by code (`digestOut`): its own words (`digest`, `isData`), the count of lines and the
record are fields of their own, and each kept line is [its number, its text], or [first, text, last] for a run, so no
line of the result can pass for Spark Console's words, a line number or the count. The result is masked before it is
cut, so a key across two lines is hidden whole. The whole result is in the journal the moment it is read
(`journalTool`); the digest names its record, and `recall {id, find}` gives that record's lines that hold every word of
`find`, `recall {id, lines}` a stretch (like `1860-1880`), numbered as in the digest, 200 lines or 8,000 characters at
a time with `next` (`recordPart`). The record's text is read whole and masked again whole before it is cut into lines,
so a key across two lines, or one kept after the record was written, stays hidden. Who reads a record's lines is who
reads its text (R43): a chat's tool results the owner's own call only (not from Telegram), a command's output a caller
that may run there (`mayRun`), a `said` record as `jSaidHere` says; in an agent's chat or on Telegram the digest says
only the owner reads the record back. The tool output a message may read (R50) counts the digest, not the result.
`run`'s output keeps its own first-and-last cut (`forBrain`, R42), because every caller gets it (agents and the API
too, never only a turn); its `shown` line names `recall {id, find}` for the middle. With `digest` in
`SPARK_CONSOLE_MEMORY_OFF` (stand-in consoles: the brain eval) a long result is cut at 12,000 characters, as before.

## Why

What the owner asked to be rid of, and words said on the page, must not go out to a phone or an agent by another door.

A cause in the middle of a long log was cut off before the brain saw it, and a cut could not say where the rest was.

## Today

- There are two cuts: the digest for a turn's long results, and `run`'s own first-and-last cut for every caller.
- A JSON result is seen as its text: a line is part of the JSON, quotes and escapes and all.
- The digest keeps no line for sharing words with the owner's request (design G 3.4's third list).
- `recall {id, find}` reads the record's whole text (16 MB at most) and masks it each time.
