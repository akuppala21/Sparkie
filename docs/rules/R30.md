# R30

## Rule

**R30.** `/health` answers before every gate: on the socket and the local port with `ok`, `build`, `startedAt`,
`jobsRunning`, `replying`, `telegram`, `internet` (null, not known, until Tailscale's answer names the main address),
`workflows`; through Funnel only `{ok:true}`. Installer, `restore.sh` and watchdog match the exact text `"ok":true`.
Installer lists name shipped files (`UI_FILES`, `SERVICE_FILES`, `RECOVERY_FILES`); `pull.sh` is renamed beside
`go-back.sh` only after its build is kept. `SKIP_ROUTES=1` (`pull.sh` sets it, with `local`) makes an
install call no `tailscale`, `sudo` or `ssh`: the routes and the other Sparks' reach are not checked. An install from
`pull.sh` over a build that answers is judged by that build, not the incoming one (`deploy/update-guard.sh`, beside
`pull.sh`): the real address (`config.json`'s `origin`) must answer `/console/api/health` with the running build first,
or nothing changes; the owner is asked there if work is running; then, before the incoming installer runs, a copy of
what an install changes (the by-hand files, `REBUILD.txt` among them) is made and one timer is armed in the owner's systemd (`spark-console-update-guard.timer`,
30 minutes, enabled so a restart of the hub arms it again), and the incoming installer runs with `tailscale`, `sudo`,
`ssh` and `systemd-run` refused (`SKIP_ROUTES` enforced, not trusted). The new build is kept only when its installer
kept it, it called none of those, and within 10 minutes the real address answers with it, each page path that
served the old page serves the new one, and sign-in answers as far as it can without a passkey (R58). Otherwise the
copy's own put-back runs (or the timer runs it, if `pull.sh` was cut off), under its lock (the timer's may first
stop the install): it stages what differs beside the live folders, checked first, starts the service whatever
happens, and disarms once all is back and the service seen started, else stays armed (R58); a copy counts only while its `guard` file
is there (written last, removed first): a copy cut off half-done is never put back. Through Funnel the build is read
from the page's `version.json` (never an empty one). A silent real address confirms nothing, so it
goes back too. Its one timer lives for one install. When
nothing is installed (a first install), no way back is armed; a build installed but silent on its socket goes on
unguarded only on a yes typed at the terminal (`ASSUME_YES` doesn't answer it). An install made outside an armed
update (another process group or boot) puts that update's build from before back first; while that update's
`pull.sh` still runs, or when its put-back leaves it armed, it is refused. An interrupted install's result names what answers; a stop before the way back is
armed is refused with nothing changed, and one while it is being armed takes this install's own way back (never another
update's). Every install leaves `install-mark`; the watchdog
runs `go-back.sh` once when the console has been silent 15 minutes within a day of it, never while an update's way
back is armed. The installer asks on the socket as owner (`Tailscale-User-Login` = `config.json`'s `ownerLogin`, else `access.json`'s) and reads: `/health`
`startedAt` and `telegram`; `/whoami` `access`; `/main` `configured` and `healthy`; `/mcp` (any answer but silence or a
5xx); `/v1/models` `object`; `GET /chats` (`id`, `title`, `messageCount`, `agent`), `POST /chats` `id`; the chat
stream's `tool` (`ok`) and `done` events. An update stays only if all hold after 40 s in one process; otherwise, on a failed copy or a cut session,
previous files go back (in place and checked if no room beside). If Sparkie's model is not answering before
an update the installer refuses (`SKIP_CHAT_CHECK=1` updates without the chat turn); it also refuses, with nothing
changed, when the hub has no room for the snapshot and the new files. The chat check reuses 'Update check.'
(chats need the passkey). `restore.sh` stages/checks before stopping anything and ends with the unit started.
With `--with-state` it skips/removes `saved-runs.json` and its `.prev`. The watchdog counts `activating` and only restarts. `lastSnapshot` passes over a snapshot without `restore.sh` or marked `same`.
`DEV_LOGIN`, `SERVE_PORT`, `DIG_FIXTURE` (an entry `{hf, card}` in it also stands in for Hugging Face, `versionOf` and
the card read, for that repo, A9), `WEB_FIXTURE`, `HF_FIXTURE` (every Hugging Face look-up, `search_huggingface`
included, answers from a list of `/api/models/<repo>` answers; `'none'`, the default there, answers as Hugging Face does
when unreachable; `test/start-mock.mjs` sets it to `test/mock/hf-fixture.json`), `SELFTEST_PORT` (the self-test’s web
page’s port), `WORKFLOW_LOCK`, `ASSUME_VALIDATED`, `RELEASES`, `TELEGRAM_API`, `SECRETS_FILE`, `TELEGRAM_LIMITS`, `JOURNAL_DIR` (else
the journal sits beside that run's state folder), `JOURNAL_PIECE`, `JOURNAL_MAX_BYTES` and `JOURNAL_NEEDS_BYTES` need
`SPARK_CONSOLE_ALL_LOCAL=1`, as does `pull.sh`'s `SPARK_CONSOLE_REPO_URL`; `SPARK_CONSOLE_WORKER` (the code run on every Spark), `STATE_DIR`, `SOCKET`,
`AGENT_CHANGES_PER_HOUR` and most `*_MS` switches work without it (not `PRESS_MS`, `WIDE_MS`, `ROUTE_MS`,
`DANGER_MS`, `DANGER_LATE_MS`, the heartbeat's). The installer's own switches for tests are
`SPARK_CONSOLE_INSTALL_WAIT_S` and `SPARK_CONSOLE_INSTALL_SETTLE_S` (45 and 40 seconds by default).

## Why

Installer, rollback and watchdog parse it.

## Today

The pull install, left for later by its review (C4a, C4b):
- After `go-back.sh` or `/undo update`, the fixed `pull.sh` and `~/spark-console-src` stay the newer build’s.
- The incoming installer still copies its `go-back.sh` and `RECOVERY.txt` before it installs (from `pull.sh`, the way
  back puts the old ones back when the build isn't kept), and still writes the snapshot `/undo update` uses later.
- The real address is asked from the hub itself, whose own address can't act as a person over the tailnet: sign-in is
  asked on the socket as from the internet instead (R58), through the real address only through
  Funnel; and the page's script isn't run, only its files served (`app.js` naming its build).
- The timer fires 30 min after arm/restart; `pull.sh` checks the real door for 10. Timer recovery: 3 persisted
  tries within 30 min of its first. Silent builds say so (`RECOVERY.txt`).
- The verdict beyond `/health`, the page's files and sign-in as far as it goes without a passkey (the owner on the
  socket, the chat turn) is still the incoming installer's. Through Funnel, a build whose page didn't change is told
  only by its socket.
- `go-back.sh` and `/undo update` while a way back is armed aren't stopped first (the timer then puts back what
  differs). The watchdog's go-back can land in an install from the Mac, and is off while a copy that isn't whole sits there.
- The installed `pull.sh` reads the incoming installer's line `kept: build <id> passed its checks`.
- `watchdog-silent-since` survives a restart and a clock step. Ten installs not kept leave ten snapshots marked `same`.
- The timer stops an install only when its process group's leader is `pull.sh`.
- A tool called by its full path (`/usr/bin/sudo`) gets past the refused commands.
- An install from the Mac and one from `pull.sh` share `~/.cache/spark-console/incoming` with no common lock.
