# Reviews, 2026-11-11

Six independent reviews (Fable 5.2, read-only), one per area: access, architecture, workflows and self-healing, Sparkie
and the agent door, models and recipes, apps. What each concluded, what is done, and what is next, in order.

## Verdicts

| Area | Verdict |
| --- | --- |
| Access | Funnel on :8443 plus passkey is the right way for one owner on a phone. No Cloudflare, no password. Tailscale stays the way back in. |
| Architecture | The shape is right: one dependency-free service, JSON state, typed actions, an installer that rolls back. Weak spots: no keeper outside the console, operations kept only in memory, and healing split over three loops. |
| Workflows and healing | Good parts, wrong wiring. Validation gates switched healing off after installs, and healing ignored the list of what should run. |
| Sparkie | Keep one action list and typed workflows. Fix the gate's English: bare Spark numbers, and more verbs. |
| Models | Sources, vetting, verified runs and known fixes are right. The best setup isn't used everywhere, and GLM's kernel caches were still lost. |
| Apps | Templates in code on Spark 2 is right. For the phone, apps need their own HTTPS address behind the console's sign-in. |

## Done in v3.1 (this batch)

- **Self-healing**
  - A model across two Sparks that loses a part is started again as a pair. If that start is refused, the part that was stopped comes back.
  - When Spark 3 or 4 comes back after being off for more than 90 seconds, what should run there comes back once they have settled. This happens once per power-on, and not again if a Spark went down within 30 minutes of the last time.
  - Sparkie's own model, if running but silent for 10 minutes, is restarted (at most twice in 6 hours).
  - The automatic pause for an agent that looped no longer stops healing; only the owner's own pause does.
  - Heal attempts are kept for 6 hours.
  - A heal no longer writes an undo revision.
- **Validation**
  - Self-healing and the owner's own clear request to Sparkie count as a workflow's validation run, so there's no button and nothing switches off after an install.
  - "Test the changes" no longer fails while a model holds Spark 3 and 4 across both.
- **Jobs**
  - A running operation is never evicted from the last-50 list.
  - The service unit uses `Restart=always`, and the installer says if linger is off.
- **Sparkie's gate**
  - "start gemma on 3", "across 3 and 4" and "3+4" name Sparks.
  - New verbs: switch … to, swap, replace, set up, install, "use …" (as an instruction), and free up / clear spark N.
  - Changes in one reply run one after another, and lookups run together. Only the calls that run are on the record.
- **Phone**
  - The public page's Sign in leads to the :8443 address when it's open to the internet, so it works with Tailscale off.
  - /health says whether the internet route is on.
  - The first passkey can only be set up from the tailnet.
- **Models**
  - CuTe DSL and b12x kernel caches are kept per image.
  - A setups look where a source failed keeps what earlier looks found, and isn't marked fresh.

## Round 2 (same day): standalone, simplicity, agentic, memory, API, brain

The owner: "truly make it standalone and not over-engineered … the APIs and chat are the main forms and I'll only be
using it through those".

| Area | Verdict |
| --- | --- |
| Standalone | Not yet. It runs for weeks alone, but the source, the installer and the test gate live only on the Mac (no git anywhere), and Sparkie can't update, test or undo the console. |
| Simplicity | The core is the right size: actions, runAction, workflows, healing, the door, /v1 and chats. About 35–40% can go: a 5,300-line multi-user page, members and sharing, the short address and workers.dev page, the editor and file browser, and about 40 REST routes that copy actions. |
| Agentic | One message works well; nothing carries on after it. A finished operation posts a fixed notice and Sparkie is never called again. There are no schedules and no benchmark action. |
| Memory | Sparkie knows the fleet and remembers nothing about the owner. Nothing the owner says outlives its chat. |
| API | The MCP door is the strongest part. Gaps: Codex can't use /v1 (no Responses API), agent keys aren't accepted on chats, it pauses for everyone, and there are four error shapes. |

**The brain** (Qwen 3.8 27B on Spark 2): the right model on the right machine. The live setup is `aphex-agent-fast`: 4 at once, thinking on, 262K context, warm start in about 51 s. The review suggests these, for the owner to decide (only the owner changes the brain):
- **A tuned agent preset:**
  - 8 draft tokens instead of 16 (SGLang's Qwen3.8 guide and GB10 recipes);
  - `--max-running-requests 8` with `--max-mamba-cache-size 48`;
  - `--chunked-prefill-size 2048` (8192 pauses everyone about 600 ms per chunk);
  - `--mem-fraction-static 0.7` (apps share Spark 2).
- **Owner first:** `--enable-priority-scheduling`, with priorities chat 100, carrying on 80, ask_sparkie 50, /v1 20, helpers 0. Also cap /v1 replies that set no length.
- **Health:** `--tmpfs /tmp` on the brain container. Docker's own crash restart keeps the stale `/tmp/sglang-rdv`, which can hang the start.
- **Remove:**
  - the YaRN overlay, which hurts short-context quality and also rewrites the draft model's rope;
  - chat routing to other models;
  - the 1-at-a-time `aphex` presets.
- **Measure:** time to first words, rounds and cache hits per answer, and a nightly eval at the lowest priority.
- **Fix next batch:** a reply waiting in SGLang's queue sends nothing, so the chat-timeout "stuck" signal added today could restart a busy brain. It goes; the engine's own watchdog and /v1/models stay.

Also done in this batch, from round 2:
- A closed page or a locked phone no longer cuts Sparkie's turn; it finishes and is saved.
- A saved workflow's steps count as validation runs, so saved workflows no longer break after installs.
- The owner's saved workflows, self-healing and the gateway don't count toward the agents' safety pause.
- Two chat replies timing out count as Sparkie's model being stuck, even while /v1/models still answers. Before restarting it, the engine's rendezvous file is removed.

Done in the next batch:
- **Memory.** `memory.json` with remember, forget_memory and memory, at the end of Sparkie's prompt, with its own intent kind.
- **Carrying on.** Sparkie carries a request to the end, but only requests with a next step, so no extra brain turns for one-step requests.
- **New actions.** `test_changes` and `undo_update` (the undo uses `systemd-run --collect`).
- **Source on Spark 2.** The whole source is kept there, and `host-on-portal.sh local` installs from Spark 2 itself.
- **Watchdog.** A watchdog timer outside the console.

Installed 2026-11-11 (build `c0789b85fa67`), checked live through the API and Sparkie:
- everything above;
- `POST /actions/<name>`;
- `/v1/responses`, `/v1/embeddings` and `/v1/rerank` passed through;
- no model starts from a Spark's own programs;
- the chat-timeout "stuck" signal removed;
- Sparkie's memory seeded with twelve lines of fleet facts and the owner's preferences.

A deeper gap analysis (eight areas, sub-agents, three skeptics) followed; its plan is in `docs/independence-plan.md`.

## Next, in order (both rounds, for an owner who uses only chat and the API)

1. **Standalone core.**
   - Source on Spark 2: a git checkout (`~/spark-console-src`) with its history.
   - Move the installer's remote half into `deploy/install.sh` on Spark 2, and have it wait until idle instead of asking.
   - New actions:
     - `update_console`: runs the gate in the agentbar node image with no network, then install.sh;
     - `test_changes`;
     - `undo_update`.
   - A small watchdog user timer that install.sh puts in place and self-updates never change:
     - every 30 s it checks `/health` and that `/whoami` comes back as the owner;
     - it starts Sparkie's container if it's missing;
     - it puts back the last build marked good after 24 healthy hours, at most once per build.
   - Keep the HF token on Spark 2 and write it to the Spark doing a download.
   - Warn about Tailscale key expiry 14 days ahead.
   - Backups retry when a Spark comes back and include a git bundle of the code.
   - Later: `change_console(task)`, where Sparkie changes its own code in a worktree with the coding engine; changes to sign-in or deploy files wait for the passkey.
2. **Sparkie carries work to the end.**
   - When an operation it started finishes and no other operation from that request is running, Sparkie gets a background turn in that chat to do the next step or say it's done.
   - The chat is the task. The budget is 8 continuations, 12 changes and 2 hours, and intent always comes from the owner's stored words.
   - Saved workflows gain an `{"ask": …}` step (a background Sparkie turn) and a `when` (daily at a time, every N hours, or when a Spark comes on). The daily setups look becomes one of those, reporting what's new.
   - `benchmark_model`.
   - "Done" lines are built from the jobs.
   - `ask_sparkie` follows the operations it started.
   - A `category` input for start_model ("the best coding model").
3. **Memory.**
   - `memory.json`: at most about 40 entries, each a preference, correction, fact or lesson, with remember and forget actions and their own intent kind.
   - It is loaded at the end of the system prompt, so the prompt cache stays warm.
   - Seed it once with the fleet facts and preferences now only in Claude's notes.
   - Keep each Spark's last-known disk while it's off.
   - Record failed starts on the same setup key in verified.json, so bestHow avoids them.
   - Cache recipeCatalog.
   - Archive old owner chats instead of the hard 300 limit.
   - Reload events.jsonl.1 after rotation.
4. **One way in, simpler.**
   - `POST /actions/:name` → runAction. Delete the REST copies (/deploy, /stop, /deploy/*, /desired/bring-back, /recipes/*, …).
   - Turn the REST-only verbs into actions: download_model, add_recipe, forget_should_run.
   - Retire members, sharing, the door socket and short address, the workers.dev page, the editor proxy and the file browser. *(2026-11-11: the door socket, short address and workers.dev page are retired; one address.)*
   - The page becomes chat, sign-in, devices, agent keys, and a status strip.
   - Drop brain routing (ROUTES).
   - Cut the contract to about 200 lines Sparkie can use, and generate the action list for agents from the code.
5. **API for agents.**
   - Pass through `/v1/responses` (Codex), `/v1/embeddings` and `/v1/rerank`.
   - `callWith` gives the gateway address and says whether tools work.
   - Agent keys are accepted on /chats, with a JSON long-poll mode.
   - The safety pause becomes per agent, with `console.mjs resume`.
   - Check every saved-workflow step's arguments before step 1.
   - One error object: code, retryable, retryAfter.
   - Fix the scope bypass on /v1 on the tailnet, and don't let programs on the Sparks start models through /v1.
6. **Apps.** With chat and the API as the only ways in, Open WebUI is optional. If it's wanted, build it as described under round 1 (its own port behind the console's sign-in).

Round 1's list, still valid where not covered above:

1. **Apps: Open WebUI, done right** (apps review).
   - Labels: `spark.app=<id>`, with apps kept out of the model inventory.
   - Open WebUI listens on 127.0.0.1.
   - Its own HTTPS port (10000) is reached through a console socket that adds a trusted login header. The owner runs one Funnel command; the Tailscale config stays the owner's.
   - Settings: `WEBUI_AUTH_TRUSTED_EMAIL_HEADER`, `ENABLE_SIGNUP=False`, version v0.13.3 pinned by digest, and the secret in a 0600 env file.
   - Background title, tag and autocomplete calls are off, because the brain serves one request at a time.
   - Memory is capped at 4 GB with a high OOM score.
   - Then SearXNG, Jupyter under the console path, and ComfyUI on Spark 3/4.
2. **Keeper** (architecture).
   - A small, frozen unit outside server.mjs checks the socket with a real call every 30 s and restarts the console.
   - After repeated failures it runs restore.sh.
3. **Durable operations** (architecture).
   - Jobs are written to disk with their `ranHere` and `stoppedHere`.
   - After a restart, interrupted operations are put back or resumed, not just reported.
4. **One reconcile loop** (workflows and architecture).
   - maybeHeal, healPass and watchHeld become one decision table.
   - One fleet snapshot per Spark replaces about 25 uncached `inventory(null)` calls.
   - Add an SSH ControlMaster.
5. **Every start uses the best setup** (models).
   - The page's Start uses bestHow too.
   - Runs that gave something up (shorter context, dropped flags) rank last.
   - On-disk starts wait for the setups look, up to 150 s.
6. **Starts that fail in a new way** (models and workflows).
   - Try the next-ranked setup once.
   - Save fixes that worked (`learned-fixes.json`).
   - Turn down setups that failed in the last 7 days.
   - Compute the memory share from the engine's own report.
7. **Switches**.
   - Copy weights and pull images before stopping anything.
   - Later, one port per model.
   - A paired model is stopped as a pair when the owner says to switch a Spark that holds half of one.
8. **Sparkie, faster** (Sparkie review).
   - Keep reasoning between tool rounds.
   - Put fleet notes in the prompt.
   - Cut Sparkie's tools to about 20; outside agents keep them all.
   - A `category` input for `start_model` ("the best coding model").
9. **Downloads and disk**.
   - A download stuck for 10 minutes is resumed, up to 3 times.
   - A `free_disk` workflow removes only Spark Console's own leftovers.
10. **Access, small**.
    - Close the sign-in cookie's reach to the public :443 app. This needs one owner-run `tailscale funnel` command.
    - Limit how many requests one key can have open on /v1.
    - Drop the `door.public` flag and the console page framed inside the workers.dev page. *(Done 2026-11-11.)*
11. **Simplify**.
    - Remove: dead forum-reading code in dig.mjs, the paused member and access-request features, and the duplicate page routes (send them through runAction).
    - Workflow versions should hash the parts each workflow lives in.
