# Who holds the truth outside the state folder

Outside the hub's state folder: memory, Docker, hub and Spark files, and repo files.
State-folder facts, even with memory copies, belong in `docs/state.md`. Update changed rows.

| Fact | Lives in | Written by | Read by | Survives a restart |
|---|---|---|---|---|
| Containers | Docker on each Spark. Apps carry `spark.app=1`, GPU apps `spark.gpu=1`, jobs `spark.job=1` and `spark.chat` (A13). `appRunCommand` saves the hub route (`selfTailnetHost` from `refreshBlocked`) in new apps and jobs | console jobs, `main-start`, `bringBack`, `watchBrain`, Docker’s restart policy for the brain, or by hand | inventory, plans, watcher, worker, `runningDetail` (on-demand inspect for `running_models {detail}`). No Docker reply: `dockerOk: false` in inventory, watcher skips it (R21) | yes |
| How a model on disk runs | its `spark.json` in `~/models` on the Spark; the Hugging Face cache in its default place, `~/.cache/huggingface/hub` (the service's SSH skips the shell profile, so a cache moved with `HF_HOME` in `.bashrc` isn't seen) | a start (`copyModel` from another Spark; `downloadVersion` into the cache, the page’s too); `run` and `write_file` after the owner’s yes; the owner by hand | `inventory`, `plan`, `agentSafeSetup` | yes |
| Operations and claims | memory: `jobs`, `busySparks` | `newJob`, `runJob`, `claimSparks` | chat, healing, page, `wait_operation` | no (`events.jsonl`: start/end; journal: end/log, R43) |
| A start's context constraint and proposed retry | memory: `contextStarts` (private operation state), `contextRetries` (frozen one-use proposals) | `contextPrepare`, `contextBind`, `contextPublish`, `contextCarry`, `contextPrune` | `startWithFixes`, `contextConsume`, `contextPark`; public jobs carry only the question's chat/group and safe choices | no: a restart invalidates pending retries; saved chat text is not authority to run them |
| Choices and asks | `pendingChoices` | `question` | `runChoice`, `redeemChoice`, `passkeyGate`, `tellReplyText` | no |
| An ask that waits for the owner’s press | memory: `dangerOpen` (the open dangerous ask and its two digits, R54), `tgAsks` (payload, pairing, full delivery); `TG_OWNER_PROOF` (request’s verified pairing), `workAsks` (the wall and script hashes a button showed), `aheadLists` (a request’s go-ahead, R65), `evalWaiting` and `trialWaiting` (a result waiting to be kept; R52, R67) | `dangerAsk`; `tgAsk`; `workRecord`; `aheadGive`; `evalWait`, `trialWait` | `dangerPress`, `dangerTypedHere`, `tgApproving`, `workChange`, `hubChange`, `aheadCover`, `evalYes`, `trialYes` | no: a restart closes each |
| Stops made on purpose | memory: `consoleStopped` | set by `stopContainer`, `putBack`, `restartJob`, `bringBack`, `appPutBack`, `healDrill`; cleared by `deploy`, `clusterParts`, `restartJob`, `putBack`, `asideBack`, `bringBack`, `keep_running`, `unpark` | `maybeHeal`, `healReason`, `startOnCall`, `healApp`, `jobEnded` | no |
| Which build is tested | `service/workflows.lock.json` (not in git); GitHub’s `tested/<tree>` tag holds the tested commit plus lock | `test/lock.mjs` only (here, on compute Sparks or GitHub); tag only by `.github/workflows/full-run.yml`’s `mark` (writes no lock) | `workflowStatus`, once at start; the installer (its build id) | yes |
| Sparkie's open proposal of its own code (R69) | The hub's copy of the repository (`~/.local/share/spark-console/repo.git`): `refs/sparkie/<id>` (its branch's head), `refs/sparkie-base/<id>` (the noted commit of `main`), `refs/sparkie-chat/<id>` (a blob holding the chat's id); on GitHub the branch `sparkie/<id>` and its pull request | `propose_update` (`selfStart`, `selfSend`, `selfDrop`; `selfInstall` takes the refs away once merged) | `propose_update`, `check_update` (`selfProposalFacts`) | yes |
| Which tests a change needs | `test/affected-map.json` (git doesn’t keep it): for every function of the parts, the test files that ran it, named by the tree; a Spark runner’s copy beside its lock, `<name>.affected-map.json`. The landings, one line each: `spark-landings.log` beside the work folders | `test/lock.mjs` with `SPARK_TEST_MAP=1` after a passing whole run (`buildMap`); its `missed` only by `noteMissed`; the log by `tools/land.mjs` | `pick` (`tools/affected.mjs`), `tools/land.mjs` | yes (files outside the service) |
| Eval evidence | `<result>.diagnostics.json` (0600; `docs/eval-evidence.md`) | `writeDiagnostics` (`test/eval-diagnostics.mjs`) | people; `--store` refuses it | yes, runner only |
| Hub source and proof | `~/spark-console-src` and `~/spark-console-src.manifest` | installer; update guard restores both | local `deploy/host-on-portal.sh` (rebuild/test/install without Mac), `deploy/root-for-sparkie.sh`; service `evalSetNow`, `trialSetNow`, `selfSource` | yes |
| The self-test’s image | `config.json` `selfTestImage` (pinned by digest; a key of its own, not under `images`) | replaced with `config.json` on every install | `self_test` | yes |
| The box’s image | `config.json` `work.images.python` (pinned by digest; under `work`, never `images`) | replaced with `config.json` on every install | `boxOpen` (21-box.mjs, R62) | yes |
| Which box is where | Docker on a compute Spark: one container a chat (or caller), `spark-console-box-<12 hex>`, labelled `spark-console.box=<its name>`, its folder `~/.local/share/spark-console/work/<name>` (0700, emptied at each open); memory: `boxes` (the caller → Spark, name, end), kept until a removal is seen, and `boxFills` (the tree a box was filled from) | `boxOpen` (the one `docker run` line); its files by `boxRun`, `boxWrite` and `boxFill`; removed by its own time (`--rm`), a command past its seconds or one that left the disk under its floor, `boxEnd` (`/stop`, `run {on: "box", command: "/stop"}`), a failed check, a use on a Spark that holds the brain now; the folders of boxes that are gone at the next open there, once Docker answers | `boxRun`, `boxWrite`, `boxReadBack`; the watcher leaves out the boxes `boxes` knows (`boxesOn`) | the container until its time; `boxes` and `boxFills` no |
| The root helper on a Spark (R42, R70) | `/usr/local/sbin/spark-console-root` (root, 0755); its sudo line, `/etc/sudoers.d/spark-console-root` (0440); the proof’s mark, `/var/lib/spark-console/proved` (current while helper, systemd and kernel are as proved); root’s switch, `/var/lib/spark-console/root-on` (0600); while a call runs, `/run/spark-console/<id>/` (root’s: the command, its input, any key given; gone with the unit) and its mark in `/run/spark-console/.calls/`; systemd’s look mask is `/run/systemd/inaccessible/sock` | the owner’s one-time command (`deploy/root-for-sparkie.sh`: the helper, the line, the switch with `--with-root`; `--undo` removes them and the mark); the helper (the mark, after a proof that passed; the held folder) | `helperScript`, `guardScript` (its SHA-256 against `HELPER_SHA256` before every call); its `check`, `state --id` (`runnerRunState`), `stop --id` (`longStop`) | yes; `/run/spark-console` until the Spark restarts |
| The lock-out net’s copies on a Spark (R60) | `/var/lib/spark-console/guard/<id>/` on that Spark (root’s, 0700): the ways in as they were (`/etc/shadow`, the SSH host keys and Tailscale’s state among them; on the hub also the state folder’s sign-in files but `sessions.json`), `restore.sh`, and `pending`, `kept` or `result`; while open, a timer in that Spark’s systemd (`sw-guard-<id>`) and a unit for a restart (`sw-guard-boot-<id>.service`). The console’s record: `net.json` (`docs/state.md`) | the root helper (`run --net`, `root --net`, `keep`, `putback`, its timer); copies over 7 days old go when the next guard is armed, never an open one’s | the helper, by the guard’s id (`guardCall`); the service never reads the copies | yes; one open when its Spark restarts is put back as it starts |
| The copies a change makes first (R61) | `~/.local/share/spark-console/before/<set>/` on that compute Spark (folder 0700, files 0600; hidden from every command): each file the sorter placed (at most 16 MB a file, 128 MB a command), a manifest, the ways-in fingerprints before and after | `copiesOn` (from `runChange`), which prunes when a new set opens: sets over 7 days old, all but the newest 20, then the oldest down to 2 GiB; never the newest set of a chat that can still undo it | `runChange` (the set goes back when a way in differs), `runnerUndo` (`undo_last_change`) | yes, until pruned |
| Files in a Spark’s shared folder | `~/.local/share/spark-portal/workspaces/shared` on each Spark (outside the state folder and the daily copy) | `save_file` (new files only, through `sparkFiles`; the worker writes nothing else there); `run` and `write_file` after the owner’s yes (R61); the worker makes the empty folder the first time anything but `files` looks there; `keep_running`’s job makes `jobs/<name>` with one fixed `mkdir -p` (`jobFolder`; jobs’ outputs count toward the worker’s 64 MiB and 1,000-entry limit), and the job itself writes there, as its image’s user (often root), mounted at `/out`; it reads the whole folder at `/in`, read-only (A13) | `files` (first checks the folder is there, so a look never makes it); `compareScore` (a job’s `result.json`) | yes |
| The brain's long context | `~/.cache/spark-console/overlay/<served name>/{model,draft}` on the hub, when its setup has `ropeScaling`: links to every cached file, plus a `config.json` with the YaRN change (factor 4 over a 262,144-token base, like the benchmark's "extended" copies); the cache itself is never modified | `mainRunCommand`, at each start | the brain's engine | yes (made again at each start) |
| What was said, called, run and seen (R43) | The masked journal in `JOURNAL_DIR` (`~/.local/share/spark-console/journal`, 0700); monthly `journal-YYYY-MM.jsonl` records and `.out` long text, 0600. R43 defines sizes, write-ahead syncing and retention. Never copied off the hub, rewritten or deleted; excluded from daily copies and install snapshots | `journal` only (`20-journal.mjs`), called by chat, actions, jobs, execution, events and restart recovery | `recall` streams reads; `journalAfterRestart` reads the newest two months; `journalNeeds` uses in-memory `journalProblem`, `journalWorked` and `journalCut` for owner notices | yes; hub disk failure loses it |
| Telegram’s token, the paired chat, its needs-me and `approve` switches; the recovery codes’ hashes; the heartbeat’s address; named keys (`keys`, R51); the put-back record (`auth`, R23) | `~/.config/spark-console/secrets.json` (0600; outside state, daily copies and install snapshots) | `PUT /telegram`, pairing (`tgTryPair`), `telegramRoute`, `tgApproveRoute`, `tgLock`, `ownerTelegramApprovals`, `DELETE /telegram`, `/unpair`; `makeRecoveryCodes`, `useRecoveryCode`; `PUT /heartbeat`, `DELETE /heartbeat` (`heartbeatRoute`), a key in the owner's chat (`keepNamed`, `beatSave`) (all through `secretsWrite`) | `tgBinding`, `tgPaired`, `needsMeTick`, `recoveryView` (the passkey page; `/whoami`’s `recovery`, yes or no, F18; inside `accessView`, where an unreadable file shows as no figure and a `problem` line, never “0 left”, A5), the recovery sign-in (read on each use); `beatOnce` (each beat; the address is never shown); `keptForms` (every value, for the mask). Unreadable: Telegram, recovery codes and the heartbeat off, never written over | yes |
| The install’s GitHub token; where each kept key has gone; the seal’s key | in `secrets.json` (above): `github` (`repo`, `token`) and `hosts` on each named key (where it has gone, 50 at most); beside it `eval-seal.json` (0600: seals the results kept in `brain-profiles.json`) | `pull.sh setup` (its own write, not `secretsWrite`; `/key GITHUB` runs it); `runKeysUsed`; `evalSealKey` (once, never written over).
