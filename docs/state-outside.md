# Who holds the truth outside the state folder

What the console keeps anywhere but its state folder on Spark 2, or nowhere: what runs in Docker, what is only in
memory, files elsewhere on Spark 2 or on other Sparks, and files in the repository. A fact with a file in the state
folder is in `docs/state.md`, even when memory holds the working copy. A change that adds or moves a fact updates its
row here.

| Fact | Lives in | Written by | Read by | Survives a restart |
|---|---|---|---|---|
| What actually runs | Docker on each Spark (names, labels; apps Spark Console started carry `spark.app=1`, with the GPU `spark.gpu=1`; a job `spark.job=1` and the chat that asked, `spark.chat`, A13) | console jobs (the brain keeper’s `main-start` too); healing’s direct commands (`bringBack`, `watchBrain`); Docker’s restart policy for the brain; anyone by hand | `inventory`, `plan`, watcher, worker; `runningDetail` (one container’s `docker inspect`, on demand, for `running_models {detail}`). A look Docker didn’t answer: the inventory marks it `dockerOk: false`, the watcher skips it, never read as empty (R21) | yes |
| How a model on disk runs | its `spark.json` in `~/models` on the Spark; the Hugging Face cache in its default place, `~/.cache/huggingface/hub` (the service's SSH skips the shell profile, so a cache moved with `HF_HOME` in `.bashrc` isn't seen) | nothing in the service | `inventory`, `plan`, `agentSafeSetup` | yes |
| Operations and claims | memory: `jobs`, `busySparks` | `newJob`, `runJob`, `claimSparks` | chat, healing, page | no (`events.jsonl` keeps start and end; the journal keeps each one's end and log, R43) |
| What an open button runs | memory: `pendingChoices` | `question` | `runChoice`, `redeemChoice`, `passkeyGate` | no |
| Stops made on purpose | memory: `consoleStopped` | set by `stopContainer`, `putBack`, `restartJob`, `bringBack`; cleared by `deploy`, `restartJob`, `putBack`, `asideBack`, `bringBack` | `maybeHeal`, `healReason`, `startOnCall` | no |
| Which build is tested | `service/workflows.lock.json` (git doesn’t keep it); on GitHub also the `tested/<tree>` tag, the tested commit plus its lock | `test/lock.mjs` only (here, on a compute Spark, or in GitHub’s `suite` job); the tag only by the `mark` job of `.github/workflows/full-run.yml`, which writes no lock | `workflowStatus`, once at start; the installer (its build id) | yes |
| Which tests a change needs | `test/affected-map.json` (git doesn’t keep it): for every function of the parts, the test files that ran it, named by the tree; a Spark runner’s copy beside its lock, `<name>.affected-map.json`. The landings, one line each: `spark-landings.log` beside the work folders | `test/lock.mjs` with `SPARK_TEST_MAP=1` after a passing whole run (`buildMap`); its `missed` only by `noteMissed`; the log by `tools/land.mjs` | `pick` (`tools/affected.mjs`), `tools/land.mjs` | yes (files outside the service) |
| The source on Spark 2 | `~/spark-console-src`: the whole source, so Spark 2 can rebuild, test and install without the Mac | the installer, swapped in whole once an update is kept | an update from Spark 2 itself (`bash ~/spark-console-src/deploy/host-on-portal.sh local`) | yes |
| The self-test’s image | `config.json` `selfTestImage` (pinned by digest; a key of its own, not under `images`) | replaced with `config.json` on every install | `self_test` | yes |
| Files in a Spark’s shared folder | `~/.local/share/spark-portal/workspaces/shared` on each Spark (outside the state folder and the daily copy) | the page’s files route (`sparkFiles`); `save_file` (new files only); the worker makes the empty folder the first time anything but `files` looks there; `keep_running`’s job makes `jobs/<name>` with one fixed `mkdir -p` (`jobFolder`; jobs’ outputs count toward the worker’s 64 MiB and 1,000-entry limit), and the job itself writes there, as its image’s user (often root), mounted at `/out`; it reads the whole folder at `/in`, read-only (A13) | the page; `files` (first checks the folder is there, so a look never makes it) | yes |
| The brain's long context | `~/.cache/spark-console/overlay/<served name>/{model,draft}` on Spark 2, when its setup has `ropeScaling`: links to every cached file, plus a `config.json` with the YaRN change (factor 4 over a 262,144-token base, like the benchmark's "extended" copies); the cache itself is never modified | `mainRunCommand`, at each start | the brain's engine | yes (made again at each start) |
| What was said, called, run and seen (R43) | The journal, `~/.local/share/spark-console/journal` on Spark 2 (`JOURNAL_DIR`; folder 0700, files 0600): two files a month, `journal-YYYY-MM.jsonl` (one line per record, 1,500 bytes at most; a change written down first has a start line, synced before it runs, and an end line with the same id) and `journal-YYYY-MM.out` (records' long text: a tool's result, an operation's log, up to 16 MB each). Masked before it is written; no secret. Outside the state folder: the daily copy and install snapshots never take it. Never copied off Spark 2, rewritten or deleted | `journal` only (`20-journal.mjs`), from `sparkieTurn`, `runAction`, `runJob`, `note`, `fleetEvent` and `journalAfterRestart` (an end line marking a start cut off) | `recall` (a file read 1 MB at a time); `journalAfterRestart` (the two newest months, at start-up); `journalNeeds` (`openProblems`: its size; from memory, `journalProblem`, `journalWorked` and `journalCut`, changes cut off, for a day) | yes; a dead Spark 2 disk loses it |
| Telegram’s token, the paired chat and its needs-me switch; the recovery codes’ hashes; the heartbeat’s address; named keys (`keys`, R51) | `~/.config/spark-console/secrets.json` (0600; never in the state folder, the daily copy or an install snapshot) | `PUT /telegram`, pairing (`tgTryPair`), `PUT /telegram/needs`, `DELETE /telegram`, `/unpair`; `makeRecoveryCodes`, `useRecoveryCode`; `PUT /heartbeat`, `DELETE /heartbeat` (`heartbeatRoute`), a key in the owner's chat (`keepNamed`, `beatSave`) (all through `secretsWrite`) | `tgBinding`, `tgPaired`, `needsMeTick`, `recoveryView` (the passkey page; `/whoami`’s `recovery`, yes or no, F18; inside `accessView`, where an unreadable file shows as no figure and a `problem` line, never “0 left”, A5), the recovery sign-in (read on each use); `beatOnce` (each beat; the address is never shown); `keptForms` (every value, for the mask). Unreadable: Telegram, recovery codes and the heartbeat off, never written over | yes |
| Short-lived memory | breaker counts; `inUse` (30 min); `callStarts`; `unreachableUntil` (60 s); `blockedAddresses`; passkey challenges, device codes, the sign-in key; the app door's tickets (`doorTickets`: a token's hash, the session or Tailscale sign-in it came from, the app; 12 hours, 200 at most) and `doorOn` (R40); `agentCache` (5 to 30 s); `gatewayBrainCalls` (app calls on the brain now); `brainRestarting`; `brainDownSince`; `liveTurns` (by chat, for `/stop`); `waking`; `chatsUnsaved`; `saveFailed` (by file, until that file saves) and `saveWorkedAt` (a failed save is listed only while none has worked since); `accessBad` (why `access.json` can’t be read while its copy answers); `needsGone` (told problems off the list, for 6 hours); `needsSince` (when each open problem was first seen open, for 5 minutes); `backingUp`; `webSeen` (addresses `search_web` returned, an hour) and `searches` (results, 10 minutes) | their own functions | `runAction`, `start_model`, `/v1`, `run`, `requestGate`, sign-in, read actions (`read_page` reads `webSeen`) | no |
| The idle power-off’s counts | memory: `sparkCalls` (the last `/v1` call to a model on each Spark, model copy from it or daily copy to it), `idleSince` (from this process’s start), `serveCount` and `serveUnseen` (the model server’s own `/metrics`), `keepAwakes`, `wokeFor` | their own functions | `powerTick`, `busyReason`, `sparkNeeded` | no |
| What is waiting on the owner | nothing kept: `openProblems()` (20-needs) builds it on each ask from `accessBad`, `secretsRead()`, `chatsUnsaved`, `saveFailed` with `saveWorkedAt`, Spark 2’s disk in `statusCache`, the `*.unreadable-*` files, `backup.json`’s record, `knowledge.sparks[id].dockerDownAt`, `heldLast`, `watchdog-restarts`, `last-crash.json`, `beat` (20-beat, memory only: since when beats fail), `waysIn` (20-ways-in, memory only: Tailscale’s keys and linger as last read) and `funnelOn` with `funnel-seen.json`; each entry has a stable key (kind and target) | the facts’ own writers | `/status` (page and Telegram), the top of Sparkie's fleet notes (only when there is something), `fleet_status.needsOwner` (always, second key; at most 8 lines, the 8th counting the rest), `needsMeTick` | built again from the facts |
| Outside the state folder | `~/.config/spark-console/secrets.json` on Spark 2 (above); engine caches in `~/.cache/spark-console/engines` on each Spark; release snapshots in `~/.local/share/spark-console/releases` on Spark 2 (each holds a copy of the state, a `build` file naming its build, `restore.sh` written last, and `same` once it equals what is installed: the same update run again, or a snapshot whose files were put back, answering or not); `go-back.sh` and `RECOVERY.txt` in `~/.local/share/spark-console` on Spark 2 (copied by every install; read by nothing in the service; `/help` prints their paths); the daily copies on another Spark (`~/.local/share/spark-console/backups/state-<day>.tgz`, the last 14; each arrives as `.part` and is moved in, and the oldest beyond 14 removed, only after `gzip -t` reads it whole and tar on Spark 2 ended well) | jobs; the installer and `restore.sh`; `backupState` | starts; `undo_update` and `/undo update` (`lastSnapshot`); `noteUpdate` (the newest snapshot's name); `go-back.sh` and restore by hand | yes |
