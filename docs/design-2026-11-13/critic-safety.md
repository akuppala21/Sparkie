## 1. Decisions 20 to 22 (everything, root, Telegram, keys): the least dangerous way

**1. Root: A's "passwordless sudo for everything" lets more than Sparkie be root, and cannot start on Spark 2 as written. [before]**
- *Goes wrong:* (a) with `NOPASSWD: ALL` every script that calls `sudo` by itself is silent root, outside the gate, the record and the net. The installer does: its route step calls plain `sudo tailscale serve`, which would then run as root with no ask. So "root is always a fact the gate, the button and the record can see" holds only for Sparkie's own wrapped commands. (b) On Spark 2 the script that runs `sudo -n` is a child of the console, whose unit forbids new privileges, so root fails there, and with it the net's timer (inference). (c) Root on the ladder is too wide: "an edit under `/etc`" and "a root look" run at once or under a go-ahead. Many files under `/etc` are run by root later (a unit file, `ld.so.preload`, an apt source, `update-motd.d`, udev rules). A root look with a grammar hole (finding 8) is root code with nobody asked, and root can read Docker's own record of every container's environment (the kept keys), which is not on the never-shown list. (d) `ssh` between the fleet's Sparks is on the ladder: `ssh spark2 '…'` typed on Spark 3 carries any command to Spark 2, past "anything on Spark 2 is asked".
- *Evidence:* A 2.8 (the root tables, the first table's third row), A 2.3 (root looks), A 2.5 "How it runs". Verified: `deploy/host-on-portal.sh` `serve()` falls back to plain `sudo tailscale serve`; the console's unit sets `NoNewPrivileges=true`; `deploy/power-setup.sh` already installs a sudoers file checked with `visudo -cf`.
- *Change:* (1) The sudoers line names one root-owned helper, not `ALL` and not a list of commands (A weighed only a list). The helper runs whatever code hands it, so Sparkie loses nothing; nothing is stored; one line undoes it; a plain `sudo` in any other script still asks, and fails when nobody is there. A stored password stays the worst choice, as A says. (2) The helper is also the home of three kernel walls this review leans on. **Run**: an ordinary command as the owner's user with the Docker, Tailscale and user-manager sockets, the secrets file and loopback hidden (about 0.1 s, inference). **Look**: any command, root's read rights, the whole disk read-only, no network, key material and `/run` hidden; the look grammar then stops mattering. **Net**: finding 2. (3) On Spark 2 start `sudo` from a unit of the user manager, as A already does for ordinary commands; prove it there. (4) At once as root: a closed table only (a named package from the archives already set up, restart of a unit that exists, owner and mode under the owner's home, a look in look mode). Any write under `/etc` or another system folder is asked. (5) The command inside `ssh <Spark> '…'` is sorted as a command on that Spark.

**20. On a compute Spark a command can outlive itself, end a healthy model, and delete without the delete ask. [when built]** A 2.5 runs each command as a short-lived unit "so nothing outlives it".
